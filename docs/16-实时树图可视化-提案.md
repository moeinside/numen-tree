# 实时树图可视化（白盒化）提案

> 2026-11-08 04:3x 用户提出：**一个同步更新的三维树图，实时读取行为树定义并更新，树走到哪一步就同步亮起显示。**
> 本文只记录概念与设计草案，**未动工**。相关：`docs/15`（双策略/任务变换）、`docs/12 §10.17`（寻路/施工）、`docs/14` 交接。

## 1. 用户原意（理解确认）

- 不是手画的示意图，而是**从代码里的树定义自动生成**（配方/步骤/技能/中断/日程/仲裁规则）→ 改代码图就变；
- **实时同步**：树当前执行到哪个节点，对应节点就亮起/高亮；
- 目标：把"黑盒子"变成"玻璃盒"——能看见树为什么做这个决定、卡在哪一步、降级到了哪一级。

## 2. 我们已有的数据基础（这件事可行性很高）

| 数据 | 来源 | 用途 |
|---|---|---|
| 配方图（步骤 + next/onFail + 技能/参数） | `src/recipes.mjs` | 静态树骨架（分支边） |
| 技能清单/参数/元数据 | `src/skills/*.mjs`（`meta`） | 叶子节点 |
| 中断表 | `src/interrupts.mjs` | 安全/日程守卫节点（虚线边） |
| 日程表 | `src/schedule.mjs` | 时段上下文（白天/夜晚/无家） |
| 合成树 | `src/crafttree.mjs` | 材料依赖子图 |
| 运行态 | `GET /status?detail=1`（plan.cursor、stepResults、current_skill、goals、slotBlocked、inbox） | 高亮当前节点/队列/失败 |
| 历史 | `logs/trace-*.jsonl` | 回放、时间轴、失败原因 |

当前 `tree_status` 已精简到 ~200B，1 秒轮询对树没有负担；也可以加 SSE/WebSocket 推送。

## 3. 设计草案

### 3.1 后端（只读，不影响树行为）

- `GET /graph/model`：从源码 import 后导出静态图（节点/边/参数），进程启动时生成一次（热重载时刷新）；
- `GET /graph/state`：返回每个同伴的运行态（planId/cursor/stepResults/current/goals/queue/inbox ★），可直接复用现有 state，做投影；
- `GET /graph/events`（可选 SSE）：把 trace 事件实时推给前端，做"瞬时光效"；
- `GET /graph`：返回内置静态 HTML 查看器（单文件，无外部依赖）。

### 3.2 前端分三期（建议 2D 先跑通，再上 3D）

**P0：静态图（改代码即更新）**
- 2D DAG/树布局（canvas 或轻量布局算法），节点=配方步骤/技能，边=next/onFail；
- 按层：`仲裁/日程 → 配方 → 步骤 → 技能`；中断/守卫单独一层。

**P1：实时高亮**
- 轮询 `/graph/state`（0.5~1s）：当前 plan 路径加粗、当前 step 呼吸灯、已完成绿、失败红、挂起黄、队列灰；
- 顶部同伴卡：位置/HP/饥饿/模式/日程/当前动作/已运行秒数/槽占用；
- 收件箱 ★ 角标。

**P2：把"决策"也画出来（白盒的核心价值）**
- 颜色/标签显示**为什么**：仲裁命中哪条规则、哪个中断预占、日程段、失败 kind、降级阶梯第几级（配合 docs/15 §8）；
- 双策略模式（attached/autonomous）徽章；任务变换（回家→区域目标）在图上显示为"目标节点替换"；
- 可点节点看参数和最近 trace。

**P3：3D（可选）**
- three.js / WebGL 真 3D 树，节点为球/卡片，边为曲线；旋转/缩放；
- 注意：3D 可读性不如 2D、布局易抖；建议 2D 稳定后再加"3D 皮肤"，或只在"整体树"视图用 3D、执行路径仍用 2D 高亮。

**P4（可选）：游戏内叠加层**
- 通过树/游戏侧 mod 在 HUD 画小图（复杂、需要改 mod，优先级最低）。

## 4. 技术选型草案

- 本地离线优先：不引 CDN；2D 用原生 canvas + 简单布局（层级树布局约 100~200 行）；3D 只在确有需要时打包 three.js；
- 无外部依赖的 `viewer.html` 内联 JS，避免依赖安装；
- 拓扑来源用"导入源码模块"而非解析文本，保证图与代码一致（改代码 → 重启树/热重载 → 图更新）。

## 5. 风险 / 待定

1. **语义映射**：我们的树不是经典 BT（没有 tick 节点），是"仲裁+配方 DAG+中断"；图要展示哪一层，需要先定（建议：配方图 + 当前计划实例 + 中断/日程覆盖，三层）。
2. **布局稳定性**：每帧重排会晃眼；固定布局 + 只改颜色/高亮更好。
3. **规模**：配方 ~13、步骤 ~100、技能 ~25，2D 完全放得下；3D 需要分组/折叠。
4. **实时性来源**：轮询够用（1s）；SSE 更顺滑但增加后端复杂度。
5. **多同伴**：先支持单同伴，按同伴分 tab/分屏。
6. **权限**：纯只读，不提供操作按钮（避免误触发树），后续可加"暂停/清队列"只读外操作。

## 8. 独立工具架构（用户 2026-11-08 要求：单独工具，不是树工具的组件）

**依赖方向（硬约束）**：`treeview 工具 → 读树（只读）`；**树永远不依赖 treeview**。树进程里不加任何可视化代码、不新增组件注册、不改启动脚本。

**数据来源（全部只读，零侵入）**：
1. 静态结构：treeview 进程直接 `import` 树的定义模块（`src/recipes.mjs`、`src/interrupts.mjs`、`src/schedule.mjs`、`src/crafttree.mjs`、`src/skills/*.mjs`）生成图模型——**不需要树新增接口**；
2. 运行态：HTTP 读树控制 API `GET /status?detail=1`（当前 plan/cursor/goals/current/slotBlocked）——现有接口就够；
3. 历史/细节：只读 `logs/trace-*.jsonl`（step 结果、中断、降级原因）。

**目录（建议）**：
```
tools/treeview/                  # 独立进程 + 独立前端，不被 src/ 引用
  server.mjs                     # 本地 HTTP 服务（建议端口 8780）：/（页面）、/api/model、/api/state、/api/trace
  model.mjs                      # import 树定义 → 图 JSON（节点/边/参数）
  live.mjs                       # 轮询 8766 + 读 trace → 投影成节点状态
  public/index.html              # 单文件查看器（canvas 2D，无外部依赖）
  README.md                      # 怎么启动、看什么、和树的关系
```
**启动**：`node tools/treeview/server.mjs` → 浏览器打开 `http://127.0.0.1:8780`（树没开时显示静态图 + "离线"灰态）。

**好处**：
- 完全满足"单独工具"：可随时关掉、不影响树；树重启/升级不影响工具；
- 零侵入：做不出来/不好用可以直接删目录，树无感；
- 可与树并行开发（甚至可让子智能体独立做，只约定只读数据契约）。

**代价**：静态图依赖 import 树模块，属于"源码级只读耦合"（改字段名时工具要跟一下）；这是可接受的，且比"往树里加可视化端点"更符合用户要求。
