# 接口契约（草案 → 已实现 v0.1）

> 树对 LLM 的 MCP 工具面。实现见 `src/mcpserver.mjs`。
> 端点：`http://127.0.0.1:8767/mcp`（streamable HTTP，无鉴权，仅本机）
> 2026-11-07 晚：新增第 9 个工具 `tree_place`（地点簿）；M1 新增第 10 个工具 `tree_task`（模糊意图→配方计划）。

## 1. 工具面（10 个）

| 工具 | 参数 | 返回 | 是否阻塞 |
|---|---|---|---|
| `tree_status` | `detail?`（true=完整 JSON，默认精简一行/同伴） | 每同伴一行摘要（位置/HP/饥饿/任务/队列/计划/上一步）+ 收件箱待决策数；`detail:true` 才返回完整 goals/plan/progress/inventory JSON | 否 |
| `tree_skills` | — | 技能卡列表 + 参数 | 否 |
| `tree_goal` | `companion, skill, params?, priority?` | 排队确认（精确指挥单个技能） | 否 |
| `tree_task` | `companion, intent, deadline_seconds?, params?` | 计划已建 `{ok,plan{recipeId,title,steps}}` / `no_recipe`+可用配方 / `busy` | 否 |
| `tree_control` | `companion, op(pause/resume/stop/clear/mode/tether/reload-skills)`；`tether mode=owner|home` 动态牵引绳；`resume` 重置 LLM 接管预算；`stop` 暂停+清队列+重置预算；`exit` 优雅退出树进程 | 状态摘要 | 否 |
| `tree_inbox` | `since?, brain_only?, full?, limit?` | 上报列表；**默认每条压成一行短文本**，`full:true` 才带原始 detail JSON | 否 |
| `tree_wait` | `since?, timeout_seconds?`（≤90） | 需要决策的上报 + 状态摘要 | **是**（长轮询） |
| `say` | `companion, text` | 结果 | 否（直通 numen） |
| `memory` | `companion, command, ...` | 结果 | 否（直通 numen） |
| `tree_place` | `action(record/list/find/forget), name?, kind?, pos?, query?, note?, companion?` | 地点簿操作（见 §6） | 否 |

**纪律：树对 LLM 不暴露 `lua`。** LLM 只能下目标，不能写游戏代码。

## 2. 上报（inbox）条目

```jsonc
{
  "seq": 12,                  // 自增序号，tree_wait/tree_inbox 的 since 用它
  "at": "2026-11-07T09:20:00Z",
  "kind": "goal_done",        // 见下表
  "companion": "tyrander",
  "needsBrain": true,         // ★ 是否需要 LLM 决策
  "text": "...",              // 主人说的话（owner_query）
  "detail": { ... },          // 结构化事实（失败码、位置、尝试次数等）
  "data": { ... }             // 技能成功时的结果
}
```

| kind | needsBrain | 含义 |
|---|---|---|
| `goal_done` | ❌（通知） | 目标完成；**完成靠拉**（tree_status/tree_inbox），不叫醒 |
| `task_detached` | ❌（通知） | 程序被打断但任务继续在后台跑 |
| `task_done` | ✅ | 后台任务收尾（事件，由大脑决定下一步） |
| `task_failed` | ✅ | 后台任务失败/被取代 |
| `plan_done` | ❌（通知） | 计划完成，同上：完成靠拉 |
| `plan_failed` | ✅（仅 LLM 计划） | 计划失败/放弃，需要大脑决策 |
| `skill_failed` | ✅ | **大脑下的**目标失败（自动行为的失败只在 trace 留痕，连续 3 次才升成 `auto_action_failing`） |
| `drive_stopped` | ✅ | LLM 接管超预算自动停手（见 §6.2） |
| `owner_query` | ✅ | 主人在游戏里说话（`text`） |
| `starving` | ✅ | 饿且没吃的持续 180 秒 → 上报后停手 240 秒等大脑 |
| `stuck` | ✅ | 牵引绳连续 3 次走不回主人 → 上报后停手 180 秒 |
| `death` | ✅ | 同伴死亡（mod 会自动复活），附带自动记录的死亡地点 |
| `auto_action_failing` | ✅（首次）/❌（窗口内） | 某条自动规则连续失败 3 次 |
| `goal_expired` | ❌（通知） | LLM 目标排队超 120 秒未执行被作废 |
| `slot_blocked` / `slot_blocked_persistent` | ✅ | Lua 槽被占（僵尸锁/别的驱动者） |
| `leash` | ❌ | 离主人太远，自动往回走 |
| 其它世界事件 | ❌ | 通知，不叫醒（同一 kind 20 秒内去重） |

**规则：`needsBrain: true` 才允许叫醒 LLM。** 另外 `behavior.escalateDedupeSeconds`（默认 300 秒）内，**同类求助重复出现只当通知**，避免连续死亡/卡住刷爆大脑。

## 3. 技能卡契约

```js
export default {
  id, title, params,
  build(ctx, params) -> { code, timeoutMs }
}
```

Lua 程序必须 `return` 一个**紧凑 JSON 字符串**（≤300 字符）：

```jsonc
// 成功
{"ok":1, ...}
// 失败
{"ok":0,"kind":"no_path","msg":"...","hint":"..."}
```

失败 `kind` 取值（沿用 mod 的语义）：`no_path` / `out_of_reach` / `not_found` / `denied` / `owner_offline` / `bad_argument` / `failed`。

## 4. 控制 API（给 CLI / 调试用，非 LLM 面）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 存活 |
| GET | `/status` | 完整状态 JSON |
| GET | `/skills` | 技能列表 |
| GET | `/inbox?since=&brainOnly=1` | 上报 |
| POST | `/goal` | `{companion, skill, params, priority}` |
| POST | `/control` | `{companion, op, mode}`；`op=reload-skills` 热重载技能卡；`op=exit` 优雅退出 |
| POST | `/task` | `{companion, intent, deadlineSeconds?, params?}` 开计划（模糊意图→配方） |
| GET | `/task?companion=` | 当前计划 + 上一条计划 |
| GET | `/recipes` | 配方表 + 中断表（调试/LLM 可读） |
| GET | `/places?kind=&query=&near=x,y,z&companion=` | 地点簿列表；带 query 时附模糊匹配结果 |
| POST | `/place` | `{action: record/list/find/forget, name, kind, pos, note, query, companion}` |
| GET | `/lock` | 僵尸锁补丁状态（`127.0.0.1:8768`）+ 每个同伴 `slotBlocked` |
| POST | `/lock` | `{op:"unlock", companion?, all?}`：外部清锁（不重建同伴、不丢背包） |

默认 `http://127.0.0.1:8766`。CLI：`node src/cli.mjs place list|find|record|forget`。

## 5. 地点簿（`places.json`）

**目标**：死亡点、基地、主人位置、矿洞入口之类的"地点"要能被记住、被模糊地找回来。
**分工**：树负责**记录与解析**；LLM 只负责把主人的模糊说法传下来，不需要自己算坐标。

- 存储：项目根 `places.json`，`{version, seq, places:[{id,name,kind,dimension,pos,note,source,companion,createdAt}]}`；上限 500 条（超了先删非 `base` 的旧条目）；原子写（tmp→rename），坏文件降级空簿不崩。
- `kind`：`base|death|owner|poi|custom`。
- **谁写**：
  - 树自动写：同伴死亡时自动记 `kind=death`（坐标取最后一次观测，`note` 里注明可能有几格偏差）。
  - LLM/主人写：`tree_place {action:"record", name:"家", pos:"here"|"owner"|{x,y,z}}`；
  - `pos` 省略时先 `here`（同伴当前观测位置）再 `owner`（主人当前位置）。
- **模糊解析**（`tree_place {action:"find"}` / CLI `place find`）：
  1. 精确匹配 `id`/`name`；
  2. 时间词（上次/最近/last…）→ 最新一条；
  3. 中英别名（家/基地/老巢/home→base；死/坟/death→death；主人/你/owner→owner）；
  4. `name`/`note` 子串包含。
  - 返回 `why`（为什么匹配到）、`distance`（到同伴当前位置）、`alternatives`（备选）。
  - 查 "主人/我的位置/你在哪" 时**直接返回主人实时坐标**（`live:true`），不写簿。
- 边界：地点簿是**纯数据 + 机械解析**，不做价值判断，也不主动指挥同伴；"去那个地方"仍由大脑下 `tree_goal go_to`（用 find 拿到的坐标）。
