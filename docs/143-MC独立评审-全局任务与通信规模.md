# 143. MC 独立评审：全局任务、环境变量、通信与规模

> 2026-11-12。MC 专家独立评审，不站队。  
> 视角：整个 MC 玩法、玩家小任务/大工程、环境变量、两模块通信规模。

## 1. 行为领域覆盖缺口

已有/部分：

```text
生存（饥饿/血/夜/坠落/岩浆/溺水）
资源采集
建造庇护
采矿
基础战斗（fight_safe/flee）
探索
```

明显缺口（按 MC 重要性）：

```text
1. 装备降级链（木→石→铁）+ 耐久不可观测
2. 按怪种战斗：creeper 突进、骷髅走位、蜘蛛爬墙、撤退回基地
3. 玩家小任务与 consent（玩家放置方块同意通道会被拒）
4. 死亡→重建（death drop recovery、B 里的 death debt）
5. 附魔/经验：无 xp 字段 → 附魔域应显式排除
6. 农业/畜牧、村庄交易、维度切换：P2 后，但 method schema 先留位
```

## 2. 环境变量分层

### 硬信号（执行事实，不可补偿）

```text
hp / hunger / air
in_water / in_lava / 坠落
hostileDistance ≤ 阈值
is_dark / 光照
```

### 档位

```text
生命档：hp/hunger/air
不可逆档：岩浆/深水/高处
可逆档：资源/建造
机会档：探索/交易/多人
```

### 软分

```text
天气

白天剩余秒
走行成本

```

### 方法前置

```text
工具等级
工作台/熔炉/床
维度
consent

```

### 禁止进入

```text
世界种子
结构精确坐标
刷怪计时
他人背包
```

## 3. 通信方式

混合：

```text
pull 不可变快照：
  1 Hz + 段边界
  {seq, gameTick, fields, stale[]}
  决策纯同步消费，绝不 await

push 事件：
  GET /events?since=seq
  只用于失效与抢占（hard signal、原子结果、latch）
  不作为打分输入
```

铁律：

```text
动作边界前后必采
1 Hz 周期
事件即时但不入分
```

TTL：

```text
hp/hunger       1–2 s
pos/in_water    0.5–1 s
hostiles        0.5 s
方块/容器       不用 TTL，用 seq 失效
```

冲突：

```text
双源不一致 → unknown + 复核
禁止 last-write-wins
```

## 4. 规模估算

```text
活跃承诺        3–7（上限 8）
外层候选        每档 2–5，总 ≤20
方法库          30–60 条（可用子集 ~30）
事件量          峰值 5–10/s
                20 min 一天 ≈ 6k–12k 条
决策成本        纯函数 ≤1 ms
快照大小        5–20 KB JSON（用句柄+seq，不要塞实体/方块列表）
日志            ~0.5 KB/条 → 3–6 MB/天
```

## 5. 哪里过重/不够

过重：

```text
P1 就上 B→外层→内层 三层
结果事件 40+ 字段（先冻结 15 个必需）
每 tick 全量快照
```

不够：

```text
方法库没定义与 allowedMethods 的匹配键与前置 schema
缺 metrics：decision_tick 延迟、抢占率、stall 率、假成功计数
缺 death debt 与 consent 域
```

## 6. 先测三件

```text
1. 内层打分：不阻塞 + methodId ∈ allowedMethods
2. 事件 schema 冻结 15 字段 + 游标不丢
3. 双源一致性（numen vs 触手）
   这条不过，所有 postcheck 都不可信
```

## 7. 机制判负

```text
allowedMethods 放行的方法
其声明的硬前置（工具等级/站点/维度/consent/加载区）
未被事实层确认
却仍被派发 atom
→ 判负
```

可判形式：

```text
atom_begin{methodId} 存在
但该 method 的 preconditions 在同期快照中任一为 unknown/false
```

## 8. 一句话

```text
架构方向对，但真正的缺口不在打分层，
而在装备降级、按怪种战斗、玩家小任务/consent、死亡恢复
这四个领域，以及方法库前置 schema。

P1 先用：
  pull 快照 + 事件仅失效 + 15 字段事件契约
跑通内层打分与双源一致性，再谈三层。
```
