# 60. P0-0 最终范围共识（项目经理裁决）

> 2026-11-10。行为学审计 + 点子王红队 + 项目经理裁决后的最终 P0-0 范围。  
> 结论：**有条件批准；P0-0 拆 a/b，设硬时限，防止滑成行为架构重构。**

## 1. 最终拆分

```
P0-0a 核心闭环
  → P0-0b 行为最小
  → P0-a 真实两夜
  → P0-b 真实 kill/重启/续跑
  → P0 出线
```

### P0-0a：核心闭环（必须）

1. 原最小眼：
   - 白名单三态 Facts；
   - 四类动作前置门 + settle 后 postcheck；
   - PerceptionService 唯一写入；
   - 单 inflight、≤2 观察/动作、超时退避；
   - 真实水失败 trace 回归 + 三负样本。
2. 事务提交原子性：
   - begin→settle→postcheck→commit；
   - 普通抢占不能插入；
   - 反射可打断，但结果只能 `unknown`，不得携带 success；
   - attempt/generation 只做最小字段，不建完整事务框架。
3. unknown 生命周期：
   - 最多重观测 2 次；
   - 超时转“信息缺失”；
   - 不计策略失败，不堵槽。
4. 副作用分类：
   - 只做标注 + 禁止自动重入；
   - “放置/建造”可重建 vs“消耗材料/存箱”不可重放；
   - 不做重放引擎。
5. 失败责任归位：
   - owner + 计数器；
   - 只有 milestone 可判 unreachable；
   - 同根因去重。
6. 观察微打断：
   - 不占计划槽；
   - 触手 HTTP 不占 numen Lua 槽；
   - Lua postcheck 只在动作边界。

### P0-0b：行为最小（收缩）

- 安全去重只做：硬信号 OR 门槛、不进候选分；
- 加**一条**回放级组合负样本（入水+低血）即可；
- dusk 过渡、疲劳可覆盖 schedule 进 P0-0b；
- **夜间 idle glance 后置 P1**；
- 三条组合与“留出组合 100%”后置 P1。

## 2. 硬时限

- P0-0 设硬时限；
- 到期未完，按 cut line 砍掉未完成项，直接进两夜；
- 不允许 P0-0 无限吸收需求。

## 3. 验收门

新增硬门：

- 事务中断后“携带 success” = 0；
- unknown 被误计策略失败 = 0；
- 重观测 >2 = 0；
- unknown 非幂等自动重做 = 0；
- 硬信号重复计权 = 0；
- “0 进度时间”有上界；
- 失败责任越权（atom/onFail 宣布 unreachable） = 0；
- 观察占计划槽 = 0；
- 触手 HTTP 占 Lua 槽 = 0；
- 固定组合样本抢占 3/3。

证据：

- 真实水失败 trace + 假 ok + 回档三负样本进永久回归；
- 组合负样本至少一条进回放。

冻结项追加：

- 事务/attempt schema；
- unknown 生命周期策略；
- 副作用分类表；
- 硬信号清单与 OR 语义；
- 失败责任矩阵；
- TTL；
- 预算数值；
- 历史 trace；
- 审计版本。

## 4. 验收口径修正

“留出组合 100% 强制抢占”改为：

> **固定 3 组合全抢占**。

3 条样本撑不起“留出 100%”，会制造新的不可证伪门；留出矩阵归 P1。

## 5. 最大风险

P0-0 从“补感知门”滑成“行为架构重构”，重演“离线全过、真实仍挂”。

单开发者上下文下，这等于用两周换一次更贵的失败。

## 6. 一句话

> **有条件批准：P0-0a 核心闭环 + P0-0b 行为最小 + 硬时限；不接受则反对现在开工。**
