# 110. 高频坑与当前工程假设

> 2026-11-11。来源：D1/D2、M3、Phase C、fixture 多轮真实运行。  
> 目的：记录会随智能提升放大的结构性问题；除少数原则外，不把当前解法固化成红线。

## 0. 一句话

当前很多问题不是“智能不够”，而是**状态机不封闭、动作不幂等、观测不单一**。  
智能拔高后，这些坑会被放大，不会自动消失。

## 2. 当前工程约束（可改，不是红线）

> 这些是当前阶段反复踩坑后的防护假设，不是永久原则。  
> 如果后续出现更强的状态机/规划架构，允许整体替换，不需要为这些约束让路。

### 状态机

1. **单一当前目标写者**：plan/tactic/strategy 不能各自改 current；抢占统一走事务。
2. **取消级联**：接管/放弃 plan 必须取消其 step goals，并释放 actionLock。
3. **外部任务有终态**：timeout/settle 必须停任务或明确 detached；不能留幽灵 Lua。
4. **锁存用稳定身份**：planId+cursor / tacticId + atom + interrupt，不用会变的 goal.id。
5. **执行状态单一来源**：execMode、plan.suspendedBy、gate reason 最好同源；矛盾先当 bug 查。
6. **恢复必须重评估**：挂起解除后先 world/postcheck，再续同一 cursor，不重跑整包。

### 进度与失败

7. **派发 watchdog**：plan active + N 秒无 atom begin → no_progress。
8. **进度 watchdog**：有 atom begin 但 steps/cursor N 秒不变 → progress stall。
9. **放弃是合法终态**：abandon/blocked 带 reason；是否无限 retry 由验收决定。
10. **失败预算按不同策略数**，不按次数；同参数≤2、同原子≤3。
11. **动作 ok ≠ 世界达成**：关键结果必须有 world/postcheck 或独立 oracle。

### 能力与包

12. **每个 strategy 至少一条可执行回退**；`tactics=0` 必须上报，不静默。
13. **长技能有界化**：count 小步、可续 cursor、可中断；不靠拆包绕 gate。
14. **威胁响应梯**：retreat → shelter → fight/ask/abandon，每阶有进入/退出谓词。
15. **不为通过测试加 lane 测试门**；夹具只改世界/配置/观测。

### 玩家可解释性

16. **30 秒可解释**：玩家能说出“在干什么、为什么、大概多久”。
17. **切换必须有新信息/完成/失败事件驱动**；无新信息切换率超阈值 = 碎片化。
18. **意图流优先于动作流**：日志/监控出口显示单一当前意图。

## 2.1 真红线（少，且只到原则层）

只保留三条真正不该被工程便利绕过的：

1. **证据完整性**：不伪造 world/postcheck；不用“动作 ok”冒充“世界达成”；关键结论要有独立证据。
2. **测试隔离**：夹具/GM 不得污染 Track A；产品路径不内置只为取证存在的测试门。
3. **安全边界**：测试便利不能压过真实生存反射；force_hold/lockfix 卡反射不进入产品。

除此之外，方案、状态机、watchdog、锁存、包结构都可以被更好的设计替换。

## 3. 智能拔高后最容易翻车的地方

- 更聪明的规划器会生成更多候选 → 若没有单一写者和锁存，抖动放大；
- 更长的动作链 → 若没有外部任务终态，幽灵任务放大；
- 更多并行需求 → 若没有 abandon/预算，死循环放大；
- 更强的注意力 → 若没有承诺窗口，玩家观感更 ADHD。

## 4. 建议修复顺序

1. 取消级联 + actionLock 释放；
2. timeout 停任务/清锁；
3. gate 状态单一来源；
4. 稳定身份锁存；
5. dispatch/progress watchdog；
6. 失败 abandon + 威胁响应梯；
7. 夹具 oracle 与玩家可解释性指标。

## 5. 不做

- 不靠“加更多战术包”掩盖状态机问题；
- 不靠调高/调低 priority 分数掩盖抖动；
- 不把 fixture 特判写进产品路径；
- 不把“苟住”当终态而不记录。
