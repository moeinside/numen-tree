# 24. 动态决策：效用仲裁（Utility Arbitration）

> 用户：战略优先度其实是动态变化的；需要一个更好的机制做动态决策。
> 结论：保留"安全/紧急"的硬优先级带，其余战略用**效用分数**竞争；在决策点重算，带迟滞/承诺/防饿死。

## 1. 为什么不用固定优先级

固定 P 级只能表达"谁更急"，表达不了：
- 同一战略在不同状态下价值不同（存材料：背包满/快死/在家时价值高）；
- 时间窗口（天黑前、天亮后）；
- 机会成本（跑一趟要多久、风险多大）；
- 承诺（已经做了一半，切换损失大）。

## 2. 分层：硬优先级 + 效用

```
P0/P1 安全紧急（本能、night_chase、低血）—— 硬优先级，可直接抢占
P2    主人/LLM 明确指令 —— 硬优先级（可被 P0/P1 抢占）
P3~P5 普通战略/工程 —— 效用分数竞争
```

- **硬优先级**保证"救命"永远优先，不被效用算错；
- **效用分数**只用于普通战略之间选"现在做哪件最划算"。

## 3. 候选（Candidate）接口

```js
{
  id: 'strategy.store_materials',
  level: 2|3,
  kind: 'need'|'strategy'|'project',
  eligible(state, ctx): boolean,          // 硬前置：时间/地点/资源/安全
  score(state, ctx): { total, parts },    // 0~100 效用
  preemptible: boolean,
  minRunSeconds: 8,                       // 最少跑多久再允许切
  cooldownSeconds: 30,                    // 放弃后冷却
  deadline(state, ctx): timestamp|null,   // 用于紧迫度
  run(ctx): Promise<Result>,
}
```

## 4. 分数公式（初版，权重可调）

```
score = 100 * clamp(
    0.30 * urgency        // 截止时间越近越高（如天黑前）
  + 0.25 * value          // 做完的收益（活命/资源保存/效率）
  + 0.15 * opportunity    // 当前时机好（在家/背包满/材料齐/顺路）
  + 0.10 * commitment     // 正在做/已投入的加成
  + 0.05 * starvation     // 等太久的补偿
  - 0.10 * risk           // 执行风险（敌对/夜晚/远）
  - 0.05 * cost           // 时间/路程/资源成本
)
```

- 各分量先归一化到 0~1；
- 权重放 `tree.config.json`（可调）；
- 每次决策记录 `parts`，便于 debug/调参。

## 5. 决策点（不是每 tick）

只在以下时机重算：
1. 当前动作/战术结束（成功/失败/抢占）；
2. 每 5 秒兜底；
3. 重大状态变化：死亡、入夜/天亮、发现敌对、到家、背包满、获得装备。

## 6. 迟滞与承诺（防抖）

- 当前战略有 **commitment 加成**；
- 只有 `score(new) > score(current) + margin(默认 8)` 且 `minRunSeconds` 已过，才切换；
- 放弃后 `cooldownSeconds` 内不重选同一战略；
- 硬优先级（P0/P1）不受迟滞限制，可在战术边界抢占。

## 7. 防饿死（starvation）

- 候选排队每 30 秒 +1 分（上限 +10）；
- 长期选不上的战略写入 trace/inbox（可选），让 LLM/主人知道。

## 8. 候选示例（当前阶段）

| 候选 | 层级 | 硬/效用 | 分数主要来源 |
|---|---|---|---|
| `night_safety` | L3 need | 硬（P1，黄昏后升） | 截止时间（天黑）+ 基地不安全 |
| `night_chase` | L3 need | 硬 P1（夜里被追） | 敌对/离家距离/reflex |
| `get_weapon` | L2 need | 硬（无武器+敌对 P1） | 死亡/敌对/时间 |
| `get_tools` | L2 need | 效用（P3 左右） | 缺工具 + 当前任务需要 |
| `secure_gear` | L3 strategy | 效用（需求触发时高） | 需求分数 |
| **`store_materials`** | L2/L3 strategy | **效用** | 背包满/在家/死亡风险/箱子空 |
| `light_base` | L2 strategy | 效用 | 火把/燃料/夜晚 |
| `prepare_for_night` | L3 协调器 | 硬（黄昏后） | 时间窗口 |

**存材料**是效用型战略的典型：
- 背包接近满 → opportunity 高；
- 快死/刚死过 → value 高（保存资源）；
- 在家/箱子空 → cost 低；
- 平时 → 分数低，不抢紧急任务。
