## 5. 必须遵守的设计边界（别破坏）

1. **树是"自动"不是"自主"**：查表 + 固定规则，不做价值判断。
2. **LLM 只有目标权/否决权/时间权**，没有逐步指挥权。
3. **树掌握节拍**：自己转，永不等 LLM。
4. **两条单向通道**：下行写目标，上行读事件；谁也不等谁。
5. **汇报 = 分类 + 事实字段，不给建议**。
6. **报了 = 已经停手等你**（自己还能处理的不报）。
7. **只有求助推，完成/通知拉**。
8. **台词库只查表不生成**；对话永远归 LLM。
9. **同一同伴同一时间只能有一个驱动者**。
10. **一个会话只启用一个预设**。

## 7. 下一步：打磨行为树（建议顺序）

**第一步：把生存闭环补全**（P0）
```
饿 → 有食物：吃
    没有食物：打被动生物取肉 → 有肉就吃
    附近没动物：探索找生物群系 / 搜箱子
    都没有：报告"要饿死了"，等大脑决定
```
这是目前最影响"像个活人"的一环。

**第二步：战斗策略**
```
血 > 60% 且有武器 → 打
血 ≤ 40% 或无武器 → 撤（retreat）
被围（敌对 ≥ 3）→ 撤
```
先做"评估表"，再谈战斗技巧。

**第三步：状态可见性**
- `tree_status` 增加：当前技能已运行秒数、上次动作结果
- 长任务在 trace 里每 N 秒写一条进度（技能内部 `print` 不会实时回来，需要别的手段）

**第四步：任务可中断**
- 目前长 `go_to` 卡住只能等 300 秒上限
- 需要"程序自己检查 deadline"或 mod 层支持

**第五步：生产智能化**
- 先扫（`scan.blocks` 多个候选）再决定
- 按背包需求决策（没镐子先做木镐 → 需要先砍树）

**第六步：多同伴协同**
- 资源互斥（别抢同一棵树）
- 跟随队形
- 分工（一个战斗、一个采集）

## 8. 踩过的坑（新会话必读）

| 坑 | 现象 | 解法 |
|---|---|---|
| `get_events` 长轮询独占 MCP 会话 | 动作调用被饿死、观测永远不更新 | **必须两个独立 NumenClient**（动作/事件） |
| 用 `Mcp-Session-Id` 判断连接 | 每次调用都重连 → 重连风暴（曾 121 次） | 用内部 `#connected` 标志 |
| 换档后僵尸锁 | `lua` 永远被拒，日志里却没新程序 | `numenlockfix` 补丁 mod（清 JVM 静态表） |
| 普通会话也有 numen 工具 | 别的会话偷偷驱动同伴 | 停用 profile 根级插入 |
| 长调用被 kill | 服务端槽位永久占用 | 客户端永不主动中断在途调用 |
| PowerShell 传 JSON | 引号被吃 → JSON 解析失败 | 一律用 `callfile` + 文件 |
| PowerShell 回写文件 | 加 BOM / 中文乱码 | 用编辑工具，别用 `Set-Content` |
| 冷却时间写反 | 失败后反而等更久 | `ready()` 是 `now - last >= cd`，反推时注意 |
| bat 中文乱码 | 编码/换行 | `chcp 65001` + UTF-8 无 BOM + CRLF |
