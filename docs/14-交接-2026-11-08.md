## 5. 已知坑与 SOP

### 5.1 僵尸锁（Lua 槽永久被占）

判定：`tree_status` 里 `slotBlocked` 持续上涨、`a program is already running...`；游戏日志最新 `[numen-program]` 远早于现在。
成因：程序没正常结束（切档 / 客户端死在调用途中 / 死亡打断在途调用）；`ServerPrograms.RUNNING` 是 JVM 静态表，不清理就一直拒。

**v3 后首选（不重建、不丢背包）**：
1. 树侧（默认已开，`behavior.lockRecovery`）：慢观测连续被拒 **2 次**会自动调补丁清锁，成功后发 `lock_unlock` 通知（不叫醒）。
2. 手动：`node src/cli.mjs lock` 看补丁状态；`node src/cli.mjs lock --companion helper` 清单个；`--all` 清全部。
3. 也可以直接打补丁端口：`GET http://127.0.0.1:8768/status`、`POST /unlock?uuid=<同伴id>`。
4. 兜底：游戏内 `/numenlockfix`（权限 2）。

**前提**：补丁 `numenlockfix-1.1.0.jar` 已在 `mods/`，但 **mod 只在 JVM 启动加载 → 换 jar 后必须重启一次 Minecraft**。重启后 `node src/cli.mjs lock` 应返回 `patch:"1.1.0", foundClass:true`；若 `foundClass:false`，看游戏日志 `[numenlockfix]` 行里的类加载器尝试链再修。

**最后手段（会掉背包、id 变）**：`control --op exit` 停树 → `delete_companion` + `create_companion`（见 patcher/README）→ 起树。只在补丁不可用时用。

**实测记录（2026-11-08 00:15）**：两个同伴夜里先后死亡（helper 被溺尸、tyrander 被蜘蛛），死时都有在途调用；**v2 补丁一条日志都没有、完全没清**，树被拒 27 分钟（142 次）。→ 这就是 v3 加显式日志 + 外部端口的原因。另：死亡时写地点簿出过一次 `EPERM rename places.json.tmp`（文件被占用），内存保留、后续写盘成功。

**预防纪律**：树进程**永不主动打断在途 lua 调用**（用 `control --op exit`，它最多等 240s 收敛）；开发重启树前先看 `status`：不要在同伴飞 `go_to`/`seek_food`（detached `move.go`）时重启。

### 5.2 其他高频坑（细节见 docs/13）

- PowerShell 传 JSON 会被吃引号 → args 文件 + `callfile`
- `Set-Content` 写文件加 BOM → 用编辑工具或 `UTF8Encoding($false)`
- Windows PowerShell 5.1 按 ANSI 读 `.ps1` → 脚本 ASCII-only
- `reload-skills` 要给 ESM 模块加 `?t=` 破缓存（已修）
- 观测 3.6s/1.2s 分层；Lua 单程序 200 次 API 调用上限；`numen.task.timer` 会**打断**程序（别用它报进度）
- **游戏重启后必须重启树**：旧树的 numen MCP 会话会失效，表现是 `this tool needs a 'companion' argument` / `fetch failed`，树会在那里空转（2026-11-08 01:16 实证）。先 `control --op exit`，再 `node src/daemon.mjs`。
- 补丁 v3 的 `[numenlockfix]` 日志**不会进 latest.log**（stdout 没被文件 appender 收），诊断以 `GET http://127.0.0.1:8768/status` 为准。
