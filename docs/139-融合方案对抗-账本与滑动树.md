# 139. 融合方案对抗：账本 + 滑动树

> 2026-11-12。点子王 × MC 专家对抗后收敛。  
> 前提：B 日记本管跨天承诺；A 滑动树管当前焦点；执行器管原子事实。

## 1. 最终结构

```text
B 账本
  承诺 / 债 / deadline 窗口 / 进展证据引用 / 配额
  不存执行态（cursor/tactic/next step 一律不存）

打分器
  只排序，不生成承诺
  读 B + 只读 snapshot
  输出候选与硬资格透传，不自己算硬资格

A 滑动树
  只接收「当前焦点」的候选子集
  焦点内选择/抢占/下滑/恢复
  不跨焦点换目标

执行器
  actionLock / atom tx / cursor / steps_done / postcheck
  唯一执行事实来源
```

```text
唯一决策出口 = A 的输出 intent 队列
执行器只消费这一条流
```

## 2. 最小数据契约

候选只保留 6 条：

```text
commitmentId
predicateRef + must|soft
deadlineWindow（before_dusk / before_day_end / within_night ...）
evidenceRef
eligible
basis { snapshotSeq, gameTick, ttl, staleFields }
```

砍掉：

```text
horizon（由 deadline 推）
debtAge（B 内部用）
progress 明细（只留引用）
```

## 3. 硬资格 vs 软分

### 硬资格（只能拒绝，不能加分）

```text
硬安全信号
deadline 已过 / must 过期
前置事实不满足（工具/站点/在场）
known unreachable
actionLock/单槽占用
stale/unknown 字段不得满足前置
```

### 软分（只能排序，不能放行）

```text
priority
接近的 deadline
机会成本
progressEvidence 摘要
```

关键：

```text
硬资格由执行器/事实层计算并透传
打分器不能自己算 eligible
否则会出现两套硬约束
```

## 4. 冲突裁决

```text
执行事实 > B 账本
postcheck 与候选冲突 → 候选作废
B 只能接受作废，无申诉权
A 不能反写 B
```

顺序：

```text
1. 候选 basis 过期 → stale，取消资格
2. postcheck 冲突 → 候选作废，回写 B
3. hard signal → A 立即抢占，候选挂起
4. 无新事实 → 才允许用候选
```

## 5. deadline/债本防过期

```text
B 只记意图与约束，不记世界事实
deadline 用窗口语义，不写绝对 tick
basis 带 snapshotSeq/gameTick/TTL
basis 过期 → 债条降级为 hypothesis
必须一次现场观测后才能重新晋级
deadline 到点只产生评估请求，不产生动作
```

## 6. 原子阻塞/抢占写权限

| 时机 | B 可写 | A 可写 |
|---|---|---|
| 原子阻塞中 | 计划/债/配额（纯本地） | 焦点、候选评分、抢占请求 |
| 抢占发生 | 挂起/pending + 原因 | 抢占请求 |
| 原子完成 | 从 result 派生账 | 从 result 派生下一步焦点 |

共同禁止：

```text
actionLock
plan.cursor
steps_done
atom tx
FactStore known
```

## 7. 双方让步

```text
点子王：
  接受 A 保留「焦点内下滑/上浮」
  仅限当前焦点内部，不允许跨焦点跳

MC 专家：
  接受唯一决策出口 = A 的输出队列
  执行器只消费这一条 intent 流
  每个 intent 必须带 snapshotSeq + reason + basis
```

## 8. 判负（任一即失败）

```text
A 读到焦点外候选并据此换焦点
B 账本里出现执行态（cursor/tactic/next step）
除唯一写者外任何组件写 B
打分器输出「新承诺」而非仅排序
候选 basis.gameTick 早于最近 postcheck/世界变化
却仍被派发 atom
```

## 9. 一句话

```text
B 记“欠什么、何时该看”，A 选“当前焦点下一步”，
执行器说“世界事实是什么”；
打分只排序，事实永远赢。
```
