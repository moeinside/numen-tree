# 119. 3D 空间与到达判定共识

> 2026-11-11。行为学家 + MC 专家 + 点子王圆桌。  
> 触发：同伴 y68、家 y59，水平 7 格 < 12 → 树判定“已在家”，实际在房间外。

## 1. 共识

```text
缺 3D/体积是“到达/归属判定”的系统性根因。
不是所有移动问题的根因。
```

必须分开两类：

### A. 到点/归属判定错（3D/体积问题）

会用水平距离当“到家”：

```text
dist = hypot(dx, dz)
dist <= radius → at_home / at_safe_point
```

表现：

```text
在房顶/地下 → 判定已到家
回家不进屋
“到了但不动”
```

### B. 目标不合法 / 不可达（no_path 问题）

```text
目标点在方块里/悬空/水里
落差 >1 且无阶
门/活板门未开
水/岩浆/悬崖
远距/未加载
```

这些 **加 3D 距离不会自动好**。

## 2. 四种口径，各用各的

| 口径 | 用途 |
|---|---|
| 3D 距离 | 到家/回安全点/leash/交付/“是否附近” |
| 体积包含 | 家/基地/活动中心归属 |
| standable target | 所有 move.to 之前 |
| route reachability | 候选生成后、派发前 |

“在家”应满足：

```text
3D 距离 ≤ radius
且 |Δy| ≤ 2（同屋/同层）
且 能站在屋内
```

不能只用水平距离。

## 3. 审计清单

已知 2D 到点判定：

```text
safetyHold
returnHome
#leashAnchor
交付/储物到点
```

目标合法性：

```text
所有 move.to 目标是否经过 standable 校验
```

`no_path` 归因：

```text
必须带 from/to/距离/目标方块/plan.reason
```

## 4. 最小改法

```text
1. 新增 space 模块：3D distance / isInside / standable
2. 先只改“到达/归属”调用点
3. move.to 目标加 standable → route.plan 两级预检
4. 不改执行器、不改全局路径规划
5. 每类调用点单独迁移 + 回放
```

不要一次性把所有距离都替换成 3D。

## 5. 与 P0 的关系

```text
属于 P0 谓词层修复，不单开阶段。
不替代 DispatchGate/latch 主线。
优先于任何功能扩展。
```

理由：不修则所有 home/leash/交付/巡逻结论都不可信；动作 ok 但世界没达成，属于 P0 的假成功。

## 6. 验收

夹具：

```text
同伴站在家屋顶正上方
水平 ≤7，垂直 9
tether=home
跑 30s
```

通过：

```text
不报 at_home/at_safe_point
发起回家
30s 内 3D 距离 ≤3 且 |Δy| ≤1
```

判负：

```text
30s 内出现 at_home/at_safe_point 且同伴无位移
→ 假成功
```

## 7. 结论

```text
修 3D/体积：解决“以为到了”
修 standable/reachability：解决“根本到不了”
两件事都做，但不能混成一件。
```
