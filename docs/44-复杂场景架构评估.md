# 44. 复杂场景架构评估：Profile / Milestone / Arbiter / Planner

> 2026-11-09。基于“Profile 管理器 + milestone 粒度 + 有界规划器 + ResourceLedger + 优先度”这套目标架构，
> 评估可预见复杂场景下运行结果是否符合预期。

## 1. 目标架构

```text
反射/本能（最高）
  ↓
Arbiter：选一个 work unit（need / routine / profile milestone）
  ↓
ProfileManager：活跃长期任务、milestone、checkpoint、依赖
  ↓
Planner：对当前 milestone 做有界分解/选路
  ↓
Executor：战术/原子；settle
  ↑
Facts / Readiness / ResourceLedger（共享事实与资源占用）
```

不变量：

1. 每个同伴同一时间只执行一个 work unit；
2. 反射可随时抢占，规划器挂起而非销毁；
3. 恢复前必须重新校验事实；
4. 多个 profile 只能通过 milestone 竞争，不并发执行；
5. 共享资源/前置要复用或认领；
6. 做不到就求助，不无限重试。

## 3. 结论

### 能解决

- 单同伴、多复杂 profile 的**串行调度**；
- 反射打断后的挂起/恢复/重规划；
- 共享前置复用与资源冲突（需 ResourceLedger）；
- 缺工具/缺水/缺炉的降级；
- 失败求助而不是无限重试。

### 不能解决

- numen 执行限制（例如冰面安全挖掘）；
- 世界资源确实不存在；
- 没有方法库/前置模型时的规划；
- 多同伴共享项目；
- 在线学习/自创战略；
- 人格/情绪/长期记忆。

### 当前实现差距

- 单意图调度有了；
- 压力/注意/本能有了；
- Readiness 第一版有了；
- **ProfileManager / milestone / ResourceLedger / 有界规划器还没有**；
- 所以现在 2~3 个复杂任务会退化成“优先级抢目标”，没有真正的 milestone 管理。

## 4. 反复推翻的根因

之前的问题是：

1. 先改组件，没先定义**场景矩阵与验收**；
2. “战略包/优先度/计划”责任边界反复变化；
3. 缺 profile/milestone 这个中间层；
4. 每次遇到新场景就往 onFail 里塞分支。

修正方式：

- 以本矩阵作为**行为契约**；
- 先实现一个纵向切片（food_security）；
- 再补 ProfileManager/ResourceLedger；
- 用回放/实机逐条验收，不再整体推翻。
