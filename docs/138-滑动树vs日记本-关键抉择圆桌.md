# 138. 圆桌：滑动树 vs 日记本（关键抉择）

> 2026-11-12。点子王 × 行为学家 × 总控 × 项目经理 × 玩家代表。  
> 用户直觉：滑动树高速稳定但“中间缺了什么”；日记本拟人但体感怪。

## 1. 结论

```text
不是 A/B 二选一。
A 和 B 不在同一轴：
  A = 同一时刻怎么选、怎么抢占、怎么下滑
  B = 跨时间怎么记住承诺、进展、欠债、再入
```

真正的关键决策：

```text
承诺与进展由谁记账？
```

不是“选五层树还是选日记本”。

## 2. 用户直觉对应什么

```text
“A 中间缺了什么”
  = 跨段/跨天的承诺账、进展账、再入
  = 不是缺层级，是缺时间维度

“B 体感有点怪”
  = 缺即时显著性层，反应像按议程过日子
  = 管理语言外露：议程/配额/债本/日结像上班
  = 再入没有玩家可理解的叙述
```

## 3. 两方案各自只占一轴

```text
A 滑动树：
  强在即时选择、稳定、不抽
  弱在时间连续性：5 分钟后无话可说

B 日记本：
  强在跨天连续、欠债、进展、再入
  弱在即时反应、显著性竞争
  表达容易像项目管理系统
```

玩家验收一句话：

```text
A 回答“不抽”
B 回答“不呆/不空”
活人 = A 的速度 + B 的记忆，但不能用 B 的词汇
```

## 4. 推荐结构

```text
B 的账本层做骨架：
  议程 / 焦点 / 债本 / 进展账 / 配额 / 日结

A 只做焦点内的快速选择与追溯：
  候选排序 / 抢占 / 下滑 / 原子边界
  不做 A2 每日排班表
  不另开仲裁
```

硬约束：

```text
同一时刻只有一个目标决策者
只有一条 reason 链
禁止两套调度都能改目标
```

## 5. 为什么不直接选 A

```text
A 再快，也不会自己长出“欠了什么、做到哪、为什么回来”。
加更多层级不解决时间账本。
A 的扩展空间在“焦点内选择/执行”，不在替代账本。
```

## 6. 为什么不直接选 B

```text
B 有连续性，但如果没有即时显著性层：
  近身威胁/玩家呼叫反应慢
  焦点切换像课表
  空焦点像发呆或演戏
```

## 7. 落地建议

### 先影子，不拍死

```text
同一批真实 trace
预登记阈值
A/B 只读并行计算
比较：切换率、长期进展、可解释性、诊断判定
跑 1–2 个游戏日
```

判负：

```text
A/B 没有出现“两边不同且都有理由”的分叉
或指标无法区分两条轨迹
→ 实验无效，不得据此选型
```

### 若必须现在定方向

```text
B 做目标/承诺层
A 只做焦点内排序与追溯链
禁止 A2 每日排班 + B 议程两套并存
```

## 8. 最小第一步

```text
V3 薄骨架：
  3–5 条结果型议程（谓词 + deadline）
  单焦点
  再入线索
  空焦点基线

只加 A 的两个成分：
  显著性打断（轻量即时层）
  焦点内候选排序（不做 A1–A5 全套）
```

用 P1.1 live probe 验证：

```text
决策速度
债务遗漏
2 天不可逆进展
reason 链
```

## 9. 一条判负

```text
日终有议程项：
  未完成
  未进债本
  无放弃理由
次数 > 0
→ 静默丢债，判负
```

## 10. 一句话

```text
滑动树是“手和眼”，日记本是“账和记忆”；
缺的不是更多层级，是让手眼知道自己在还哪笔账。
```
