# 127. 最终施工顺序（点子王 × 总控 × 项目经理）

> 2026-11-11。三方对抗后的最终决定。  
> 目标：先让 P0 用可判负证据出线，再按 V3 线推进；不先造排课引擎。

## 1. 最终顺序

```text
S0  P0-2 收口：latch / watchdog / gate 真实证据
S0.5 P0-3 时间/空间事实回归
S1  P1  V3 薄骨架：议程 + 单焦点
S2  P1  V3.1 薄长期层：债本 + 日结 + 配额
S3  P1 末 V3.2 倾向种子：只读/可复现实验
S4  P3/P4 V4 多同伴分工
```

**V2 不单独施工**：段表只做 V3 的昼夜/暴露门控，不做排课引擎。

## 6. P1 高优先级插入项：树诊断工具

watchdog 升级为**树的只读诊断工具**，不是角色判断：

```text
输入：plan / goal / actionLock / 世界快照 before-after / trace
输出：progressing | waiting | stalled | contradiction | unknown
      + 证据 + 建议
约束：只建议，不派动作；最终决策仍由策略层
```

用途：

```text
发现假工作：plan active 但世界没变
发现目标已满足仍在做
发现重复失败/矛盾
为其他策略提供统一证据
```

阶段：

```text
P0：不改，保留现有 watchdog 契约
P1：优先实现只读诊断器
P2：再考虑策略自动消费
```

一句话：

```text
P0-2 真实验收 → V3 薄骨架 → V3.1 长期层 → V3.2 只读种子 → V4；
V2 只当门控，不当排课引擎。
```
