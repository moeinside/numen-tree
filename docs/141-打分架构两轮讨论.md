# 141. 打分架构两轮讨论：外层档位 + 内层方法

> 2026-11-12。点子王 × 行为学家 × MC 专家。  
> 第一轮发散，第二轮对抗。最终设计如下。

## 1. 最终结论

```text
不采用单标量效用。
不采用纯词典序。
采用：外层档位/承诺 + 内层方法排序。
```

```text
外层：不可补偿的档位 + 当前承诺 + allowedMethods
内层：只在 allowedMethods 内排方法
执行器：拒收 methodId 不在 allowedMethods 的派发
```

## 2. 为什么淘汰单标量

```text
可补偿性错误：
低血 + 远处资源
→ 加权和让“多砍一棵树”补偿“用命换木”
```

```text
不可证伪：
换权重就换答案
“为什么砍树”答“0.37 > 0.35”
```

单标量只保留为早期调试对照，不作为正式架构。

## 3. 为什么纯词典序也不行

```text
高档次永远非空：
饥饿 17，永远差 1
→ 永久压制资源/工具
→ 木镐永不补
```

```text
悬崖效应：
低血 9 vs 10 微差
→ 行为大跳变
```

所以档位必须：

```text
带阈值 + 迟滞
只做“拒绝/允许”
不做无限期绝对优先
```

## 4. 外层契约

```text
outerDecision {
  schemaVersion,
  snapshotSeq, gameTick,
  tier,                 // life / irreversible / reversible / opportunity / maintenance
  commitmentId,
  deadlineWindow { openAt, closeAt, remainingSec },
  allowedMethods[],
  staleFields[]
}
```

外层职责：

```text
分档（不可补偿）
选当前承诺/焦点
给 allowedMethods
拒绝过期/不合格
```

不负责：

```text
不给单标量总分
不排方法
不写执行态
不派动作
```

## 5. 内层契约

```text
innerDecision {
  methodId,   // 必须 ∈ allowedMethods
  score,
  rank,
  basisSeq
}
```

内层职责：

```text
只在固定焦点/allowedMethods 内排序
按 expectedProgress / cost / risk / reversibility / failure history
```

不负责：

```text
不改 tier
不改 focus
不跨档比较
不写 B
```

## 6. 防双真相

```text
外层唯一写 tier/commitment/allowedMethods
内层唯一写 method order
执行器拒收 methodId ∉ allowedMethods
内层发现档位错 → 只能发重分档请求，不能自行升档
每条 action 记 focusId/version
```

冲突：

```text
执行事实 > 外层档位 > 内层排序
```

## 7. 档位与防饿死

档位：

```text
life
irreversible_loss
reversible_need
opportunity
maintenance
```

规则：

```text
跨档不可补偿
但高档次不是永久占用
用阈值 + 迟滞 + 最小维持配额
```

例：

```text
生命档只在 HP/饥饿低于阈值时激活
离开阈值后必须释放
maintenance 有最低保底
```

## 8. 更新节拍

外层：

```text
事件驱动：硬信号、deadline、进展、玩家干预
+ 段边界保底
不每 tick 重算
```

内层：

```text
焦点进入
原子边界
方法失败
不每 tick
```

所有输出带：

```text
basis { snapshotSeq, gameTick, ttl }
```

过期：

```text
stale 候选不可执行
旧 basis 不得派 atom
```

## 9. 先做哪层

### 先做内层方法级

```text
固定 focus + allowedMethods 桩
验证 decision_tick 不被动作阻塞
验证原子边界切换
验证方法失败可换
```

### 外层先影子

```text
固定档位表 + 固定 deadline
只记录不接管
与现有打分对照
```

### 后接管外层

```text
B 账本稳定后
外层档位 + 承诺接管
```

## 10. 最小切片

```text
单焦点
3 个方法候选
allowedMethods 硬门
P1.1 live probe
```

判负：

```text
actionLock 期间 decision_tick 中断或间隔 >2× 节拍
派出 methodId ∉ allowedMethods
焦点在原子边界外变更
```

## 11. 两轮让步

```text
点子王：
接受外层档位化，但档位只拒绝、不排序。

行为学家：
接受内层先落地、外层先影子。

MC 专家：
接受外层档位由执行事实层提供，
打分器只消费标签，不自己推导档位。
```

## 12. 一句话

```text
外层只分档（不可补偿），内层只排名（快而不阻塞），
执行器用 allowedMethods 做最后一道闸；
档位由事实层给，方法分由打分器给，
两者永不同时决定“做什么”。
```
