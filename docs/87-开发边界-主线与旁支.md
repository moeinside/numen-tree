# 87. 开发边界：主线与旁支

> 2026-11-10。Lead 开发动作硬禁令。  
> 目的：防止 Lead 从“树工具开发”跑偏到旁支工具实现。

## 1. Lead 只负责树工具

Lead 可以直接开发、修改、调试的范围：

```text
src/
  lane / needs / drives / attention / instinct
  strategy / recipes / tactics / atoms
  perception / action-tx / predicates
  goalstore / goalresume / places / worldmem
  schedule / time / state / ...
```

也包括：

- 树工具的行为逻辑、架构、P0 验收；
- 树的测试/回放/审计；
- 树相关文档（docs/、PROJECT-*）。

## 2. 旁支工具一律交子体

旁支包括：

- Pilot Harness / 试驾员；
- mode/lease/互斥；
- Dev GM mod / 命令 portal；
- dsh-bridge、日志/分段/归档工具；
- 其他开发辅助、观测、实验工具。

Lead 只做：

1. 和用户讨论想法；
2. 写需求/边界/验收（一页）；
3. 交给独立工具子体；
4. 看交付、验收、退回；
5. **不直接写旁支工具代码，不直接修旁支 bug**。

## 3. 工具子体必须交维护文档

任何旁支工具交付必须包含：

- `README.md`：用法/命令；
- `MAINTENANCE.md`：架构、状态机、端口、故障处理、升级/回滚；
- `TESTPLAN.md`：验收清单与负样本；
- 变更日志。

没有维护文档 = 不算交付。

## 4. 独立维护子体

- 工具实现与工具维护分开；
- 独立维护子体负责长期维护、回归、文档时效；
- Lead 不兼任工具维护；
- 维护子体只改 `tools/` 和工具文档，不碰 `src/`、验收口径。

## 5. 旁支不阻塞主线

- 树主任务优先；
- 旁支工具只在：
  - 主线明确需要；
  - 有独立子体；
  - 不影响 Day1/验收
  时启动；
- 旁支讨论不能变成 Lead 的实作任务。

## 6. 当前状态

- 树主任务：P0-0b / early_survival / Day1；
- 旁支开发工具：已暂停，现有文件保留，不再由 Lead 修改；
- 后续旁支实现全部走独立工具子体。

## 7. 一句话

> **Lead 的手只碰树；旁支工具只碰需求和验收；实现和维护交给独立子体，且必须留下维护文档。**
