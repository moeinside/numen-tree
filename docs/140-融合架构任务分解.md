# 140. 融合架构任务分解：滑动树 × 打分 × 账本 × 执行

> 2026-11-12。理想架构已同意，本文只拆任务与接口。

## 1. 总图

```text
B 账本（跨天承诺/债/进展）
        │  只读承诺快照
        ▼
打分模块（只排序，不生成承诺）
        │  decisionInput（当前焦点候选子集）
        ▼
A 滑动树（焦点内选择/抢占/下滑）
        │  intent 队列（带 basis）
        ▼
执行器（actionLock / atom / postcheck）
        │  结果事件
        ▼
B 账本（只从 result 派生进展/债）
```

单向环：

```text
B → 打分 → A → 执行 → B
```

任何反向写：

```text
A 写 B
打分写承诺
B 写执行态
执行器直接改 A 焦点
```

都判为双调度/双写。

## 2. 两主模块

### 模块 1：打分

职责：

```text
读 B 承诺 + 只读世界快照
生成当前焦点候选
排序软分
透传硬资格
标 stale/TTL
```

不负责：

```text
不生成承诺
不决定当前焦点
不算硬资格
不写 B
不派动作
```

交付：

```text
decisionInput {
  snapshotSeq, gameTick,
  candidates: [{
    commitmentId,
    predicateRef,
    must|soft,
    deadlineWindow,
    evidenceRef,
    eligible,
    basis { snapshotSeq, gameTick, ttl, staleFields }
  }],
  hardSignals,
  staleFields
}
```

### 模块 2：滑动树

职责：

```text
只接收当前焦点候选子集
焦点内选择/抢占/下滑/恢复
输出唯一 intent
不跨焦点换目标
```

不负责：

```text
不读焦点外候选
不排日计划
不写 B
不写执行态
```

交付：

```text
intent {
  goalId, methodId, atom/tactic,
  basis snapshotSeq/gameTick,
  reason,
  preempt: none|soft|hard
}
```

## 3. 两个共享层

### B 账本

管：

```text
里程碑（承诺）
deadlineWindow
债本
进展账
配额
再入线索
```

不管：

```text
cursor / tactic / next step
当前焦点
actionLock
```

### 执行器

管：

```text
actionLock
atom tx
cursor / steps_done
postcheck
执行事实
```

不管：

```text
目标选择
跨天账
优先级
```

## 4. 跟里程碑/战术包/战略表怎么咬合

```text
里程碑 = B 的承诺表示
战略表 = 方法库/适用条件，不是调度器
战术包 = A 焦点内的方法节点
原子 = 执行器的最小事务
```

规则：

```text
战略表不能自己写当前焦点
战术包不能在 A 之外另开抢占
里程碑不能存执行态
```

它们是“数据/库/节点”，不是第四套调度。

## 5. 接口卡点

### 卡点 1：B → 打分

只读承诺快照：

```text
commitmentId
predicateRef
must|soft
deadlineWindow
evidenceRef
```

打分不得回写。

### 卡点 2：打分 → A

只给当前焦点候选：

```text
eligible 由执行/事实层透传
basis 必须带
过期/stale 候选直接剔除
```

A 不得请求焦点外候选。

### 卡点 3：A → 执行器

唯一 intent 流：

```text
必须带 snapshotSeq + gameTick + reason
执行器按原子边界接受/拒绝
```

执行器不得自己换焦点。

### 卡点 4：执行器 → B

只传结果：

```text
success/failure
postcheck evidence
progress evidence ref
```

B 只派生债/进展，不申诉。

## 6. 任务拆分

### P1-A 账本 B

```text
schema：承诺/截止窗口/证据引用
生命周期：active/blocked/done/abandoned
债本结转、进展账、日结
单写者
```

### P1-B 打分

```text
读 B 快照
候选生成
must/soft 资格透传
TTL/stale
软分排序
```

### P1-C 滑动树 A

```text
当前焦点候选子集
焦点内选择/抢占/下滑
intent 队列
basis 透传
```

### P1-D 执行器

```text
actionLock
atom tx
postcheck
结果事件
原子边界
```

### P1-E 影子集成

```text
A 只读并行
与现有打分对照
同一 trace / 同一夹具
不接管动作
```

## 7. 依赖顺序

```text
1. B schema + 单写者
2. 执行结果事件
3. 打分 candidate contract
4. A 当前焦点选择
5. 影子对照
6. 窄缝接管
```

不能先做：

```text
先重写 A 再补 B
先让打分生成承诺
先让 B 存执行态
```

## 8. 判负

```text
A 读焦点外候选并换焦点
B 存 execution state
打分器生成承诺
执行器改 A 焦点
除唯一写者外写 B
intent 缺 basis
```

## 9. 一句话

```text
四个模块不是解耦成四个大脑，
而是用四个契约串成一个单写者闭环；
卡嵌是接口卡嵌，不是状态互相写。
```
