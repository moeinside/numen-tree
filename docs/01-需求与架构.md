# 需求与架构

> 本版已吸收 2026-11-07 的活体探针结论（见 `02-探针记录.md`），相比最初设想**简化了一块关键设计**。

---

## 1. 问题

- Numen 同伴**没有 MCP 驱动就完全不动**（唯一内置本能：遇敌逃跑）。
- 所以现在 LLM 在做所有决定，包括"卡住→跳→跳失败→挖-跳"这种反射级动作。
- 代价：每次决策重新 prefill 大段固定前缀（实测 207,639 in / 670 out）；DSH 循环是"工具返回必推理一次"，空轮询也花钱。
- 附带：单 Lua 槽、长调用被 kill 有僵尸锁风险。

## 2. 需求

1. 同伴能**自动连续行动**，不需 LLM 逐步参与。
2. LLM 只保留：目标权、否决权、沟通权。
3. 异常**结构化上报**，一次看懂。
4. 可续跑、可调试、**可扩展**（新 mod 新功能能接进来）。
5. 多同伴支持（不做死成单同伴）。

## 3. 设计原则（八条铁律）

1. **树是"自动"不是"自主"**：确定性程序，查表 + 固定恢复阶梯，不做价值判断。
2. **LLM 有目标权/否决权/时间权，没有逐步指挥权**。
3. **树掌握节拍**：自己转，永不等 LLM。
4. **两条单向通道**：下行写命令盒，上行读事件；谁也不等谁。
5. **汇报 = 分类 + 事实字段，不给建议**。
6. **报了 = 已经停手等你**（自己还能处理的一律不报）。
7. **只有求助是推的，其余都是拉的**。
8. **贵的思考外包给右脑，结果内联、沉淀成宏计划**。

## 4. 分层

| 层 | 是什么 | 频率 | 干什么 |
|---|---|---|---|
| 大脑 | DSH 的 LLM | 事件驱动 | 目标、计划、说话、协调 |
| 右脑 | 一次性子 agent | 需要时 | 拼宏计划、大规划、情报整理、事后叙述 |
| 小脑（树） | 外部常驻进程 | 一直转 | 查表、任务下发、状态机、哨兵、trace |
| 脊髓 | mod 内置反射 | 游戏 tick | 遇敌跑、脱困、落地缓冲、憋气 |

## 5. 数据流

```
             ┌──────────────────────────────┐
             │   大脑：LLM（DSH 会话）        │
             └───────────┬──────────────────┘
                         │
        下行（写命令盒）  │            ▲ 上行（事件 / 摘要）
        goal / control    │            │
                         ▼            │
             ┌──────────────────────────────┐
             │   小脑：树进程（常驻）         │
             │   目标栈 / 技能卡 / 哨兵 / trace│
             └───────────┬──────────────────┘
                         │
              MCP：只有"动作"占 Lua 槽
              get_events / say 不占槽
                         │
                         ▼
             ┌──────────────────────────────┐
             │   numen（游戏内）              │
             │   任务系统 + 恢复阶梯 + 反射    │
             │   身体：N 个同伴               │
             └──────────────────────────────┘
```

**关键：树是 DSH 与游戏之间的唯一接口**，避免两个调用方抢同一个 Lua 槽。

## 6. 执行模型（探针修正后的版本）

```
① 一次 lua 放一个任务 → 程序等它结束
② 主人说话打断 → 程序立即返回，任务继续后台跑
③ 后台任务在跑时 → Lua 槽是空的（只读 lua / get_events / say 都能用）
④ 改主意 → 直接派新任务，旧任务自动被取代
⑤ 任务结束 → task_finished 事件进收件箱
```

**因此不采用最初的"10–20 秒切片循环"设计。** 理由：

- mod 的任务本身有边界，内部已有 `RecoveryLadder` / `UnstuckChain` / `Watchdog`；
- 抢占靠"派新任务"天然实现，不需要 cancel 原语；
- `task_finished` 事件就是完成上报。

树的实际工作因此变成：**目标栈裁决 + 任务下发 + 事件归纳 + 升级判断**。比原方案薄很多。

## 7. 与 mod 已有能力的边界（不要重复造）

| 能力 | 谁提供 | 树要不要自己写 |
|---|---|---|
| 走路/挖/打/造/合成 | `numen.*` Lua API | ❌ |
| 卡住脱困、落地缓冲、憋气 | `UnstuckChain` / `MLGChain` / `BreathChain` | ❌ |
| 失败重试策略 | `RecoveryLadder`（rung + FailureType） | ❌ |
| 危险动作同意 | `permission.Gate` / `ConsentDesk` | ❌（只需配置） |
| 任务生命周期与持久化 | `TaskApi` / `TaskPersistence` | ❌ |
| **选什么目标、什么时候换** | —— | ✅ **这正是树存在的理由** |
| **对 LLM 的接口与唤醒预算** | —— | ✅ |
| **跨同伴协调与资源占用** | —— | ✅ |

## 8. 多同伴

- **一个树进程管一组同伴**（不是每同伴一个进程）：共享世界模型、便于协调、单一 LLM 接口。
- 每同伴一条串行动作队列；不同同伴可并发（Lua 槽是按同伴的）。
- 状态：每同伴一套黑板 + 一块共享区（谁在哪、谁占了什么资源）。
- LLM 侧 `companion` 参数是**枚举**，不是自由文本。
- 实际天花板更像游戏性能（2–4 个舒适），不是树。

## 9. 社交分层

| 层 | 归谁 | 成本 |
|---|---|---|
| 协同（让路、轮流用工作台、别抢同一只怪、递东西） | 树（机械） | 零 |
| 低级社交（打招呼、道谢、让一让） | 树 + 模板台词 | 零，但会重复 |
| 高级社交（关系、承诺、谈判、讲故事） | LLM，**事后叙述** | 定期一次，不是每次互动 |

"事后叙述"：树记录交互流水（谁给了谁什么、一起打了什么），LLM 定期把流水变成对话。比实时寒暄便宜，而且更像人。

## 10. 左右脑

- **左脑**：一个 DSH 会话，管所有同伴，按同伴切换 persona。
- **右脑**：一次性子 agent，全新上下文（不用 fork），纯函数：输入目标 + 目录，输出计划数据，无副作用。
- 两者之间靠**宏计划库**连接：右脑产出一次 → 左脑校验保存 → 以后零成本复用。

## 11. 模式并存

| 模式 | 内容 |
|---|---|
| `numen 脑模式`（旧） | 原样不动，做对照与回退 |
| `numen 脑树模式`（新） | 重写 persona + 树的 MCP 连接 + 时间注入 + 压缩 |

规则：一个会话只启用一个预设；一个同伴同一时间只被一个会话驱动。

## 12. 牵引绳（leash）

**问题**：同伴被怪追、或者执行完任务后，会离主人越来越远且不会自己回来。

**做法**：树在**空闲时**（没有其它目标）检查 `ownerDistance`，超过阈值就自动加一个
`go_to(owner)` 目标。带冷却（默认 15 秒），不会刷屏，也不会干扰正在执行的任务。

```json
"leash": {
  "enabled": true,
  "maxDistance": 32,
  "minIntervalSeconds": 15,
  "priority": 5,
  "skill": "go_to",
  "params": { "target": "owner", "range": 4 }
}
```

**实测**（2026-11-07）：把同伴派到 40 格外 → 距离 40.9 时触发
`leash 离主人 41 格 > 32，加目标 g2 回去` → 约 15 秒后回到主人身边 4.1 格。

**边界**：只在空闲时生效。如果同伴正被 mod 的逃跑反射带着跑，树不会打断它；
等反射结束、树拿到空闲 tick，牵引绳才接管。

## 13. 行为模式（2026-11-07 新增）

每个同伴独立一个模式，可随时切换（`tree_control` / CLI），互不影响。

| 模式 | 干什么 | 关键参数 |
|---|---|---|
| **survival**（默认） | 只保命：饿了吃、血低于阈值撤退、太远牵引回来 | `survival.retreatHp` / `eatHunger` / `fleeDistance` |
| **production** | 挖资源：轮换方块列表，连续找不到就出去探 30 秒 | `production.blocks / count / radius` |
| **combat** | 主动清怪：16 格内有敌对就打最近的 | `combat.radius` |

**仲裁顺序**（固定规则，不做判断）：

```
生存检查（血/饿） → 模式行为（combat / production） → 牵引绳 → 待命
```

每种自动行为有独立冷却；失败后按类型拉长冷却（`gather` 6 秒换下一种，其它 2 倍）。
所有自动行为的目标都带 `note: auto:<key>`，便于在 trace 里区分"人下的"和"树自己下的"。

实测与多同伴结论见 `08-试验记录-三模式与多同伴.md`。
