# 53. 触手与架构的感知契约

> 2026-11-10。检查 tentacle v0.3 实际输出与架构 Facts/Readiness/SiteRegistry 的假设后，结论：
> **架构不能把“触手信息”当成完备事实源；必须补 PerceptionContract + ObservationPlan + 三态事实。**

## 1. 触手 v0.3 实际提供什么

代码：`tentacle/src/numentree/tentacle/NumenTreeTentacle.java`、`src/tentacle.mjs`。

| 类别 | 提供 | 说明 |
|---|---|---|
| self | uuid/name/pos/yaw/pitch/hp/max_hp/food/dimension/light/day/day_time | 不含背包/手持/护甲 |
| entities | 视锥内实体 id/type/category/x/y/z/distance | 数量/距离受限 |
| landmarks | kind/x/y/z/distance | 可能未完全按 FOV/LOS 过滤 |
| water | open_count/ice_covered_count/nearest_open/nearest_ice | 可能穿墙/穿地层 |
| terrain | in_water/in_lava/on_ground/dirs/feet/head/above/below | 不含完整方块面/可达性 |
| limits | radius/vision_range/fov | 有截断 |

**没有**：背包、手持、容器内容、箱子坐标、掉落物精确列表、听觉、记忆来源、`observed_at`、`confidence`、`source` 标记。

这些由 numen MCP / 现场交互补，不是触手。

## 2. 与架构的冲突/拉扯

1. **事实源分裂**：触手负责环境/实体，numen 负责自身/背包/动作/扫描；两边可能不一致，架构未定义优先级。
2. **未知 ≠ 假**：当前 Facts 容易把“没观测到”当 false；planner 会误判“没有水/没有箱子/没有怪”。
3. **触手有穿墙/过期风险**：water 扫描、landmarks 过滤未完成；直接把 `openWater` 当权威会重演“以为有水/没水”的错误。
4. **观察成本**：use-time validation 若每动作都查触手，会打满 HTTP 2.5s 超时/轮询；需要观察预算与 TTL。
5. **信息边界**：触手禁止未访问容器/隔墙实体/矿脉透视；但 planner 可能需要这些信息；不能靠 numen scan 绕过边界。
6. **动作后反馈**：动作 settle 后必须重新观测；否则 Facts 还是动作前状态。
7. **记忆/站点**：触手 v0.3 不提供容器内容记忆；SiteRegistry 必须靠“打开/近距离确认”+ `last_seen`，不能靠触手。
8. **语义层污染**：SemanticResolver 不能把“触手没看到”解释成“世界中不存在”。

## 3. 必须补的接口

### A. Observation（原始观测）

```text
Observation {
  source: body|sight|hearing|memory|numen_scan|interaction,
  kind: self|entity|terrain|water|landmark|container|inventory|site,
  observedAt: gameTick + wallTime,
  radius, fov, partial: bool,
  confidence: 0..1,
  payload
}
```

### B. Fact（三态事实）

```text
Fact {
  key, value,
  status: known|unknown|stale,
  source, observedAt, ttl,
  confidence, evidenceSeq
}
```

规则：

- `unknown` 不能当 `false`；
- 过期 → `stale`，使用前必须重观测/现场校验；
- 每条事实带来源与快照序号。

### C. ObservationPlan（观测子目标）

```text
observe(water nearby) / observe(chest contents) / observe(site valid)
```

- 由 Planner 作为前置子目标；
- 有观察预算/超时；
- 观测失败 → unknown → 探索/求助，不硬执行。

### D. 来源优先级

| 事实 | 权威来源 |
|---|---|
| 自身 HP/饥饿/背包/手持 | numen body |
| 附近实体/地形/光照/时间 | 触手 sight/body |
| 水域/岸边 | 触手候选 + 现场/局部校验 |
| 容器内容 | 打开/交互 + 记忆（非触手远程） |
| 站点有效 | 现场校验 + SiteRegistry |
| 动作结果 | numen 动作结果 + settle 后触手复观测 |

## 4. 需要的修复/增强

### P0（不阻塞 P0-a，但必须定义）

- Facts 三态（known/unknown/stale）；
- Observation 带 `observedAt/source/confidence`；
- `unknown != false` 的显式规则；
- 动作 settle 后重观测；
- 观察预算，避免每 tick 打触手。

### P1

- 触手补 FOV/LOS 过滤（water/landmarks）；
- 输出 `observed_at/confidence/source`；
- 触手/numen 冲突日志与仲裁；
- SiteRegistry `last_seen` + 使用前校验；
- 容器记忆与现场验证。

### 暂不做

- 触手读背包/容器（违反边界）；
- 全图/穿墙扫描；
- 用 numen scan 绕过感知边界。

## 5. 验收指标

- 使用 stale 事实执行动作的次数 = 0；
- 把 unknown 当 false 的误判 = 0；
- 水域/站点事实的现场证伪率可统计；
- 每动作观察调用预算不超；
- 触手/numen 冲突有日志、有仲裁结果；
- 动作 settle 后有复观测证据。

## 6. 一句话

> **触手是感官，不是全知数据库；架构必须把“观测→三态事实→使用前校验”显式化，否则多日任务会在“以为世界是那样”上失败。**
