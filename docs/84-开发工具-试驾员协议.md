# 84. 开发工具：LLM 试驾员协议

> 2026-11-10。修订 docs/80-83。  
> 关键澄清：开发工具不是 DSH 的“外挂大脑（Numen）”预设；它是 LLM 试驾员 + Pilot Harness。  
> MCP 入口只有两个：树工具、开发工具。手动直连模式不属于开发进程。  
> 状态（2026-11-10）：mode/lease/fencing/protect/force/tree-start guard 已实现；GM/8770、触手客户端、`src` 最小 hook 未交付（见 §8）。

## 1. 定位

```text
开发工具 = LLM 试驾员 + Pilot Harness
  - 直连 numen MCP，驾驶具身同伴
  - 留下可读的功能性日志
  - 极限状态下可用 GM 打破无解
  - 与树工具互斥
```

它不是：

- 第二个树工具；
- 常驻顾问；
- 自动验收器；
- DSH 手动直连会话。

## 2. 试驾员职责

- 驾驶具身同伴做测试；
- 记录动作/观察/失败；
- 判断“是否真的无解”，必要时提出 GM 请求；
- 不替树做长期规划；
- 不参与验收；
- 不依赖触手/作弊来完成正常驾驶。

## 3. 互斥协议（带反向保护）

### 状态

```text
OFF
TREE       树工具运行
DEV        开发工具运行
DEV_PROTECTED  开发工具正在测试，拒绝被树启动排斥
TRANSITION 切换中
```

### 规则

- 同一时间只允许一个工具持有 numen MCP；
- 树启动前必须检查 `run/mode.json`：
  - `DEV`/`DEV_PROTECTED` → 树拒绝启动，退出码 `dev_active`；
  - 不允许树“抢锁”把 dev 踢掉；
- 开发工具可以在测试进行中设置 `protect=true`：
  - 带 TTL/heartbeat；
  - 记录 reason/runId；
  - 防止树工具误启动；
- **Lead 有一键强杀权**：
  - `mode force-tree --yes` / `mode force-dev --yes`；必须二次确认；
  - 每次切换绑定 runId（`--run-id` 未给则自动生成）并写审计；
  - 先 graceful stop，再清锁，再切换；
  - 记录审计；dev 不得拒绝 Lead。

### 非对称

- 树不能驱逐 dev；
- dev 可以拒绝树的自动启动；
- Lead 可以强制驱逐任何一方。

## 4. GM 打破无解

### 触发

只有以下情况允许：

- 长期卡在水里/坑里，无解；
- 无路径且探索预算耗尽；
- 测试夹具需要复位；
- 同伴位置/状态导致测试无法继续。

### 使用前自问（必须写入日志）

1. 真的无解吗？有没有非 GM 方案？
2. 最小 GM 操作是什么？
3. 会不会让本次测试失效？如何标记？
4. 操作后如何验证/回滚？
5. 是否只需一次，能否立即停？

### 允许（开发期）

- TP 到安全点/主人附近；
- 给必要测试物品；
- 设置时间/天气；
- 复位夹具。

### 禁止

- 改同伴决策/记忆；
- GM 结果写 Facts/学习/验收；
- 生产世界；
- 连续 GM 依赖；
- 不记录原因的 GM。

### 记录

`gm.jsonl`：

```json
{
  "runId": "...",
  "reason": "stuck_water",
  "selfChallenge": ["...", "..."],
  "command": "tp @s ...",
  "before": {...},
  "after": {...},
  "assisted": true
}
```

GM run 标 `assisted/gm`，不作验收/学习正样本。

## 5. 触手（Tentacle）

开发工具**知道**触手存在，可用只读世界信息做态势判断，但：

- 触手不是动作前置权威；
- 触手 landmarks/water 可能穿墙，不能当全知；
- 驾驶具身同伴时，优先用 numen 现场观测；
- 触手仅作诊断/候选/对照；
- 使用要记录 `tentacle_use`，必要时标 `assisted`；
- 不得靠触手绕过具身边界完成正常任务。

## 6. 日志

```text
runs/<runId>/
  actions.jsonl       动作/结果
  observations.jsonl  观测
  gm.jsonl            GM 使用（含自问/前后态）
  tentacle_use.jsonl  触手诊断使用
  preemption.jsonl    互斥/拒绝/强杀
  manifest.json
```

归档：

```text
archive/<runId>/...
```

## 7. 一键强杀（已实现）

入口：`node tools/mode.mjs ...`（等价 `node tools/pilot/mode.mjs ...`）。Lead 专用；每次切换/拒绝/强杀都写 `logs/preemption.jsonl`。

```bash
# 声明 TREE（不启动树）；真正启动必须走 guard
node tools/mode.mjs tree
node tools/tree-start.mjs
node tools/tree-start.mjs --dry-run

# Lead 强杀：--yes 必须；--run-id 建议显式，未给则自动生成
node tools/mode.mjs force-tree --yes --run-id=switch-a --reason="switch to A"
node tools/mode.mjs force-dev  --yes --run-id=switch-dev --reason="Lead switch"
node tools/mode.mjs force-dev  --yes --once   # 仅脚本；退出即 stale，慎用

# 释放 / 恢复
node tools/mode.mjs off --force
node tools/mode.mjs recover
```

- 缺少 `--yes`：退出码 `2`、`confirmation_required`，并记 `refused` 审计；
- runId 强制绑定：显式 `--run-id` 优先，否则自动生成 `force-tree-<ts>` / `force-dev-<ts>`，写入审计与 `detail.runId`；
- 顺序固定：`reconcile` → transition lock → 推进 fencing → graceful handoff（`control --op exit`，**不 taskkill**）→ 清锁 → 换 lease → 落目标态；
- 失败/超时回 `OFF`；并发冲突退出码 `4`（`transition_busy`）；
- `force-tree` 只声明 TREE，不启动树；随后仍需 `tree-start`。

## 9. Token 效率原则（硬要求）

试驾员必须把 token 当预算，不是免费资源。

### 9.1 分工

- **确定性脚本/探针**：负责探路、状态、计数、扫描摘要；
- **LLM**：只在需要判断/歧义/策略时调用；
- 能用一次脚本拿到的，不拆成多轮 LLM 对话。

### 9.2 观测压缩

- 只读单行摘要，不打印整张 map/help/长列表；
- 优先 diff：只报告变化字段；
- 一次 Lua 批量取多个字段，减少往返；
- 未变化/刚查过的状态不重复问。

### 9.3 预算

- 每次 run 设 `maxTokens` / `maxSteps` / `maxMinutes`；
- 目标达成/无新信息/卡死倾向 → 立即停；
- 不写长 summary，不把 trace 回灌上下文；
- manifest 记录 token/调用数，供后续优化。

### 9.4 效率指标

- tokens / 有效观测；
- LLM 调用数 / 有效决策；
- 重复观测率；
- 每步信息增益；
- 目标达成所需 token。

### 9.5 禁止

- 全量 API 探索；
- 反复读同一状态；
- 为“更完整”打印大对象；
- 用 LLM 做脚本能做的事；
- 无预算长跑。

## 10. 一句话

> **试驾员负责开、负责记录、负责在无解时申请 GM；树不能踢它，它不能拒绝 Lead；GM 必须有自问、有记录、有标记。**
>
> **Token 也一样：能脚本就不 LLM，能一行就不整页，能停就别续。**
