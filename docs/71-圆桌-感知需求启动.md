# 71. 圆桌会议：感知 → 需求建立 → 任务启动

> 2026-11-10 开发前会议。全体顾问参加；达成共识后才开工。  
> 主持/收敛：Lead。

## 1. 玩家的判断（待质询）

当前一日测试不通过，问题可能不在工具/战术包，而在：

```
感知（世界状态）
  → 需求建立（今天该干什么）
  → 启动任务（第一件事做什么）
```

这条链没有可靠的判断与入口。

玩家视角：

- 进入新游戏、0 资源，第一件事就是“无脑撸树”；
- 这是所有需求的起点；
- 现在的行为失败，可能都因为“状态→需求→起点”没建立。

## 2. 提议（待质询）

1. 每天黎明做一次**作弊级世界状态扫描**；
2. 用这次扫描建立当天的**北极星级任务**；
3. 这可能也是未来多同伴协作的基础（共享世界状态/任务）。
4. 需要讨论：作弊扫描是否允许、在什么范围、运行时还是仅测试、如何不破坏具身边界。

## 3. Day1 通过基准（待定义）

新世界、0 资源、无 LLM、玩家零干预，到 day1 结束：

- 能自己发现树/资源并启动采集；
- 获得木头，做出工作台/木工具；
- 进入“求生状态”（食物/火把/夜间安全至少一项稳定）；
- 无死亡、无无限循环、无假成功；
- 全程可解释、可判负。

## 4. 会议问题

1. 你同意“问题在感知→需求→启动链”吗？如果不同意，真正断点在哪？
2. 黎明作弊扫描：允许/禁止/仅测试/仅战略层？理由与边界。
3. Day1 的“真正起点”是什么？如何编码：硬编码 bootstrap、需求生成、状态扫描、还是别的方式？
4. Day1 通过基准应该怎么定义？证据是什么？
5. 每日北极星任务是否合理？对多同伴协作是基础还是过早？
6. 开发前最小必须改什么？明确不做什么。
7. 最终：同意开工 / 有条件同意 / 反对。条件是什么？

## 5. 规则

- 每人一页，先结论后理由；
- 必须明确同意/反对/条件；
- 不写实现/排期；
- 不追当前 bug；
- 引用 `NORTH-STAR.md`、`WORLD-CONSTRAINTS.md`、`PROJECT-STATUS.md`。
