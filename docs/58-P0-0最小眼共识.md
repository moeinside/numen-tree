# 58. P0-0 最小眼共识（产品/验收裁决）

> 2026-11-10。产品经理裁决：A 不可选，B 过大，选 **C 收紧版 + P0-0 最小眼**。  
> 结论：先做最小眼，再跑 P0 真实两夜；不是先继续旧验收。

## 1. 为什么

- A（继续旧 P0）：审计只覆盖合成假通过，真实水失败未被判负；继续等于用已知会漏判的门验收。
- B（完整感知层）：会在 P0 前再造一个 P1，范围过大。
- C（收紧）：只补 P0 关键感知门，立即重跑真实验收。

## 2. 顺序

```
P0-0 最小眼
  → P0-a 真实两夜
  → P0-b 真实 kill/重启/续跑
  → P0 出线
```

不改 P0-a/P0-b 大顺序；只插入 P0-0。

## 3. P0-0 范围

只接四类动作：

1. 移动/脱困；
2. 采集；
3. 开容器；
4. 放置。

白名单事实：

- `in_water`
- `on_ground`
- 目标方块变化
- 掉落/背包增量
- 容器可交互
- 动作位移

能力：

- PerceptionService 唯一 `Observation → Fact` 写入；
- 白名单三态 Facts；
- 动作前 critical facts ensure；
- settle 后 expected predicate 校验；
- 单 inflight、每动作 ≤2 观察、超时退避 30~60s；
- 惊讶（位置未变/仍在水中/动作成功但谓词假）→ 打断当前 SOP；
- 真实失败 trace fixture + 三负样本。

不做：

- FOV/LOS/partial/confidence；
- ObservationPlan 作为 Planner 子目标；
- 双源冲突完整仲裁；
- SiteRegistry last_seen；
- 观察进 Arbiter；
- 任何“先全量观察再行动”的串行阶段。

## 4. 权威源（最终修正）

**不能用 numen body 自报状态当权威。**

- `in_water/on_ground` 权威 = **新鲜触手观测**；
- numen body 只是带 `observedAt/TTL` 的 Observation，过期即 `unknown`，不是 Fact 权威；
- 冲突或触手也超时 → `unknown` + 一次现场复核；
- 禁止用旧自报补位；
- 该键 TTL 随夹具冻结。

其他：

- 目标方块/掉落/背包增量 → numen 动作结果 + postcheck 世界观测；
- 容器可交互 → 交互结果 + postcheck；
- 动作位移 → numen 动作结果 + postcheck；
- 结果不一致 → 以 postcheck 判负。

## 5. move_segment 契约

- atom 语义不变：`ok` = 动作已执行，不等于世界达成；
- action/strategy 边界加 `expectedPredicate`；
- plan/strategy 成功 = 动作 ok 且 predicate 真；
- postcheck 假 → 失败三分，不是补丁。

## 6. 验收门

新增硬门：

1. **历史真实失败 trace 回归必须判负**（水里 move ok 但仍在水中）；
2. 动作 success 但 expected predicate 假 → 必须进失败三分，“假 ok”计数 = 0；
3. 白名单状态改变动作 postcheck 覆盖率 = 100%；
4. 带 stale/unknown critical fact 执行动作 = 0；
5. 观察/动作 ≤2、单 inflight、超时退避生效；
6. `in_water` 误报 = 0；
7. 决策延迟与 suspension 不劣化。

冻结项：

- 白名单事实键；
- 权威源表；
- expected predicate 定义；
- 观察预算数值；
- 历史失败 trace；
- 审计版本；
- TTL。
