# 116. 时间压力与过夜准备共识

> 2026-11-11。行为学家 + MC 专家 + 点子王圆桌。  
> 问题：是否按时间段动态调整优先度；黄昏是否应由“安全过夜准备是否充足”驱动；会不会推翻 P0。

## 1. 结论

```text
是，需要动态时间压力。
但不是新增独立 need，也不是让 strategy 看钟表摆动。
```

正确位置：

```text
needs 提供原始驱动
attention 提供 deadline / 剩余日照信号
preflight 把“时间窗 + 暴露 + 准备度”作为候选生成输入
strategy 保持与时间解耦
```

行为学家：时间压力是**评估层的剩余时间预算**，以乘子/门控作用于现有 need，不参与候选分。  
点子王：放 preflight/调度层，不新增 needs 项；否则与 night_safety/safety_hold 叠加，造成安全权重过高。  
MC：复用现有 `prepare_for_night`/`night_hold`，把“动作清单驱动”改成“readiness 谓词驱动”。

## 2. 过夜准备度（一个谓词，不是动作清单）

### 必须（日落前全部满足）

| 项 | 判定 | 动作 |
|---|---|---|
| 遮蔽/就位 | `terrain.above` solid 且四周不 standable，或距 home ≤8 | 侧向 1×2 洞封口 / 回 home |
| 食物 | 可吃 ≥2 份，或 hunger ≥14 | 吃/就近取食 |
| 距离 | 距锚点 ≤16 | 回家/回锚点 |

### 加分（做不到不算失败）

```text
火把 / light ≥8
木剑或可用武器
床（Day1 不做）
```

五条合成一个 readiness 总分，不各自触发独立 goal；避免“有食物但离家 200 格”被判充足。

## 3. 时间窗

MC 机制事实：黄昏只有约 50 秒（12000–13000 tick），所以不能等黄昏才开始。

```text
准备启动：game_time ≥ 9000（约 15:00）
强制收工：≥ 11500
必须完成：< 12000
入夜：≥ 13000
```

双源：

```text
numen is_dark_outside / is_bright_outside
触手 day_time / day
```

冲突以 `game_time` 区间为准；雨天/雷暴可作提前量，但不改区间。

## 4. 黄昏 → 夜间

```text
黄昏 = 准备窗口，准备度单调上升，查缺补缺
入夜 = 门关闭，段级承诺
夜间 = 只做低暴露/基线行为，不再“重新准备一次”
```

单向转换 + 滞回：

- 进入和退出条件不同；
- 退出等天亮或硬信号；
- 准备完成后不反复重启准备；
- 夜间未达标项转受限模式（守夜/就地容纳/低暴露修正）。

## 5. 与 P0 的边界

**不推翻 P0。**

```text
P0 不变：DispatchGate / actionLock / latch / 状态机
P1 新增：时间窗 preflight + readiness 谓词
```

失败走现有“不生成/挂起”通道，不重写 gate。  
**红线：时间压力不能改 hard gate 阈值；不能为了过夜调 dusk 窗口或安全阈值。**

## 6. 验收

### 夹具

```text
game_time=9000
距 home 40 格
背包 0 食物
无遮蔽
hostile=0，白天光照正常
```

### 通过

```text
12000 前同时满足：
遮蔽或距 home≤8
食物≥2 或 hunger≥14
距离≤16
且 trace 有 prepare_for_night 意图（由 readiness 触发）
```

### 判负

```text
到 13000 三项任一不满足且无 abandon+reason
或 9000→13000 无任何夜间准备意图
或 readiness 未达标却继续派发白天长任务 atom
黄昏前后 5 分钟内 goal 切换 >3 次
```

## 7. 实施顺序

1. 加 `readiness.night` 谓词（遮蔽/食物/距离/武器）；
2. preflight 读取 game_time 窗口 + readiness；
3. `prepare_for_night` 改为按缺失项生成子目标；
4. 入夜门 + 段级承诺 + 基线行为；
5. 最后才调 attention/priority 权重。

## 8. 一句话

```text
不是“夜间不能做什么”，
而是“为了安全过夜，我们还缺什么，现在补不补得完”。
```
