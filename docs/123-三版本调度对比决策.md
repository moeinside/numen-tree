# 123. 三版本调度对比与升阶决策

> 2026-11-11。玩家代表 + 项目总控 + 点子王 + 行为学家 + MC 专家。  
> 对比：V0 当前扁平调度 / V1 A1–A5 滑动栈 / V2 日骨架 + 小滚动排班。

## 1. 决策

```text
V2 值得升阶，但只做薄骨架。
P0 不插队。
P1：日骨架 + 少量班次数据 + 失败换兄弟。
P2：滚动重排、跳必须班次、直觉快速选择。
不采用 V1 完整滑动栈。
```

## 2. 三版对比

| 版本 | 成本 | 收益 | 结论 |
|---|---|---|---|
| V0 当前 | 最低 | 能活，但不会安排一天 | P0 先用能力证据出线 |
| V1 分层栈 | 最高 | 最晚，风险最高 | 不采用 |
| V2 排班 | 居中 | 最直接指向昼夜多任务 | 值得，但薄做 |

## 3. 预测表现

```text
体感排序：V2 > V1 > V0
```

V2 强在：

```text
段内稳定，少抖
玩家能说出“今天的大盘”
失败有退路、有次序
边界修表，不每拍改主意
```

V2 差在：

```text
容易变成课表/任务表
段边界跳班突兀
必须班次太硬会僵硬
软班次可能被无限挤掉
```

## 4. 成立条件

### 班次必须是结果谓词

```text
shift { id, 结果谓词, must|soft, deadline(gameTime), 方法引用 }
```

禁止：

```text
“黄昏必须回家”写成动作
```

必须是：

```text
入夜前 HP 无下降 + 无暴露 + 到锚点
```

### 时间窗

```text
必须班次只能在窗口内启动
窗口外执行 → 判负
```

MC 现实容量：

```text
morning 200s：1 主班次
noon 100s：缓冲/短任务
afternoon 200s：1 主班次或过夜准备
dusk 100s：必须班次（即时类）
night/midnight：守夜
```

### 失败

```text
先换兄弟方法
再跳必须班次（窗口已开）
记录 missed / partial
A1 只在段边界/硬信号修表
```

### A1 修表

```text
保留记忆
最小修补
每段重排次数上限
空白班次合法（idle/观察/恢复）
```

### 玩家可见

```text
时间线（今天干什么）
+ 深度线（现在解决什么）
两者合成一条可读叙事
```

## 5. 最小安全切片

```text
日骨架 3–4 段
每段 1 个必须班次 + 至多 1 个软班次
失败只允许换兄弟一次
不做滚动重排
不做跳必须班次
不做直觉预批准
```

## 6. 判负

```text
must 班次是动作而非结果谓词
班次在时间窗外执行
missed 无 reason
班次条目随场景线性膨胀
段边界/硬信号之外发生重排
同一窗口班次切换 >2 或跳班→返班循环
用新增调度层换 Day1 通过
```

## 7. 一句话

```text
V2 是三版里唯一值得留的；
正确形态是“薄骨架 + 数据化班次”，
不是“会排课的引擎”。
先让 V0 用能力证据出线，再让 V2 在 P1 长成 H2 的形状。
```
