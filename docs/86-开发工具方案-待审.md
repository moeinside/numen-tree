# 86. 开发工具方案（待审）

> 2026-11-10。汇总 docs/80-85。  
> 评审顺序：点子王（工程/架构风险）→ 项目经理（范围/验收/维护）。  
> 两边同意后，交给独立工具维护子体实现与维护。

## 1. 定位

```text
开发工具 = LLM 试驾员 + Pilot Harness + Dev GM 通道
```

- 只服务树工具开发，不属于树；
- 可直连 numen MCP 驾驶具身同伴；
- 留下可读的功能性日志；
- 极限状态下可执行 GM 打破无解；
- 与树工具互斥；
- 不是 DSH 手动直连模式，不是顾问，不是验收器。

## 2. 端口/信任域

| 端口 | 服务 | 用途 |
|---|---|---|
| 8765 | numen MCP | 树或 dev，二选一 |
| 8767 | 树 MCP | 树模式 |
| 8768 | numenlockfix | 清锁 |
| 8769 | 触手 | 只读诊断 |
| 8770 | numen-devtools | dev GM 命令 portal |

信任域：

- 树域：8767 + numen 8765；
- dev 域：Pilot Harness + 8765 + 8770；
- GM 域：8770 独立 mod，token + 白名单 + 审计。

## 3. 互斥协议（非对称）

```text
OFF / TREE / DEV / DEV_PROTECTED / TRANSITION
```

规则：

- 同一时间只有一个工具持有 numen MCP；
- 树启动前检查 `run/mode.json`；
- `DEV/DEV_PROTECTED` 时树**拒绝启动**（不能驱逐 dev）；
- dev 测试中可设 `protect=true`，带 TTL/heartbeat；
- **Lead 一键强杀**：
  - `mode force-tree` / `mode force-dev`；
  - 先 graceful stop，再清锁，再切换；
  - dev 不得拒绝 Lead；
- 所有切换/拒绝/强杀写 `preemption.jsonl`。

## 4. GM 通道（薄 portal）

不做类型化 op，不重写作弊功能。

```http
POST /dev/v1/command
Authorization: Bearer <token>

{
  "runId": "...",
  "command": "execute as @e[name=bigwhale,limit=1] at @s run tp @s 128.66 67 183.3",
  "reason": "stuck_water",
  "selfChallenge": ["真的无解吗", "最小操作是tp", "会标记assisted"]
}
```

mod 只做：

- loopback 127.0.0.1:8770；
- token；
- 命令 root 白名单；
- `execute` 子命令递归检查；
- 测试世界限制；
- 频率限制；
- 审计；
- 服务器线程执行。

允许 root：

```text
tp give time weather setblock fill summon effect gamemode xp execute
```

禁止：

```text
stop reload op deop ban whitelist
gamerule difficulty peaceful
kill clear data
```

## 5. 试驾员规则

- 只驾驶、记录；
- 不写总结；
- GM 前必须自问并写 `gm.jsonl`；
- GM run 标 `assisted`，不作验收/学习；
- 不依赖触手完成正常驾驶；
- 触手只读诊断，`tentacle_use.jsonl`；
- 任务完成/危险/预算到即停。

## 6. 日志与归档

```text
runs/<runId>/
  actions.jsonl
  observations.jsonl
  gm.jsonl
  tentacle_use.jsonl
  preemption.jsonl
  manifest.json
  report.md
```

- trace 原样归档 `archive/<runId>/`；
- summary 由一次性分析子体读取并归档，Lead 不读全文；
- 开发日志不进验收/学习。

## 7. 维护与交付

工具维护由**独立子体**负责：

- 只维护工具，不参与树验收；
- 写代码、测试、文档；
- 不擅自改树/验收口径；
- 版本化。

必须交付维护文档：

- `tools/pilot/README.md`：用法/命令；
- `tools/pilot/MAINTENANCE.md`：架构、端口、状态机、模式切换、GM 安全、日志、故障处理、升级/回滚、验收清单；
- `docs/86` 更新；
- 变更日志。

## 8. MVP 范围（以 §11.3 为准）

1. `mode.mjs` + `run/mode.json` + lease/fencing + protect + force；
2. 树启动 lease guard（带 fail-safe 开关，干净状态必须 100% 可启动）；
3. Pilot Harness 与 mode 集成；
4. trace 归档；
5. 维护文档（README + MAINTENANCE）；
6. 端口/lease/force/stale 恢复测试。

**MVP 不含 GM mod / GMProvider / 8770 / 触手客户端 / 一次性分析子体；全部后置第二阶段。**

## 9. 非目标

- 不重写树；
- 不改验收标准；
- 不实现运行时 WorldHints；
- 不多同伴；
- 不做类型化 GM op；
- 不做通用命令控制台；
- 不把 GM run 当验收/学习。

## 10. 主要风险

1. LLM 拿到 GM 后滥用/依赖；
2. mode 死锁/误驱逐；
3. GM portal 命令注入/白名单绕过；
4. 树误启动抢 8765；
5. 日志爆炸/上下文爆炸；
6. 维护子体越权改树。

## 11. 点子王质询后修订（Lead 采纳，待 PM 确认）

结论：有条件同意，建议 GM 拆到第二阶段。

### 11.1 互斥必须落到事实

- `mode.json` 只是人类可读状态，不是锁；
- 真正互斥锚定在 **8765 端口占用 + lease fencing token**；
- 树启动必须校验 lease，不只是读 mode；
- `TRANSITION` 必须有超时兜底到 `OFF`；
- `force-*` 必须二次确认 + 绑定 runId；
- 验收要证明：
  1. dev 运行时手动启动树会失败；
  2. force 中途杀掉控制进程，系统能回 `OFF`；
  3. 任何一方关键动作前校验 fencing token。

### 11.2 GM 后置到第二阶段

MVP **不含 GM mod / GMProvider**：

- 先无 GM 跑通一天；
- 避免试驾员退化成“卡住就 tp”；
- GM 进第二阶段，单独验收。

GM 白名单再收紧：

- **删除 `effect`**（可伪造回血/夜视，污染生存验收）；
- **删除 `gamemode`**（无限资源）；
- 参数级限制：
  - 坐标在世界边界内；
  - 禁止 tp 入岩浆/虚空；
  - give 数量上限；
  - 频率上限；
  - runId/reason/selfChallenge 缺一即拒；
  - 真实 worldId 校验，不是字符串；
  - token 只从受限文件读；
  - 生产构建不含监听。

### 11.3 MVP 缩减

保留：

1. `mode.mjs` + mode.json + protect + force；
2. 树启动 lease guard；
3. Pilot Harness 与 mode 集成；
4. trace 归档；
5. 维护文档；
6. 端口/lease/force 恢复测试。

后置：

- GM mod（8770）；
- GMProvider；
- 触手只读客户端（可先不做）；
- 一次性分析子体（先人看 report）。

### 11.4 Token 效率（新增硬要求）

试驾员必须低 token 高效试驾：

- 确定性脚本优先，LLM 只做判断/歧义；
- 观测单行/差分，禁止整页 map/help；
- 一次 Lua 批量取多个字段；
- 不重复读未变化状态；
- 每 run 有 `maxTokens/maxSteps/maxMinutes`；
- 目标达成/无新信息/卡死倾向立即停；
- pilot 不写 summary，不回灌 trace；
- manifest 记录 token/调用数/重复观测率；
- 维护文档必须包含 token 预算与效率指标。
