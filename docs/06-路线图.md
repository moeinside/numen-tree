## 阶段 0：探针 ✅

产出：`docs/02-探针记录.md`、`probe/`。

关键结论：

- 只有 `lua` 占槽；`get_events` / `say` 不占槽。
- 程序被打断后任务继续跑，并以 `task_finished` 事件收尾。
- 派新任务会取代旧任务（`status=stopped`）。
- 任务自带边界与恢复阶梯，不需要树自己写切片器。

---

## 阶段 1：树进程 MVP ✅

产出：`src/`。

- 目标栈（命令盒）+ 每同伴串行执行通道
- 6 个技能卡，自动发现
- 事件通道（独立 MCP 会话）→ 收件箱（★ 标记需大脑决策）
- trace（jsonl）+ 控制 API（status / goal / control / inbox / skills）
- 已实测：`go_to` 真实位移、`dig_nearby` 真实挖掘、`eat` 短路

**MVP 验收**：能通过 CLI 让同伴自主完成"走过去 / 挖点东西 / 跟一会儿"，全过程有 trace，失败有结构化上报。

---

## 阶段 2：MCP 工具面 + 新预设 ✅

产出：

- `src/mcpserver.mjs`：8 个工具（tree_status / tree_skills / tree_goal / tree_control / tree_inbox / tree_wait / say / memory）
- 新预设「外接大脑（Numen 树）」写在 `~/.dsh/profiles/desktop/cordis.patch.yml`，与旧预设并存
- 验收实测：`tree_goal(go_to owner)` → 同伴走 20 步 → `tree_wait` 立刻带回 `goal_done` + 状态摘要

**关键约定**：树对 LLM **不暴露 `lua`**。LLM 只能下目标。

---

## 阶段 3：唤醒器 ⬜

- DSH 侧薄插件：定时问树"有事吗"，有事才注入消息开一轮
- 空闲成本 → 0
- 替代 `tree_wait` 长轮询

---

## 阶段 4：宏计划 + 右脑 ⬜

- 宏计划库（`macros/`）：技能序列 + 前置/后果 + 版本 + 来源
- 右脑：一次性子 agent，输入目标 → 输出计划数据（纯函数）
- 两道校验：静态（拼装时）+ 运行时（每步前）
- 固化：成功的组合存成命名宏，以后零成本复用

---

## 阶段 5：多同伴 ⬜

- 共享黑板（谁在哪、谁占了什么）
- 协同规则：让路、轮流用工作台、不抢同一只怪
- 低级社交：模板台词
- 高级社交：事后叙述（流水 → LLM 变对话）
