# 91. 开发工具工作流：目标 → 操作员 → 日志 → 分析员

> 2026-11-10。对齐用户期望：  
> 用户给测试目标 / Lead 定目标 → 子体运行开发工具 → 透传控制 numen MCP → 留日志 → 独立子体整理给顾问团。

## 1. 期望流程

```text
用户 / Lead
  ↓ 写 GOAL
devtool prepare
  ↓ 建 run、拿 lease、写操作员简报
Operator 子体
  ↓ 只通过开发工具操作 numen MCP
  ↓ actions.jsonl / observations.jsonl / gm.jsonl / tentacle_use.jsonl
devtool close
  ↓ settle、archive、mode OFF
Analyst 子体
  ↓ 读 run，不读游戏
  ↓ 写 roundtable-pack.md
顾问团
```

## 2. 当前实现对上多少

### 已有

- mode/lease/fencing/protect/force；
- `dsh-bridge.mjs`：DSH 子体 → numen MCP；
- `OPERATOR.md`：操作员边界；
- `actions.jsonl` / observations / archive；
- `analyze-run.mjs`：机械分析；
- GMProvider、触手客户端。

### 缺口

1. **没有 GOAL 合同**  
   目标、预算、约束、成功/停止、允许动作、日志路径没有统一文件。

2. **没有一条命令把流程串起来**  
   目前是手工：开 mode → 给子体 prompt → 收日志 → 跑分析。

3. **Operator 与 Analyst 没有正式交接**  
   Analyst 还是脚本/人工；不是“独立子体读日志写圆桌文件”。

4. **Operator 容易越界**  
   没有 GOAL 时它会探索 API/写总结；必须由合同限制。

5. **没有统一“给顾问团看的包”**  
   需要固定 `roundtable-pack.md` 结构。

## 3. GOAL 合同（建议）

`runs/<runId>/GOAL.md`：

```text
目标：Day1 木链/食物/夜间安全
预算：20 分钟 / 40 次 bridge / N tokens
环境：新世界、玩家≥64格或离线、快照起点
允许：observe / lua / move / ...
禁止：GM（除非明确允许）、全图扫描、战斗、下水
成功：M1-M4 谓词
停止：目标达成 / 预算 / 危险 / 无法继续
日志：actions.jsonl + observations.jsonl
给顾问团的包：roundtable-pack.md
```

## 4. 角色

### Operator 子体

- 只执行，不分析；
- 每次一个 bridge 调用；
- 只留日志；
- 不写 summary；
- 卡住/不确定 → 停，交回 Lead。

### Analyst 子体

- 和 Operator 不同子体；
- 只读 run；
- 写 `roundtable-pack.md`；
- 不改游戏、不操作 MCP；
- 不回灌 Lead 全文，只报路径 + 一句话。

## 5. roundtable-pack.md 结构

```text
# Run <id>
- goal / budget / mode
- 结论：目标达成/未达成/阻塞
- 分段行为
- 失败分类（capability/material/unknown）
- 关键证据
- GM/触手使用
- 给各顾问的问题（最多 3 条）
```

## 6. 与现有工具的关系

- `mode.mjs`：prepare/close 的互斥层；
- `dsh-bridge.mjs`：Operator 的手；
- `run.mjs`：可选自动循环（OpenAI-compatible）；
- `analyze-run.mjs`：Analyst 的机械初稿；
- `gm-provider.mjs`：仅 GOAL 允许时；
- `tentacle-client.mjs`：仅诊断，不作前置。
