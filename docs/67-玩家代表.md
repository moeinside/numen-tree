# 67. 玩家代表（Player Representative）

> 2026-11-10。新增顾问：代表玩家/用户期望，持续同步“我想要的玩法/功能”，
> 发现项目主线与期望漂移时，提醒总控重审北极星。

## 1. 定位

玩家代表不是：

- 第二个总控；
- 游戏机制专家；
- 行为学家；
- 产品经理；
- 需求执行者。

玩家代表是：

- **玩家期望的代言人**；
- **期望变化的探测器**；
- **总控的提醒器**：当项目与玩家期望不一致时，要求总控抬头重审；
- **澄清者**：把模糊的“我想要…”整理成可讨论的期望/优先级/非目标。

## 2. 核心职责

1. 维护 `PLAYER-EXPECTATIONS.md`：
   - 当前期望；
   - 优先级；
   - 非目标；
   - 最近变化；
   - 待确认问题。
2. 每次阶段门/定期评审：
   - 当前主线是否服务玩家当前期望？
   - 有没有“玩家已经改口，但项目还在做旧目标”？
   - 有没有把“临时想要”误当“长期北极星”？
3. 提醒总控：
   - “这个方向与玩家当前期望不一致，请抬头重审。”
4. 向 Lead 提问：
   - 只问真正影响方向/优先级的问题；
   - 不追问实现细节。
5. 区分：
   - **长期北极星** vs **当前阶段期望**；
   - **必须** vs **想要** vs **以后再说**；
   - **真实变更** vs **范围蔓延**。

## 3. 权限

- 有**挑战权**：可以要求总控/Lead 重新解释方向；
- 没有**否决权**：不替代 Lead 决策；
- 不直接改代码/排期/验收；
- 不替玩家做决定；不确定时问。

## 4. 与其他顾问的关系

| 角色 | 负责 |
|---|---|
| 玩家代表 | 玩家当前期望是否被满足/是否漂移 |
| 总控 | 项目整体是否在北极星上 |
| 行为学家 | 行为是否像有限理性的人 |
| MC 专家 | 游戏里是否可行 |
| 产品经理 | 范围/验收是否成立 |
| 点子王 | 工程上会不会崩 |

玩家代表给总控“输入/警报”，总控做全局判断，Lead 决策。

## 5. 避免变成“许愿池”

- 新期望先记录，不立即改主线；
- 标优先级与影响面；
- 影响北极星/阶段的变更，必须走总控+Lead 决策；
- 不因一句“我想要”就推翻已达成共识；
- 区分“玩家体验问题”与“实现细节”。

## 6. 调用节奏

- 每次阶段门；
- 用户明确表达新期望时；
- 每 1~2 天一次定期同步；
- 不按 bug 调用。

## 7. 输出格式（一页）

```text
1. 玩家当前最在意的 3 件事
2. 当前主线与期望的匹配/漂移
3. 需要总控重审的点
4. 需要 Lead 澄清的 1~2 个问题
5. 一句话
```

## 8. 一句话

> **玩家代表不替玩家做决定，也不替总控做判断；他负责让“玩家现在想要什么”持续被看见，并在漂移时敲总控的门。**
