# 43. 战略：装备与后勤就绪（Readiness / Logistics）

> 2026-11-09 用户提出。目标：任务链不要因为缺工具/缺武器/没备份而反复失败。  
> 结论：不要写一条巨型战略；做**就绪层 + 三个钩子 + 库存策略**。

## 1. 核心思路

```
Readiness（就绪层）
  ├ 检查：武器/镐/斧/钓竿/食物/火把/备份
  ├ 触发：天亮审计、任务前预检、失败后复检、守夜前确认
  ├ 输出：缺失项 → gear_recovery / stock_replenish / safety_hold
  └ 库存策略：基地至少留 1 份备用工具
```

就绪层不直接执行；它产生候选/拦截条件，由优先度系统调度。

## 2. 四个触发点

### T1 天亮审计

每天第一次进入 `dawn`：

- 查装备/工具/食物/火把/备用；
- 缺什么 → `gear_recovery` 候选；
- 记录 `lastEquipmentCheckDay`，每天只自动审计一次；
- 玩家/LLM 可随时手动触发。

### T2 任务前预检（preflight）

任何采集/生产/钓鱼/战斗前，先查该任务需要的工具：

| 任务 | 预检 |
|---|---|
| 挖矿 | 镐 |
| 砍树/采集 | 斧（没有也可手挖，降级） |
| 钓鱼 | 钓竿 |
| 战斗/守夜 | 武器 |
| 合成 | 工作台/材料 |

缺失 → 任务不启动，转 `gear_recovery`，而不是进去失败。

### T3 失败后复检（postflight）

失败 kind 属于工具/装备类：

- `need_tools`、`need_pickaxe`、`no_rod`、`no_weapon`、`chest_blocked`；
- 立刻触发一次就绪检查；
- 不立刻重试原任务，先补工具。

### T4 守夜前确认

进入 `dusk/night`：

- 必须有武器；
- 没有 → 不进入 guard/fight，转 `safety_hold` 回安全屋；
- 有武器才允许 patrol/guard。

## 3. 库存策略：至少一份备份

基地箱子目标：

```
武器 ≥ 1 备用
镐   ≥ 1 备用
斧   ≥ 1 备用
食物 ≥ 8
火把 ≥ 8
```

规则：

- 生产工具时，若“背包 + 基地”总数 < 2，不把最后一件存掉；
- 有多余时，存 1 份备用；
- 没有箱子/没材料 → 记录缺口，不阻塞主任务；
- 备份不是每次都查全箱，用容器记忆 + 现场确认。

## 4. 与现有系统

- `secure_gear` 是执行器，不是就绪层；
- `get_weapon/get_tools` 是需求信号；
- `Readiness` 负责“什么时候该检查、缺什么、是否拦截任务”；
- 输出仍是 `Candidate`，交给优先度系统；
- 不绕过硬安全/反射。

## 5. 分层

```
profile: equipment_readiness
  milestones:
    M1 检查背包/箱子
    M2 计算缺失
    M3 补工具/武器
    M4 补备份
    M5 任务预检通过
```

任务侧只调用 `preflight(task)` 和 `postflight(result)`，不复制检查逻辑。

## 6. 验收

- 挖矿前发现没镐 → 不启动挖矿，先补镐；
- 钓鱼前没钓竿 → 先去箱子取/求助，不直接 fish；
- 失败一次后立刻复检，不盲目重试；
- 夜里没武器 → 回安全屋，不巡逻/硬打；
- 基地有备用工具，死亡后恢复更快；
- 检查/补缺不会无限循环（冷却、缺口记录）。

## 7. 实施顺序

1. `readiness.mjs`：纯检查 + 缺失项；
2. 天亮审计 + 失败后复检接入；
3. 任务前预检；
4. 守夜前武器门；
5. 备份/库存策略（需要容器记忆）。
