## 2. 核心思想拆解

不是“给 LLM 看截图”，而是：

```
世界状态（方块/实体/危险）
  → 语义化（只保留有意义的类别）
  → 自我中心俯视占用栅格（BEV）
  → costmap 危险膨胀（怪/岩浆/悬崖/水/黑暗的代价）
  → 预计算空间关系（距离/方向/可达/遮挡）
  → 压缩成文本/符号喂 LLM
```

关键点：**空间关系在感知层先算好**，LLM 只做“选目标/选方向”，不自己做几何推理。

## 3. 和 numen-tree 现状的对比

| 能力 | 现有树 | 该方案 |
|---|---|---|
| 局部移动 | numen 自带寻路（Driver） | 同样需要，栅格不替代寻路 |
| 世界认知 | `scan_block`/`scan_entities`/`locate_station` + `places.json` | 结构化语义快照 + 局部栅格 |
| LLM 空间输入 | 坐标/距离/扫描结果，零散 | 预计算方向/距离/可达/危险 |
| 危险避让 | 执行策略门 + 本能逃跑 | costmap 危险膨胀，提前规划 |
| 资源/基地认知 | 单次扫描，无持久地图 | 语义池 + 增量更新 |
| 上下文成本 | 随扫描量增长 | 只喂“语义摘要”，可控 |

**契合度：高，但属于“感知层/规划层”，不是替代战术/战略层。**

## 4. 对树可能的帮助

1. **有限扫描 → 语义快照**：和“我想”欲望板天然配合；扫描预算用来增量填格，不是每 tick 全量查。
2. **危险感知前移**：costmap 可让战略在“去不去”阶段就避开岩浆/悬崖/怪群，而不是走到一半靠本能逃。
3. **基地/建造规划**：照明布局、墙/门位置、安全角落、箱子位置，都可以在栅格上先算。
4. **LLM 输入更省**：只给“北 6 格有怪、东 3 格箱子、回家路危险度 0.7”这类摘要，而不是原始方块列表。
5. **资源记忆**：语义池可持久化树/矿/水/动物分布，减少重复扫描。

## 5. 风险与成本

| 风险 | 说明 |
|---|---|
| 扫描成本 | 建栅格需要区域扫描；numen 扫描接口是否支持低成本区域采样要验证 |
| 时效性 | 实体/方块会变；必须 TTL + 增量更新，不能一次扫描吃很久 |
| 坐标系 | “自我中心”随移动/转向变化；需要世界锚定缓存 + 局部 BEV 变换 |
| 尺度 | 世界很大；只能做局部栅格（如 32×32）+ 地标图 + 分层记忆 |
| 文本膨胀 | 32×32 ASCII 也会吃 token；要用符号/RLE/对象列表，按需给 |
| costmap 调参 | 危险膨胀太保守会“不敢走路”，太激进会送死；要按游戏校准 |
| 过度设计 | 当前生存闭环还没稳定，完整 BEV 工程量大，容易本末倒置 |

## 6. 建议的最小落地路径（以后）

**Phase 0：语义快照（最便宜）**
- 一次有限扫描产出：自身、附近敌对、基地关键方块、地标、危险源；
- 不建栅格，只做结构化对象列表 + 方向/距离/可达性；
- 供 needs/desire 板和 LLM 摘要使用。

**Phase 1：地标图 + 世界记忆**
- 持久化：家、箱子、床、熔炉、矿点、水源、危险区；
- 扫描增量更新，带 TTL/置信度。

**Phase 2：局部 BEV 栅格**
- 16×16 或 32×32，符号：空地/墙/水/岩浆/悬崖/箱子/光源/敌对；
- 危险 costmap 膨胀；
- 只在“选点/选路/建基地”时生成文本摘要，不每 tick 喂 LLM。

**Phase 3：战略使用**
- `light_base` 用栅格选火把点；
- 建墙/避难所选址；
- 逃跑/回家路线危险评估。

## 7. 评估结论

- **方向合理**：对 Minecraft 这种“方块语义明确”的世界，纯文本语义栅格通常比视觉更稳、更省、更可解释；
- **但不能替代 numen 寻路和现有战术**：它是“感知/规划表示”，不是执行器；
- **最大价值**在“有限扫描 → 语义快照 → 欲望/战略决策”，正好接上前面讨论的“我想”驱动；
- **现在不做**：先稳定生存闭环和战术/战略；等需要“选址/建基地/探索/危险路线”时再启动 Phase 0。
