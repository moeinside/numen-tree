# 20. 游戏内常用玩法分层评估：原子 / 战术 / 战略 / 本能

> 目的：在补战术库之前，先把"常用玩法"逐一判定层级，避免把**战略**当**战术**实现（例如 `craft_item`、`mine_nearby` 这类）。
> 判定依据：numen 全量 API（`docs/18`）+ 现有树技能/配方（`src/skills/*`、`src/recipes.mjs`）。

## 1. 判定规则（5 问）

按顺序问，命中即停：

1. **是不是一次 numen Lua 调用/一个物理动作？**（走一段、挖一格、放一格、挥一刀、吃一个、查一次）→ **原子**
2. **是不是 numen 内置反射负责？**（逃/防御/卡住/坠落/溺水）→ **本能**（树不实现）
3. **是否需要"先满足前置条件/依赖链"？**（要材料→材料要合成→要工具→要工作站）→ **战略**
4. **是否需要"在多个方案里选"？**（选配方/选材料/选路线/选目标/选工作站）→ **战略**
5. **能不能一句话定义成功、失败就重试或放弃，且只跨少数原子？** → **战术**
   否则 → **战略**

补充：
- **战术**允许小的 `if/循环`，但**不允许依赖规划**和**跨阶段目标切换**；
- **战略** = 目标 + 验收 + 依赖解析 + 战术编排 + 降级；战略只调用战术，不直接写原子；
- **本能** = mod 硬编码（`CoreReflexes`），树只让路+监听事件，不重复实现。

## 2. 分层定义

| 层 | 特征 | 例子 |
|---|---|---|
| 原子 | 单次 Lua 调用/单个动作，无规划 | 走 3 格、挖一格、放一格、`use.hit` 一次、`inv.eat` 一个 |
| 战术 | 有界单目标组合（≤十几秒），失败重试/放弃 | 找最近工作台、走到目标、打开工作台、合成一批、熔炼一批、指定目标攻击 |
| 战略 | 目标+验收+依赖树+跨战术编排+降级 | 做木镐、建安全屋、采集 N 木头、回家、找食物、守家 |
| 本能 | mod 反射链 | 逃、防御、脱困、MLG、溺水自救 |

## 9. 决策：numen 高层技能（含内部动作树）怎么用？

> 用户问题：numen MCP 技能本身可能包含战略级动作树（如 `inv.make`、`work.mine`、`move.to` 内部规划）。树工具应该**忽视它自己重建**，还是**直接用但留下打断**？哪个好？

### 9.1 结论（混合，不二选一）

**按"决策归谁"分三类：**

| 类别 | 判定 | 用法 |
|---|---|---|
| A. 决策归树，技能只执行 | 目标/配方/格子/数量/工作站已由树选定，技能内部只做执行（可能含路径规划这类**执行细节**） | ✅ **直接用**，包成原子/战术，加预算；跨 tick 的用长动作协议 |
| B. 执行很长，但决策已定 | 一个调用可能跑几秒~几分钟（`move.to` 长距离、`inv.smelt`、`fight.attack`） | ⚠️ **可以用，但必须分片或加"预算+急刹+settle+重观测"**；能用底层切片就切片 |
| C. 决策藏在技能内部，树本该自己做 | 技能自己选配方/选矿/选目标/选探索方向（`inv.make`、`work.mine`、`move.explore`、`fight.attack` 的目标选择） | ❌ **不用**（或只在"显式降级"时用并上报）；树用底层 API 自己编排 |

**一句话**：**执行可以借 numen，决策必须归树**；高层技能只有在"树已经把决策定死"时才值得直接用。

### 9.2 为什么不选纯"自己重建"

- numen 的路径规划/寻路、合成配方解析、掉落收集、容器 GUI 等是**mod 内部能力**，自己重建等于重写一套，成本高且不如它稳；
- 我们的 `move.to`/`work.dig`/`inv.craft` 等本来就是"numen MCP 技能"（用户原则：原子动作以 numen MCP 技能为基础单位）。

### 9.3 为什么不选纯"直接用 + 留打断"

- Lua 槽**不可优雅取消**：只能用补丁 `cutOff` 急刹，急刹后是 `detached`，必须 `settle` + 重新观测；
- 高层技能黑盒内部可能跑 17s~120s（实测 `fight.attack` >17s、`work.mine` 大簇 120s 超时），期间树**没有子步骤可见性、不能做每步预算、不能按原子边界抢占**；
- 会直接违反反混乱不变量（A1 三层预算、B1 一 tick 一个决策/一个原子、B3 防抖）；
- 黑盒还可能替树做错误决策（`inv.make` 不会换台、`work.mine` 选矿/路线不可控）。

### 9.4 具体 API 分类（按 2026-11-08 的 help 核对）

| numen API | 内部决策 | 建议 |
|---|---|---|
| `scan.*` / `status.*` / `inv.count/items/recipes/craftable` / `locate.*` | 无（只读） | ✅ 包成只读原子/战术 |
| `move.to(target,spec)` | 只规划**路线**，目标由树给 | ✅ 战术：短距离原子化；长距离由战略分片 |
| `route.plan` + `move.go` | 规划+整段走 | ⚠️ 可用 plan 做可见性；执行要分片 |
| `work.dig(cells)` | 格子由树给 | ✅ 原子/战术（有界格数） |
| `work.collect(radius)` | 范围由树给 | ✅ 战术（有界半径） |
| `build.place(design)` | 设计由树给 | ✅ 战术（有界格数） |
| `inv.craft(recipe,count)` | 配方由树给 | ✅ 战术（需已开格） |
| `inv.make(item,count)` | **自己选配方+台子+循环** | ❌ 战略级黑盒；树应 `recipes`+`craft` 自己编排（可作降级兜底并上报） |
| `work.mine(cluster)` | **自己选矿/找路/收集循环** | ⚠️ 仅当簇由树给出且数量有界时切片使用；否则不用 |
| `fight.attack(entity)` | 自己贴近/选武器/追击直到死亡/丢失/超距 | ⚠️ 长动作：目标已定 + 预算 + 超时急刹/settle；短兵相接优先 `use.hit` 循环 |
| `inv.smelt(furnace,item,count)` | 炉子/物品由树给，但**自己走过去+等** | ⚠️ 长战术：分片（放料/等待/取）或预算+急刹 |
| `move.flee(from,{distance})` | 距离由树给 | ⚠️ 本能已覆盖，仅显式命令时用 |
| `move.explore(dir,{until_})` | 自己找路/回调搜索 | ❌ 战略级；树自己用 `scan`+`move.to` 编排 |
| `move.follow(entity,{seconds})` | 目标/时长由树给 | ✅ 战术（有界时长）；持续跟随是战略行为 |
| `use.*` / `gui.*` / `gear.*` | 单步 | ✅ 原子/战术 |
| `task.stop` | 清理 | ✅ settle 原子 |

### 9.5 长动作协议（B 类必配）

对无法切片的高层调用（`fight.attack`、`inv.smelt`、长 `move.to`）：

1. 调用前：确认槽空闲、目标/参数已定、记预算（≤15s 原子或 ≤25s 战术）；
2. 超时/`detached`/`slot_blocked`：**先补丁急刹**（`cutOff`）→ `settle`（`task.stop`）→ 重新观测 → 由战略决定重试/降级/上报；
3. 同一长动作失败 3 次 → 熔断，不反复重派；
4. 绝不让一个黑盒调用无限占 tick。

### 9.6 对 Batch B/战略层的直接影响

- 制造：**不用 `inv.make`**；`craft_batch` 用 `inv.craft(recipe)`（配方由战略解析 `recipes`/`crafttree` 给出）；
- 熔炼：`smelt_batch` 用 `inv.smelt` 但分片+预算；
- 采集：`dig_cluster` 用 `work.dig(cells)`（格子由树给）；**不用 `work.mine` 自主选矿**；
- 战斗：自主交给本能；显式命令用 `attack_target`（`use.hit` 循环），不用 `fight.attack` 黑盒；
- 探索/回家：战略用 `scan`+`move.to` 分片编排，不用 `move.explore` 黑盒。

## 10. 环境分层执行策略（safe-batch / field-guarded）

> 用户提案：基地内安全环境 → 让 numen MCP 高层技能一口气跑完；野外遇险/被打断过一次 → 切换到树的"战略包模式"（细分、可中断）。
> 评估：**赞成**。这不是两套战略，而是同一套战略的**两种执行档位**，应做成独立的"执行策略层"。

### 10.1 分层位置

```
战略包（目标/验收/依赖/降级）
   └─ 执行策略层（本提案新增）：safe-batch 或 field-guarded
        └─ 战术/长动作（同一套战术库）
             └─ 原子 → numen Lua API
```

- **战略不变**：`make_item` 等战略在两种档位下是同一份代码；
- **执行档位只决定**：能不能用长黑盒技能、预算多大、抢占粒度多细、失败后怎么处理。

### 10.2 两个档位

| 维度 | `safe-batch`（安全） | `field-guarded`（风险） |
|---|---|---|
| 典型场景 | 合成/熔炼/建造/整理 | 出门采集/探索/战斗/长途 |
| 允许高层技能 | ✅ 可以用"决策已定"的长技能（`inv.craft`、`work.dig`、`inv.smelt`、`build.place`） | ❌ 只用战术/原子；长动作必须分片 |
| 单次预算 | 放宽（如 ≤60s，但必须有绝对上限+看门狗） | 收紧（原子 ≤15s，战术 ≤25s） |
| 抢占粒度 | 动作边界（粗） | 原子边界（细） |
| 失败处理 | 记录 + settle + 重试一次 | 立即 settle → 重新观测 → 降级/上报 |
| 中断风险 | 低 | 高（本能/敌人/地形） |

### 10.3 风险判定：只用行为证据，不用位置（用户修正）

> **不用"是否在基地"来判定安全**。基地被入侵时长任务照样会被打断；野外只要没有任何风险证据，也没必要强制细粒度。

**硬风险（立即降档；若长动作在飞→看门狗急刹+settle）**：

1. 收到 `reflex` 事件（本能出手 = 环境已不安全）；
2. 动作被抢占 / 超时 / `detached` / `slot_blocked`（"被打断过"本身就是危险证据）；
3. 受伤：`hp` 下降或 `hp% ≤ 50%`；
4. 敌对进入危险距离（`hostileCount > 0` 且 `hostileDistance ≤ 16`）；
5. 主人处于危险；
6. 危险方块贴近（岩浆/火/水，按 `scan.block` 可选）。

**软风险（降档，但不一定急刹）**：

- 饥饿 ≤ 6；
- 夜晚且无床/无光；
- 连续多次小失败（`no_path` 等）——可降档观察。

**位置不参与执行档位**：基地/锚点只影响**战略选择**（去哪干活、是否回家），不直接给"safe"资格。

**回到 safe-batch**：连续静默 N 秒（默认 30s）无硬风险事件 + HP/饥饿正常 + 附近无敌对。

### 10.4 切换规则（关键）

1. **默认乐观**：没有风险证据时允许 `safe-batch`（允许长技能一口气跑）；
2. **降档立即**：任一硬风险命中 → 立刻 `field-guarded`；
3. **长动作在飞时遇险**：例外允许**中途急刹**（补丁 `cutOff`）→ `settle` → 重新观测 → 转细粒度；不能等它自己跑完；
4. **升档滞后**：回到 `safe-batch` 需安静窗口（默认 30s，防抖）；
5. **打断后强制冷却**：任何一次 `preempted/timeout/detached` 后，强制 `field-guarded` 至少 60s，即使当下看起来安全；
6. **safe-batch 也必须有**：绝对时间上限、看门狗、`reflex` 事件监听、急刹+settle 能力。

### 10.5 与现有不变量兼容

- A1 三层预算：safe-batch 只是把"单动作上限"放宽到 `batchMaxSeconds`，仍然有上限；
- A2 硬抢占：safe-batch 下 P0/P1 仍可触发，但只能是"急刹+settle"（黑盒不可优雅取消）；
- B1 一 tick 一决策：safe-batch 的长调用占用 tick，但仍是"一个动作在飞"；
- B3 防抖：档位本身要防抖（降档立即、升档滞后）。

### 10.8 长动作"三查"协议（用户补充：事前观测判安全）

**查一：事前观测（preflight，强制新鲜）**

- 长动作开始前，强制做一次**新鲜观测**（不接受缓存）：`hp/hunger/pos`、`hostileCount/hostileDistance`（半径放大到 24）、`ownerDanger`、最近风险事件；
- 判定阈值（建议默认）：
  - 无敌对在 **24 格**内；
  - `hp% ≥ 60` 且 `hunger ≥ 8`；
  - 最近 **30s** 内无 `reflex` / 抢占 / 超时 / `detached` / `slot_blocked`；
  - 主人不在危险状态；
  - 长动作**本身风险等级**允许（见下）。
- 任一不满足 → **不进入 safe-batch**，走 `field-guarded`（先处理风险/拆分动作）。

**动作风险等级（长动作分类）**：

| 等级 | 例子 | 允许 safe-batch |
|---|---|---|
| 低 | 基地内合成、熔炼、已知蓝图放置、整理 | ✅ 可 |
| 中 | 已知区域挖一小簇、短途移动 | ⚠️ 需 preflight 全过 |
| 高 | 挖矿下探、探索、跨地形长途、战斗 | ❌ 一律 field-guarded |

**查二：事中监控（长动作在飞时）**

- 事件循环持续监听 `reflex`、主人危险、任务结束；
- 看门狗：超过 `batchMaxSeconds`（默认 60s）→ 补丁急刹 + settle；
- 收到硬风险事件 → 立即急刹 + settle（不等跑完）；
- 承认盲区：长动作期间**观测不到周围**，只能靠事件/伤害/时长兜底。

**查三：事后观测（postflight，强制）**

- 长动作结束/被急刹后，**必须**重新观测一次；
- 用结果决定：成功继续 / 失败降级 / 上报；
- 若事后观测发现 HP 下降、附近敌对、位置异常 → 标记风险，强制 `field-guarded` 冷却。

**结论**：preflight 是必要条件，不是充分条件；三查缺一不可。
