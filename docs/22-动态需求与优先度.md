# 22. 动态需求板（Needs）与紧急战略

> 用户需求（2026-11-08 22:2x）：
> 1. 死后重生，首要任务是获得武器（武器会改变战/逃判断，提高生存率）；
> 2. 入夜后被追会跑很远；
> 3. 工作缺乏工具。
> 这三个战略任务要**动态优先度**：一旦完成，或意外获得武器/工具，自动下调到最低优先度。

## 1. 核心模型：需求板（needs board）

不是"排一串固定战略"，而是维护一组**需求**，每 tick/每次观测评估：

```js
need = {
  id, level,            // 层级（L2/L3）
  when(state),          // 什么时候需要（触发条件）
  priority(state),      // 动态优先级（P1~P5 数值）
  done(state),          // 什么算满足（可数/可检测）
  strategies: [],       // 先试哪个战略，失败降级到下一个
  cooldownSeconds,      // 完成后多久才允许重新触发
  armedUntil,           // 防抖
}
```

规则：
- **未满足** → 需求激活，按 `priority()` 排队；
- **满足（完成或意外获得）** → 立刻把对应目标/战略优先级降到最低（P5/0），取消排队中的重复目标，trace `need_satisfied`；
- 条件再次变假（又死了/工具丢了）且冷却结束 → 重新激活；
- 防抖：条件需持续 N 秒才激活；完成后需持续满足 M 秒才重新武装；
- 优先级可以**随状态变化实时改**（例如武器没到手时 P2，附近有敌对升 P1）。

## 2. 三个紧急需求（本轮）

| 需求 | 触发 | 动态优先级 | 满足条件 | 首选战略 | 降级 |
|---|---|---|---|---|---|
| **get_weapon** | 无武器（`st.weapon` 空） | 无武器+敌对≤16 或 刚重生 → **P1(85)**；无武器但安全 → P2(65) | 背包/手持出现任意武器 | **`recover_death_drops`**（先去死亡点捡回掉落） | `craft_weapon`（木剑链） |
| **get_tools** | 缺镐或斧 | 缺工具且当前任务需要 → P2(70)；否则 P3(50) | 有镐/斧 | **`recover_death_drops`** | `craft_tools`（木镐/木斧链） |
| **night_chase** | 夜晚 + 有敌对 + 离家>32 或 reflex 连续>10s | **P1(85)**；威胁解除/到家 → 立即降 P5 | 天亮 或 无敌对 或 离家≤16 且安全 | `night_hold`（有武器就地防御；没武器往家/光走） | `return_home`（脱战后回家） |

**关键洞察**：死后最快的武器/工具来源是**死亡点掉落**，不是重新合成。所以"捡回装备"优先于"造装备"；只有死亡点不可达/掉落没了，才走合成链。

## 3. 三个需求对应的战略

### 3.1 `recover_death_drops`（L2，P1/P2）
- 目标：死亡点（地点簿 death 记录）；
- 战术：分片 `move_segment` 到死亡点附近 → `collect_drops`（半径收集）→ `count_items` 验证拿到武器/工具；
- 验收：武器或工具出现；
- 失败降级：死亡点不可达/无掉落 → `craft_weapon` / `craft_tools`。

### 3.2 `craft_weapon` / `craft_tools`（L3）
- 木剑：原木 → 木板 → 木棍 → 工作台 → 木剑 → 装备；
- 木镐/木斧同理；
- 需要的战术：`dig_cluster`（砍树）、`collect_drops`、`place_one`（工作台）、`craft_batch`、`equip_best`；
- 缺料时先 `gather_wood`（gather 战略/战术）。

### 3.3 `night_hold` / `return_home`（L3，P1）
- 有武器且 HP 够：不要跑远；靠近家/光源，让本能防御（MobDefenseChain）处理；
- 没武器：往家/光走，避免越跑越远；
- 脱战后：`return_home`（分片移动回锚点）→ 验收：离家≤16 且无敌对；
- 注意：树不能撤销本能 FleeChain，只能在本能结束后接管"回家"；如果持续被追，升级上报。

## 8. 黑板机制（多同伴共享需求/分配任务，后续再做）

> 用户需求（2026-11-08 22:4x）：需要一个黑板，让复数同伴掌握当前需求、分配不同任务。**等眼前三个紧急需求跑通后再做。**

### 8.1 定位

- 需求板（needs）目前是**单同伴**的：每个 lane 自己评估、自己排队；
- 多同伴时需要一个**共享黑板**：需求、任务、认领、进度、失败都写在同一处，避免重复做同一件事/互相抢资源。

### 8.2 黑板数据（草案，会话级）

```js
board = {
  needs: [{ id, level, priority, when, done, createdBy, expiresAt }],
  tasks: [{ id, needId, strategy, params, status, owner, claimedAt, progress, result }],
  resources: { /* 已知箱子/工作站/基地 */ },
  claims: { /* 谁在做什么、占用什么 */ },
  version, updatedAt,
}
```

### 8.3 分配规则（草案）

1. 需求进黑板 → 生成任务（按战略拆解）；
2. 同伴按能力/距离/优先级**认领**任务（claim 带版本号，防重复）；
3. 认领后写 `owner`；完成/失败释放；
4. 高优先级需求可抢占低优先级任务（在战术边界）；
5. 同一需求只允许一个 owner，除非任务可并行拆子任务；
6. 黑板只会话内存在（游戏/树重启清空），与"临时图鉴"一致。

### 8.4 接口（草案）

- 内部：`board.publishNeed / claimTask / updateTask / releaseTask`;
- MCP：`tree_board`（只读 summary / 任务列表）；LLM 可看但**不直接改**（避免和树抢调度）；
- 事件：任务认领/完成写 trace + inbox（只通知，不叫醒）。

### 8.5 前置条件

- 单同伴动态需求板稳定；
- 多同伴支持（daemon lanes 已有，但调度/黑板未接）。

### 2.1 恢复装备的硬前置（用户修正：夜里不出去捡）

> 用户：捡回武器要有前提，比如白天才去；否则晚上死了立马出去捡，要么跑远逃了、要么又死一次进死循环。

**规则**：
- **只在白天 + 安全时**执行 `recover_death_drops`；
- 夜里死后：**不出去**，就地守家/待在光源附近/等天亮；可选在基地内用材料做一把木剑（仅当基地安全且材料够），否则等待；
- 恢复前置条件（`gearRecoveryGate`）：
  - `!dark`（白天）；
  - HP ≥ 60%；
  - 饥饿 ≥ 8；
  - 24 格内无敌对；
  - 死亡点距离 ≤ 160（太远放弃，改合成）；
  - 最近 2 次内没有连续死亡（防死循环）；
  - 上次恢复失败后需冷却/重试许可。
- 恢复途中若入夜或遇险：**中止并返回**（不继续跑远）；
- 死亡点不可达/危险（岩浆/虚空/水）→ 标记不可恢复，走 `craft_weapon`/`craft_tools`。

### 8.6 修正：黑板是独立的"大任务/工程"层（用户 2026-11-08 22:5x）

用户想法：黑板应是一个**单独的大任务层级**。例如"修基地"挂在黑板上，预先分好子战术包组；多个同伴各自领取推进；只有一个同伴时就逐个战术包组推进。这样**不会和个人的高优先级战略包冲突**。

**分层定位**：

```
个人紧急需求（get_weapon/get_tools/night_chase，P0~P2）
     ↑ 永远优先、可抢占
个人战略队列（L2/L3，如 make_item、secure_gear）
     ↑ 空闲/安全时执行
黑板：L4 工程/大任务（如 build_safe_house、build_farm、establish_base）
     └─ 预先拆好的工作包（work packages，每个≈L2/L3）
          └─ 战术包组
```

**规则**：

1. 黑板任务**默认低优先级**（P4/P5），只在个人没有紧急需求时领取；
2. 高优先级个人需求可抢占黑板工作包（战术边界），工作包保存进度后放回黑板；
3. 工作包有依赖（先地基→墙→屋顶）、资源/角色标签（伐木/建造/守卫）；
4. 多同伴：每个工作包同一时刻只允许一个 owner（claim 带 lease/超时），避免重复；
5. 单同伴：同一黑板按依赖顺序逐包领取，行为上就是"逐个战术包组推进"；
6. 黑板只会话内存在；LLM 可看进度/提议工程，但不微操；
7. 个人战略与黑板任务解耦：个人战略不需要知道黑板；调度器按优先级在"个人需求 > 个人战略 > 黑板工作包"之间选。

**例子：`build_base` 黑板任务拆包**：
- 包1 选址/清理（L3）
- 包2 采集木材/石头（L2 gather）
- 包3 做工作台/工具（L2 secure_gear/make_item）
- 包4 地基+墙（L3 build）
- 包5 屋顶/门（L3 build）
- 包6 床/火把/箱子（L2 place）
- 包7 验收（L2 verify）
单同伴按 1→7；多同伴可并行 2/3/4（不相邻的包）。

### 7.5 觅食优先级修正（2026-11-08 23:0x）

用户观察：`seek_food` 优先级似乎太高。排查：**不是内置脑**（numen 不自主进食，游戏事件也写明 `you do not eat on your own`），是树自己的 `feed` 自动计划。

修正：
- 觅食计划只在 **safe-batch**，或**背包已有食物**（只吃、不出门找）时启动；
- `field-guarded`（夜里/有威胁/血低）且没食物 → 不启动 `seek_food` 远征，trace `feed_deferred`，等安全档再找；
- 执行闸门：`feed` 计划在 field-guarded 且无食物时会被挂起（有食物时允许"吃"这一步）；
- 需求板优先级：`get_weapon/get_tools/night_chase`（50~90）会先于自动觅食（计划步骤优先级 10）。

实机验证：
```
feed_deferred hunger 5 但 field-guarded(reflex) 且无食物 → 暂不出门找
need_enqueue get_weapon priority=90 -> secure_gear
need_enqueue night_chase priority=85 -> night_hold
```
