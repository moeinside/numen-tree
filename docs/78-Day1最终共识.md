# 78. Day1 最终共识（PM 有条件批准后）

> 2026-11-10。行为/MC 设计 + 点子王质询 + 总控接口约束 + PM 审核后的定稿。  
> 状态：**有条件批准；条件已采纳，可开工。**

## 1. 定性

Day1 是**夹具能力验收**，不是自主/泛化证明：

- 报告只能写“该夹具下可跑通”；
- 不得写“验证了自主生存”。

## 2. 入口

- A：可见树 → 默认倾向采集；
- B：无树 → 一次有界探索 ≤90s / ≤2 跳；dusk 剩余 <40% 放弃；
- C：低血/夜/水/威胁 → 硬门/反射优先。

找不到树：`log_unseen=unknown`，不得写“没有”。

## 3. 最终里程碑与判定

### M1 有木

- **原木 ≥6**；
- 计数口径：**只算原木**，木板/木棍不计入 M1；
- 给 M2/M3 留余量（4 根零余量）。

### M2 有工作台

- 已放置且 L1 现场可交互；
- 不是“造过”。

### M3 工具尝试（改名）

- 谓词名：`tool_held_attempt`，**不再宣称“工具有效”**；
- 证据：手持木工具 + attempt 绑定 + 动作前后 item/world 双观测；
- 空手砍树**不得**满足 M3（负样本）；
- 报告明确：这只证明“持工具完成了一次动作”，不证明耐久/效率。

### M4 夜间安全

- `night_no_damage`：入夜后 HP 无下降、无死亡、无新增贴脸敌对；
- `food_ok`：
  - 至少一次进食证据（food_stock 下降 / 饥饿上升 + eat postcheck）；
  - **或**入夜前食物存量 ≥2；
  - 饥饿 ≥14 只作安全条件，**不能单独满足 food_ok**；
- 火把路径删除（从零需熔炉/木炭，Day1 不保证）；
- 封闭庇护可选，不默认要求。

### Day1 通过

```
M1 + M2 + M3 + night_no_damage + food_ok
```

## 4. 失败分类（不可自报）

- `capability_fail`：有素材/机会，系统没做到；
- `material_unavailable`：世界没给树/动物/裸岩；
- `unknown`：观测失败/不确定。

硬规则：

- `material_unavailable` 必须由**离线 oracle/审计**证明；
- `unknown` 必须有占比上限，超限该次运行作废；
- 不允许用“没树/没食物”重分类规避 `capability_fail`；
- death=0 覆盖全天，不只夜间。

- `material_unavailable` 无 oracle 佐证；
- `unknown` 滥用；
- 动作 ok 但世界未变；
- 运行时 WorldHints 泄漏。
