# 66. 顾问团结构：行为层 + 世界层

> 2026-11-10。新增 MC 游戏专家顾问，与行为学家形成两层互补。  
> 目标：行为上合理 + 游戏里可行 + 可验收，而不是任何单一视角独裁。

## 1. 为什么要 MC 专家

行为学家能判断：

- 该不该找食物/庇护；
- 行为是否机械、是否像有限理性；
- 优先级/节律是否合理。

但他不知道/不该负责：

- 1.21.1 具体合成链、工具等级、耐久、掉落；
- 生物群系/结构/怪物行为；
- 食物/水源/ shelter 的实际获取成本；
- vanilla / NeoForge / numen / 触手限制；
- 某个策略在当前世界是否真的可行。

MC 专家补的是**世界可行性层**。

## 2. 两层结构

```text
行为层（Behaviorist）
  why / what：
  - 该不该做
  - 行为是否像有限理性
  - 优先级/节律/中断
  - 失败是否可解释

世界层（MC Expert）
  how / feasible：
  - 这个版本里怎么做
  - 需要什么材料/工具/站点
  - 代价/风险/替代路线
  - vanilla/mod/API 限制

交集：
  “行为上合理 + 游戏里可行”的方案
```

### 互相质询

- 行为学家问 MC 专家：  
  “这个行为在游戏里是否必要？有没有更自然的替代？”
- MC 专家问 行为学家：  
  “这个行为链是否过度拟人、忽略游戏效率/风险？”
- 产品经理问两者：  
  “这能验收吗？证据是什么？”
- 点子王问全部：  
  “哪里会崩？最便宜的捷径是什么？”
- 总控问全部：  
  “这还在北极星上吗？会震到哪？”

## 3. 权限边界

- 行为学家：可否决“行为上不可接受”的方案；
- MC 专家：可否决“游戏里不可行/机制错误”的方案；
- 产品经理：可否决“不可验收/范围失控”的方案；
- 点子王：可否决“工程上会崩/过度设计”的方案；
- 总控：可否决“偏航/症状修补”的方向；
- Lead：最终决策。

## 3.1 风险评估兼任

- **总控兼任战略/愿景风险**：是否偏航、是否破坏不变量、是否拿长期换短期；
- **点子王兼任工程/架构风险**：爆炸半径、迁移/回滚、槽竞争、测试缺口；
- 关键架构变更两层都过；模块内部功能变更主要过点子王；
- 详见 `docs/70-风险评估职责.md`。

没有单一顾问能同时决定“行为 + 世界 + 工程 + 验收”。

## 4. MC 专家的职责

- 必须读 `WORLD-CONSTRAINTS.md`，并给建议标 `[V]/[N]/[T]/[M]/[?]`；
- 提供版本准确的机制/合成/攻略/百科；
- 区分 vanilla / NeoForge / numen / 触手限制；
- 主动指出“vanilla 可行但 numen 做不到 / 触手看不见 / 需玩家配合”；
- 给“最小可行路线”和“更稳路线”；
- 标出前置、材料、时间、风险、失败模式；
- 挑战行为学家的不切实际假设；
- 挑战现有 recipe/strategy 的机制错误；
- 不写代码、不做排期、不替 Planner 规划。

## 5. 还缺什么角色

当前顾问团：

- 总控（愿景/优先级）；
- 产品经理（范围/验收）；
- 行为学家（行为层）；
- MC 专家（世界层）；
- 玩家代表（玩家期望/变更警报）；
- 点子王（工程红队）。

可选补充：

- **QA/可观测性**：产品经理可兼，暂不单设；
- **Mod/API 集成专家**：MC 专家需覆盖 numen/触手限制，暂不单设；
- **学习/ML 顾问**：离线学习阶段再设；
- **知识管理员**：文档/决策日志，Lead + 总控可兼。

结论：**现在只加 MC 专家 + 玩家代表，不再扩顾问团**；避免顾问比开发还多。

## 6. 调用方式

- 冷启动，只读；
- 每次给：NORTH-STAR + 当前能力/阶段 + 具体玩法问题 + 现有 recipe/strategy 摘要；
- 输出：机制事实、可行路线、前置/风险、对行为学假设的质询；
- 不读全量代码/trace；
- 与行为学家可开联合评审（同一问题，两种视角）。

## 7. 一句话

> **行为学家管“像不像人”，MC 专家管“游戏里行不行”；两人互相质询，产品经理和总控把关，避免单视角把项目带偏。**
