## 2. P1.1 诊断工具

### 接口

```text
输入：plan / goal / actionLock / world before-after / trace
输出：
  progressing | waiting | stalled | contradiction | unknown
  + evidence
  + suggested（只建议，不派动作）
```

### 判定

```text
progressing：stepsDelta 或谓词前进 + worldDelta
waiting：明确阻塞证据 + 等待对象 + 恢复条件 + 上限
stalled：无阻塞 + N 秒无进展
contradiction：自报 ok 但世界未变 / plan active 无 gate 记录
unknown：证据不足，不得降级成 stalled
```

### 玩家可见

```text
一行状态 + 一句理由
例：卡住了 · 因为 24s 没有方块/背包变化
最近 5 条变化，不展开 JSON
```

### 判负

```text
工具写状态或派动作
unknown 默认成 progressing
合法 wait（等天亮/等炉/等槽）被判 stalled
已知 contradiction 漏报
同一输入两次结论不同
```

## 3. 开发工具缺口（先补这些）

### P1 必需

1. **统一 game-tick 时基**：诊断/deadline/watchdog 同一时钟，不用 wall clock。
2. **动作前后世界快照**：目标格 ±2 方块、背包 item_delta、位置、hp/hunger、in_water/on_ground。
3. **trace 时间对齐/聚合**：trace / 快照 / GM / 触手四条时间线可对齐。
4. **夹具快照/回滚/清理**：整存档快照、husk 回收、barrier 清理、places/goalstore 同步校验。
5. **负样本注入器**：已知 stalled/假 ok/矛盾注入，用于诊断工具验收。

### 后置

```text
GM damage / kill / data get / gamerule
触手任意格查询 + observed_at/source
pilot/GM 平台扩展
SpatialMemory 全量
```

## 4. P1.2 V3 薄骨架

```text
3–5 条结果型议程（谓词 + deadline + must/soft）
单焦点
只在原子边界/硬信号切换
空焦点有基线行为
每次切换带 reason
```

判负：

```text
must 无 deadline
无事件按时钟切焦点
30s 内义务↔机会切换 >2
错过 must 仍判通过
```
