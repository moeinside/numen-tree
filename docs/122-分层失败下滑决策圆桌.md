# 122. 分层失败下滑/上浮：决策圆桌

> 2026-11-11。玩家代表 + 项目总控 + 点子王 + 行为学家 + MC 专家。  
> 议题：失败优先下滑、到底层再逐层上浮、A1 重排、阈值换里程碑，是否值得做；比现在强还是差。

## 1. 决策

```text
限定条件做。
不是现在全做。
完整 A1–A5 滑动栈仍放 P2。
```

最小切片：

```text
单 milestone
方法 ≤2
深度 ≤2
失败 → 标记 → 换兄弟方法 → 再失败 → 上浮一层
```

不在切片内：

```text
A1 全耗尽重排
反射回挂
Arbiter 主干重写
```

## 2. 可预见表现

### 变强

```text
长链不再一次失败整条挂
局部失败能换方法而不是换目标
意图连续，玩家看到“还在解决同一件事”
失败有交代，不是静默重试
```

### 变差

```text
下滑层数 × 单动作时长，可能吃掉黄昏/夜间窗口
从“跳”变成“磨叽/死磕”
层数越多，失败归因越糊
容易把 material_unavailable 解释成“方法不够努力”
```

### 净判断

```text
上限更高，下限更低。
多步恢复会明显强于现在；
简单场景会更慢；
阈值/时间窗/归因做错，会比现在更乱。
```

## 3. 必须满足的条件

### 失败分类

适合下滑：

```text
out_of_reach
partial
no_path（仅目标格不合法、环境正常）
缺前置
timeout（分批/短动作）
```

禁止下滑，直接上浮/放弃：

```text
material_unavailable
refused
bad_argument
slot_blocked
溺水/岩浆/低血/hostile_close
工具已坏
```

### 每层预检

```text
下滑后必须重新过 preflight
+ standable
+ route 可达
执行次数可观测
“没有 atom begin”不算真正下滑
```

### 时间预算门

```text
剩余窗口 < 下一层最短执行时长
→ 不许下滑，直接上浮
```

### 计数

```text
同 (milestone, method) 二元组 ≤2
每层独立计数
父层共享失败预算
方法需等价类判定，避免换皮重试
```

### A1 重排

```text
只在段边界/硬信号
保留失败记忆和今日已尝试
有冷却和次数上限
不得清空进度
```

### 反射

```text
回挂起点 = node id，不是层号
恢复前核对情境 + postcheck
禁止重放副作用
```

### 玩家可见

```text
每次下滑/上浮/换里程碑
带一个可读停顿 + 一句 reason
```

## 4. 判负

```text
下滑后同一动作重复失败且无新信息
上浮后未改变方法/条件就重试
失败计数跨 milestone 串味
同里程碑达阈值仍继续下沉
下滑越过时间窗
形式上下滑但 0 次 atom begin
反射恢复导致重复副作用
```

## 5. 排期

```text
P0：只做失败三分 + 单 milestone 降级/重试
P1：预留 parentId / 结果谓词 / 恢复点
P2：完整分层滑动栈
```

红线：

```text
P0 出线前不改 Arbiter 主干；
不能用架构重构替代 P0 能力验证。
```

## 6. 一句话

```text
方向对，但先证明“失败能被正确归因、降级能真的改变方法”。
否则做出来的不是调度，是一个会优雅空转的堆栈。
```
