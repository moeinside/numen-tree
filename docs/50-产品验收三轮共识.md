# 50. 产品/验收三轮共识：P0 出线计划

> 2026-11-10。三轮产品/验收讨论：R1 计划 → R2 技术细节质询 → R3 最终共识。  
> 结论：**有条件同意；P0-a → P0-b 是正确执行起点；先做“能判负的审计”，再改行为。**

## 1. 最终范围

### P0 出线 = P0-a 且 P0-b

**P0-a：恢复语义 + 两夜无 LLM**

- resume 前成功观测门；
- slot_blocked 计入 blocked；
- 同意图重试 ≤2；
- 17s suspend→resume 抖动 = 0；
- A 恢复语义 / C 失败三分 + 全局失败预算 / D 疲劳表现乘子；
- 两夜无 LLM（不要求重启）；
- 固定世界夹具。

**P0-b：最小 DurableGoalStore**

- 单 checkpoint + 意图标签；
- 原子写；
- 重启幂等；
- 一个动作边界 kill 点；
- 死后续跑；
- B 最小 2 条谓词 + evidence。

**P0-a 单独完成只算“未过 P0”。**

## 2. 最终执行顺序

1. **固定世界夹具 + 独立审计脚本**；
   - 必须先做负样本演练；
   - 三类假通过必须分别判负：
     - 执行器自报成功但世界未变；
     - 谓词由执行器自评；
     - 快照故意缺口/篡改。
   - 演练不通过，不开始 P0-a。
2. P0-a resume 修复 + A/C/D 最小；
3. 两夜无 LLM 跑通；
4. P0-b 最小 DurableGoalStore + 一个 kill 点 + B 最小谓词/evidence；
5. 两夜 + 重启续跑验收；
6. 过则 P0 出线，再 P1/P2/P3。

## 3. 证据链与验收

**一律不采信执行器自报。**

```
外部状态快照（定时+事件触发）
+ tentacle 世界观测（settle 后）
+ trace 事件（begin/settle/blocked/resume/death）
+ 独立审计脚本
```

判负规则：

- 自报与审计不一致 → 负；
- 快照缺口超阈值 → 负；
- 审计无法复现 → 负；
- 不允许“未知”状态。

**kill 矩阵**：

- P0-b：1 个动作边界杀点；
- P1：5 点 × 3 种子；
- 精确“已提交未确认”窗口无法注入 → 降级为“动作边界杀点 + 重启后世界观测幂等”；
- 残余风险：无法证明任意时序 exactly-once，必须写在 P0 验收报告首页。

**死亡口径**：

- 只承诺 milestone 进度单调 + 死亡有界/计惩罚；
- 不承诺资产单调；
- 死亡惩罚按预设规则计入期望进度分母，归因到 profile，不改历史记录。

## 4. 产品经理最后的三个条件

1. **固定夹具、审计脚本、P0-b schema 的版本与阈值，开跑前冻结**；事后调整阈值即视为未过。
2. **P1 的 5 点 × 3 种子矩阵预算上限写死**，不允许用扩充矩阵替代 P0 出线。
3. **“无法证明 exactly-once”的残余风险放在 P0 验收报告首页**，不是附录。

## 5. 一周保守版

只交付 P0-a：

- resume 修复 + A/C/D 最小；
- 两夜无 LLM；
- 固定夹具 + 审计负样本演练；
- 若余力，P0-b 只做单 checkpoint + 单 kill 点 + 死后续跑。

**不交付**：多 profile、跨天累计、P2 审计、SOP 回推、schema 迁移、留出种子矩阵。

关键路径项不做就是红，不用空接口假装完成。

## 6. 阶段依赖

```
P0-a → P0-b → P1（完整持久化/幂等矩阵/指标基线）
                ↓
P2（全谓词/watchdog/审计/SOP depth≤2/reservation）
                ↓
P3（3 个硬编码 profile，跨天穿插）
                ↓
P4（mood/习惯/社会/风险态度）
```

P3 前禁止任何跨天累计。

## 7. 一句话

> **先交付一个“会判负的审计”，再修 resume；P0-a 与 P0-b 都过才算 P0 出线。**
