# 31. 架构术语：树工具前置 / 树工具执行层

> 状态：**术语与边界记录**，暂不实现。用于以后沟通直接引用，避免把“前置接入”和“树执行层”混在一起。

## 1. 两个术语

| 术语 | 英文/代号 | 定位 |
|---|---|---|
| **树工具前置** | tree-front | 树工具前面的**独立接入层**：语义匹配 + LLM Gateway |
| **树工具** | tree | **游戏智能的执行层**：状态、需求、优先级、战略/战术、执行编排 |

```
玩家 / LLM / 本地模型
        ↓
树工具前置（tree-front，独立模块）
  ├─ 语义匹配：文本 → 意图（无 LLM 也能用）
  └─ LLM Gateway：profile、简报、工具面、会话/缓存
        ↓ 只调用树 MCP
树工具（执行层，唯一状态源）
        ↓
numen（具身动作）
        ↓
Minecraft
mods：触手（感知）、lockfix（医生）
```

## 2. 边界

**树工具前置只做：**

- 玩家自然语言 → 意图/参数/置信度；
- LLM 的模型接入、简报拼装、工具面稳定化、会话/缓存管理；
- 未命中/歧义记录，必要时要求确认；
- 调用树 MCP，把意图交给树。

**树工具前置不做：**

- 不执行游戏动作；
- 不维护长期任务/生存状态（最多短 TTL 缓存）；
- 不替代树的优先级/需求/战略决策；
- 不直接调 numen。

**树工具只做：**

- 唯一状态源（需求板、计划、地点、黑板）；
- 需求/效用/安全优先级；
- 战略/战术/原子动作编排；
- 对前置层提供稳定 MCP 接口。

## 3. 协作规则

1. **唯一状态源 = 树**；前置层不得建立第二套任务状态。
2. **唯一执行接口 = 树 MCP**；前置层不直接调 numen。
3. **前置层可替换**：换本地模型/换语义表，不影响树。
4. **树不感知模型差异**：两种 profile（stateless 8K / sticky context）都在前置层处理。
5. **术语固定**：以后说“前置”= tree-front；说“树/执行层”= tree。
