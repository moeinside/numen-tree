# Numen Tree：具身 AI 同伴项目简介

> 给“点子王”评估用：一页说明这个项目是什么、怎么分层、现在能做什么、边界在哪、想听什么意见。

## 一句话

在 Minecraft 里做一个**自给自足的具身 AI 同伴**：  
**LLM/树负责“想和决定”，numen 负责“身体动作”，mod 负责“感知和修故障”。**

不是写死脚本的机器人，也不是让 LLM 直接微操每一个动作，而是：

```
LLM（意图/高层编排）
  ↕ MCP
树（决策、优先级、战略/战术、记忆、预算）
  ↕ MCP
numen（寻路、战斗、交互、合成等身体能力）
  ↕
Minecraft 世界
```

旁边有两个小型 mod：

- **触手（numen-tree-tentacle）**：只读感知，像同伴的眼睛/触觉；
- **医生（numenlockfix）**：修 numen 的锁/内置脑卡死，不参与行为决策。

## 分层架构

| 层 | 作用 | 例子 |
|---|---|---|
| **原子动作** | 一次 Lua 调用，纯执行 | 移动、挖一格、攻击、放方块、吃东西 |
| **战术包** | 可复用的短动作组合，只做一件事 | 走到某处、挖一小簇、捡掉落、做一批合成 |
| **战略包** | 目标 + 验收 + 依赖 + 降级 | 死后恢复装备、夜里守家、解决食物、放火把 |
| **需求板** | 发现“现在缺什么”，动态升降优先级 | 缺武器、缺工具、夜里被追、饥饿、卡住 |
| **效用仲裁** | 普通任务按分数竞争，而不是死优先级 | 存材料、补光、储备食物 |
| **执行策略** | 决定“现在能不能做” | 危险时暂缓长动作、给本能反射让路 |
| **mod 层** | 感知/诊断/修故障，不做决策 | FOV/遮挡/地形感知、清锁、清内置脑任务 |

核心设计原则：

1. **执行可以借 numen，决策必须归树。**
2. **LLM 做意图级编排，不逐步微操。**
3. **需求驱动 + 动态优先级**：完成/意外获得后立即降级；紧急安全优先。
4. **昼夜分开设计**：白天准备/采集/建造，夜里守家/保命。
5. **少作弊、可复现**：尽量用游戏内动作；关键行为可回放测试。
6. **上下文预算**：原始世界数据不直接喂 LLM，树先压缩成小简报。

## 现在能做什么

- **生存闭环**：死后恢复装备、夜里回家/守家、找食物、吃东西、脱困。
- **资源与合成**：采木头/石头、工作台、木制工具、熔炉/木炭链、批量合成。
- **存储与整理**：把背包素材存进箱子；按配方从箱子取料再合成。
- **基地/过夜**：白天检查床/火把/照明，不够就补；夜里交给守家。
- **具身感知**：触手提供自身/附近实体/地标/光照/时间/地形；Lua 槽被占时树仍能拿到信息。
- **故障恢复**：锁/内置脑卡死时，可诊断、重置、加看门狗，不必每次重建同伴。
- **动态决策**：需求板 + 效用仲裁 + 硬安全优先级，避免“一个任务霸占到底”。

## 玩家在游戏里会体验到什么

**第一眼：** 一个像玩家/NPC 的同伴，在基地附近自己走动、砍树、挖石头、合成、开箱子、吃东西；不是跟着你的宠物，也不是原地站桩的商店 NPC。

**一天里大概会看到：**

- 白天：自己出去找木头/石头，回来做工作台、木镐/木斧，把素材存进箱子；饿了会找东西吃。
- 黄昏：开始检查基地——有没有床、火把够不够、要不要回家；不够就尝试补。
- 夜里：尽量回基地/守家，遇到怪会打或跑；不会为了做长期任务跑很远。
- 被卡住：会自己尝试走、跳、挖；有时会反复试几次，看起来像“新手玩家在想办法”。
- 死亡后：会在基地复活、丢背包，然后尝试重新搞装备；不是无代价复活。
- 内置脑/反射占上风时：会有一段时间“站着不动/东张西望”，然后恢复；严重时可能需要外部诊断/重置。

**它现在像什么：** 一个**有身体、会自己安排事情、但还不够熟练的具身新手**。  
不是“完美机器人”，也不是“LLM 直接遥控的木偶”；玩家能明显看到它在**自己判断、自己动手、也会犯错**。

**玩家能感知到的“生命感”来源：**

- 有真实身体和移动动画，不是瞬移/脚本传送；
- 有需求（饿、怕、想回家）导致的行为变化；
- 会说话（少量台词，如开工、低血、危险、失败）；
- 会记住地点、会回去、会补救；
- 失败不是静默的：会尝试、放弃、上报，而不是永远卡死。

**目前还不太“像人”的地方：**

- 资源不足时会反复空跑/犹豫；
- 遇到复杂地形会卡住或原地打转；
- 内置脑反射有时会长时间接管，看起来“发呆”；
- 指令入口目前偏树/LLM 侧，游戏内还不是自然语言聊天指挥。

## 还没做好 / 边界

- **资源缺口**：附近没食物/床/火把/熔炉时，仍可能长时间空转或冒险失败。
- **内置脑反射循环**：numen 自带的逃跑/战斗反应有时会长时间占住同伴，重置只能暂时缓解。
- **`no_path` 工程能力**：桥、台阶、安全下坠、绕行还在做，目前脱困偏“盲试”。
- **多同伴**：还没有共享黑板/分工；触手和树目前按单同伴设计。
- **模组生态**：兼容层（`numen_tree_compatibility`）延后，先保证原版级基础同伴可用。
- **大型工程**：农场、牧场、建基地、探索地图还没做。

## 想请点子王重点看

1. **分层是否合理**：原子/战术/战略/需求/仲裁，有没有该合并或该拆的层？
2. **优先级机制**：硬安全 + 效用分数 + 昼夜权重，会不会太复杂或太保守？
3. **多同伴方向**：共享黑板、任务分片、跨同伴感知，应该先做哪一块？
4. **mod 边界**：触手只做感知、医生只修故障，这个边界是否长期可持续？
5. **`no_path` 策略**：先诊断再搭桥/挖台阶/安全下坠，还是找路/换目标更划算？
6. **自主 vs 安全**：什么时候该让 LLM/树接管，什么时候该让本能反射优先？
7. **最值得优先做的功能**：食物、照明、基地、探索、多同伴，哪个最能提升“像人”？

## 一句话总结

**这是一个“LLM 做意图、树做决策、numen 做身体、mod 做感官与维修”的具身 AI 实验；目标不是让 AI 操作 Minecraft，而是让它在 Minecraft 里逐渐能自己活下来、自己变强。**
