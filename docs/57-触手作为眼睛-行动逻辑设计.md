# 57. 触手作为“眼睛”：行动逻辑与架构设计

> 2026-11-10。行为学家 + 点子王两轮意见综合。  
> 核心结论：**看不是独立阶段，而是行动循环里的“预测—校验”；触手应是唯一环境感知写入者，不是 fallback。**

## 1. 为什么现在不对

- 主感知是定时 Lua 轮询 + 战术内临时 scan；
- 触手只在槽被占时兜底；
- Facts 是旧状态，没有 unknown/stale；
- 战术不声明前置，Priority 不产生观察；
- 动作返回 `ok` 被当成“世界达成”，没有终态校验。

水里的 bug 是同一个病：

```
动作返回 success
  ≠ 角色已经上岸
  ≠ 世界到了预期状态
```

## 2. 人类式行动循环

```text
目标
  ↓
行动前：只看 critical facts（1~3 条 affordance）
  ↓
执行
  ↓
行动中：本体感/前向模型监控；预测误差超阈值才“抬头”
  ↓
settle
  ↓
行动后：验证 expected predicate
  ├ 真 → 达成
  └ 假 → 失败/惊讶 → 换策略/求助
```

不是“先全量观察，再行动”，也不是“每 tick 重看”。

## 3. 三档观察触发

### 必须看（top-down）

- 动作前提 unknown/stale，且该事实能翻转决策；
- 安全硬信号（溺水/低血/贴脸威胁）；
- 站点/容器使用前现场校验；
- 动作 settle 后的 expected predicate。

### 被吸引看（bottom-up）

- 威胁/疼痛；
- 预期违背（位置没变、血量跳变、动作成功但谓词假）；
- 新异/异常。

### 可凭记忆不看

- 熟悉场景、低风险、该事实不参与本次动作；
- 在 TTL 内；
- 记忆只用于**候选预选**，不能当执行前提。

## 4. 两种病

### 看太少

- 把“没观测到”当“不存在”；
- 把动作 success 当世界达成。

### 看太多

- 观察焦虑、抖动、抢执行槽；
- 治法：信息价值 > 观察成本；只查能翻转决策的事实；
- 连续 K 次无信息增量 → 停，转默认动作/求助；
- 观察禁止变成拖延。

## 5. 观察决策规则

- **R0** 硬信号/溺水/疼痛 → 立即观测，可抢占；
- **R1 前置门**：只校验 critical facts；known+TTL → 直接执行；stale/unknown → 一次现场观测；仍 unknown → 保守默认/放弃，**不许带 unknown 硬跑**；
- **R2 后置验**：按 expected predicate 复核；真=达成，假=失败，进失败三分，记 surprise；
- **R3 惊讶**：|观测−预期| 超阈值 → 打断当前 SOP，重选；
- **R4 低频扫视**：无事件时按移动距离/时段做低成本 glance，不全量轮询；
- **R5 预算**：观察/分钟上限；连续无增益 K 次即止；观测失败归因“信息缺失”，不算策略失败；
- **R6** 记忆只做候选预选与低风险捷径。

## 6. 数据契约

```text
Observation {
  source: tentacle_body|tentacle_sight|numen_body|numen_scan|interaction|memory,
  kind, observedAt(gameTick), radius, fov, partial, payload
}

Fact {
  key,
  status: known|unknown|stale,
  value,
  authoritySource,       // 单 key 单权威
  observedAt(gameTick),
  ttlGameTicks,
  evidenceSeq
}
```

必需：

- 三态（`unknown != false`）；
- observedAt / ttl（按游戏 tick，不按 wall clock）；
- partial/FOV/LOS（区分“不在视野”与“不存在”）；
- source（冲突仲裁）；
- 观察预算。

不建议：

- 数值 confidence 进 Planner；不确定性用 unknown/stale/partial 表达即可。

## 7. 权威来源

| 事实 | 权威 |
|---|---|
| 自身 HP/饥饿/背包/手持 | numen body |
| 附近实体/地形/水/光照 | tentacle |
| 容器内容 | 交互 + 记忆 |
| 站点有效 | 现场校验 + SiteRegistry |
| 动作结果 | numen 动作结果 + settle 后触手复核 |

冲突：

- 单 key 单权威，其余只作候选；
- 冲突写 conflict 日志并降级 unknown；
- 禁止 last-write-wins。

## 8. 插进现有架构

```text
Reflex/本能（最高）
  ↓
Arbiter（选目标/work unit）
  ↓
GoalProfile / Milestone
  ↓
SOP / Planner
  ↓
Executor
  ├ 动作前：ensure critical facts（PerceptionService）
  ├ 执行
  ├ settle
  └ 动作后：verify expected predicate（PerceptionService 写 Fact）
  ↓
PerceptionService（唯一 Observation→Fact 写入者）
  ├ tentacle 主环境源
  ├ numen 自身/动作源
  ├ interaction 容器/站点
  └ 去重/inflight/预算/退避
  ↓
Facts（三态，供战术/优先度只读）
```

关键：

- 观察**不进 Arbiter**（不是普通 work unit）；
- 只有“主动探索/找水/找箱”这类消耗时间的观察才作为 work unit；
- 战术层禁止直接读旧 state；只能读 Facts；
- 动作内 scan 结果回灌 PerceptionService，不许只用于当前动作。

## 9. 行为树结构

```text
Selector
├ Reflex（最高）
├ Goal/Milestone
│   ├ Preflight(criticalFacts)   // 缺则 observeOnce
│   ├ Action
│   ├ Settle
│   └ Postcheck(expectedPredicate) // 假 → FailureTriage
├ SurpriseInterrupt              // 预期违背→重选
└ IdleGlance                     // 低频扫视
```

ObservationPlan 只用于：

- 前置门无法满足；
- 惊讶打断；
- 多步查看（开容器、走到视野点）。

不要做成“总是先观察再行动”的串行阶段。

## 10. 最小原型（先治水里/卡住）

1. `PerceptionService`：
   - `observeNow(kind, ttl, inflightKey)` 唯一入口；
   - Fact 单点写入；
   - 去重/单 inflight/超时退避。
2. 动作声明：
   - `criticalFacts`（执行前确保）；
   - `expectedPredicate`（settle 后校验）。
3. 先接三个动作：
   - 移动/脱困：`expected = 不再 in_water && on_ground`；
   - 采集：`expected = 目标方块变化/掉落增加`；
   - 开容器：`expected = 窗口/内容变化`。
4. 观察触发只做：
   - 前置 missing；
   - settle 后 postcheck；
   - 异常（位置没变/仍在水中）。
5. 预算：
   - 单动作 ≤2 次观察；
   - 单 companion 单 inflight；
   - 连续 2 次超时退避 30~60s；
   - 观察不抢 reflex。

## 11. 验收

- 带 stale/unknown critical fact 执行动作次数 = 0；
- 动作 success 但 expected predicate 假 → 必须判失败（负样本必须捕获）；
- 状态改变动作 postcheck 覆盖率 = 100%；
- 观察调用/分钟 p95 + 超时率 + 决策延迟 p95 不劣化；
- 双源冲突有仲裁结论比例 = 100%；
- 水里/脱困误报 = 0。

## 12. 一句话

> **触手不是“更勤快的传感器”，而是行动循环里的眼睛：行动前确认前提，动作后验证终态，惊讶时打断；唯一写入 Facts，Planner 只吃三态事实。**
