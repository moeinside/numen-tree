# 95. Day1 优先度系统：小会共识（待项目经理审批）

> 2026-11-10。顺序质询：project-steward → mc-expert → behaviorist → idea-king → player-rep。  
> 输入：`archive/day1-tester-1/ADVISOR-BRIEF.md`、docs/78、docs/92、docs/94。  
> 状态：**待 product-architect 审批；未批准前不进入执行。**

## 1. 方向判定

- 目标不是“为通过 Day1 调一组权重”，而是让树获得**具身控制的基石**；
- Day1 是第一个证明场景，不是唯一优化目标；
- 测试员轨迹是观察参考，**不能作为设计目标、阈值来源或树的能力上限**；
- 优先度系统首先是“**什么绝不牺牲**”的排序宣言，其次才是“选谁”；
- 必须有可追溯理由；不能是魔法权重、候选打分拟合、任务清单或 LLM 在线仲裁。

## 2. 非目标 / 硬边界

- 不直接使用测试员轨迹、GM、WorldHints 作为优先度输入；
- 不为通过 Day1 修改验收口径或阈值；
- 不新增战术/战略包（`from_zero` 除外）；
- 不硬编码第一动作、夹具坐标、树种、单 biome 假设；
- 不照抄测试员带宽：石工具、熔炉、床、`gui.*` 直操容器、791 格远行、一次连杀 15 只、5 次 say、2.5 分钟手工 GUI 救场；
- 不把“玩家在场”当夜间无伤的合理解释；本 run 玩家实际在 128 格外。

## 3. 核心排序

按后果，不按任务名：

```text
死亡风险 > 不可逆损失 > 可逆需求
```

- **死亡风险**：溺水、岩浆、坠落、HP 危殆、夜间贴脸敌对无法脱离；
- **不可逆损失**：已进入战斗/破坏/消耗，掉落会消失、方块已破坏、物品已消耗；
- **可逆需求**：饥饿、庇护、资源、工具、探索。

在这三类内，再按：

```text
L0 反射（立即保命，可在原子边界抢占）
L1 危机（低血/饥饿临界/夜间贴脸敌对）
L2 生存保底（食物存量、夜间安全位）
L3 资源/工具（木→台→木工具；Day1 范围）
L4 承诺（已开段/已放台，防抖动）
L5 探索信息
```

**承诺保护窗口**：

- 动作开始时声明 `reversal: irreversible | compensable | resumable`；
- 抢占只在**幂等原子边界**发生，不在 Lua 脚本中途砍；
- 不可逆段不能无限被饥饿等可逆需求抢占；
- 被抢段要么续跑并保留目标/进度，要么整体放弃并记失败，禁止“重新接近—再被抢”；
- 同一原子连续失败两次即升级/换策略，不无限重试；
- 危机解除优先回补被抢段，而不是重新规划。

## 4. 调度与进度

- 最小单位：**幂等原子 + 段级承诺**，不是长脚本；
- 进度不存内存：靠 world/postcheck 的 `item_delta`、`block_target_changed` 等事实重建；
- resume 先“复观测→对账”，已满足的原子跳过；
- 动作必须留下世界可见中间态，否则 resume 等价重做；
- 动作声明 reversal 类型，抢占方只查声明，不做事后解释。

## 5. 可观测判据（防“报告文学”）

至少记录并跨重启累计：

- 抢占次数、抢占后短窗二次抢占率（抖动）；
- 段重启次数、同原子重复失败率；
- reason 覆盖率，且 reason 必须对上 world/postcheck 事实；
- 被抢占任务的回补率/完成率、危机解除后恢复延迟；
- 未决问题下 idle 率；
- 反证据：某优先级从未真正改变选择 → 它只是文档。

抖动上界原则（行为/红队建议，待 PM 定值）：

```text
每里程碑窗口内同因 suspend→resume 次数有上限；
suspend 占总时长有上限；
跨重启累计，run 边界不清零；
超过即该里程碑判失败，不接受“重启后重算”。
```

## 6. Day1 可观测项（不是验收通过）

- **M1**：独立记账 `inv.count(*_log)` 起点 + 每次 mine/collect 的 item_delta；判“曾达 ≥6”；
- **M2**：放置回执 + 可交互回执；最小可行证据 = 一次成功 3×3 合成 + 台坐标 L1 观测；
- **M3 `tool_held_attempt`**：同一事务绑定——动作前主手是工具 id、动作 ok、世界/背包有变化；空手砍树判负；
- **M4**：夜间独立敌对观测（`scan.entities("hostile")` 固定采样）才可判 night_no_damage；触手只辅助，且 `tentacle_use.jsonl` 必须非空；
- **food_ok**：进食证据链 + 熟食存量，不以测试员自报代替。

## 7. 外部干预 / 死亡有界

- 玩家救援、外部 GM 兜底 = **人为延长**，不算树“死亡有界”；
- 必须标 `assisted/external`，独立 channel，结论栏禁止引用，**不进失败率主表**；
- “死亡有界”定义：**无外援时死亡可归因且不复发**，不是“零死亡”；
- 测试员 run 全部为观察域，不作树能力证据。

## 9. 一句话

> **优先度系统是树的“什么绝不牺牲”宣言 + 幂等原子/段承诺调度；Day1 只是它的第一个具身证明，不是应试目标。**

## 10. 项目经理审批结论（2026-11-10）

**有条件批准**，作为 P0-0b 优先度系统基线。

### 条件

1. §5 反证据升级为验收门：每个 L0–L5 至少一条可判负证据；
2. `reversal` 声明 + “只在幂等原子边界抢占”必须进验收埋点，否则不可验证；
3. 测试员轨迹冻结，不作阈值/权重/能力上限来源。

### 冻结口径

- **死亡有界**：无外援时死亡可归因，且同一根因不复发；归因需独立证据（外部快照+审计），不接受自报；“不复发”需定义观察窗口与根因登记表，跨重启累计；
- Track A 仍要求 `death=0`；assisted/玩家/GM 救援 run 不进主统计，也不能用来证明“活着”；
- Day1 报告强制分栏：树自主判断链（reason 对 world/postcheck）、外部干预（玩家/GM/测试员/工具兜底）、assisted 标记；
- Track A 窗口内任一干预 → 该 run 不通过，相关谓词不得计通过；工具日志只能解释“为什么没通过”，不能解释“通过”。

### 抖动上界（PM 定值，冻结前只能收紧）

```text
同因 suspend→resume ≤ 2 次/里程碑窗口
suspend 占总时长 ≤ 20%
17s 级抖动 = 0
跨重启累计，不清零
超限该里程碑判失败，不接受“重启后重算”
```

采样窗口随 Day1 规格一起冻结。

### 执行范围

仅树 `src/` + 验收埋点。  
测试员/GM 不进入 Track A，不改其代码，不新增树对工具的运行时依赖；埋点只读、独立目录、随审计版本冻结；改测试员/验收口径另开审批。
