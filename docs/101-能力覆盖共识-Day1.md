# 101. 能力覆盖共识：D1 木工具链 + D2 食物闭环

> 2026-11-10。参与者：`mc-expert` + `behaviorist`，两轮对抗后一致同意。  
> 输入：`archive/day1-tester-1/ADVISOR-BRIEF.md`（LLM 测试员 Day1；机制/现象参考，不是 Track A，不是树能力上限）。

## 0. 结论

先做两个领域，最低要求是**正常路径 + 一次失败回退 + 无空转**：

```text
D1 木→工作台→木工具→一次实际使用
D2 食物闭环：发现→获取→进食（或入夜前存量≥2）
```

不把采石/石工具纳入 Day1 门。  
不把“测试员做到的”直接当树的能力上限。

## 1. 为什么是这两个领域

- D1 串起 M1/M2/M3，失败模式最密，且木头在测试员世界不贫瘠（14 原木/201s）。
- D2 暴露抢占、掉落未捡、GUI/熔炉语义坑，是“看似自主实则救场”的最大来源，也是旧 Day1 失败（avgHP5/饥饿）的直接原因。
- 夜间安全不作为独立领域：太便宜且无独立 hostile 观测时不可判，作为 D2 尾段处理。

## 2. 能力矩阵与缺口（共识）

### D1 木工具链

```text
need: missing_tool（有）
strategy: craft/gear（有）；craft_tools 只木镐+木斧（缺 stone 升级，Day1 不做）
tactic: craft_item / equip / place_one / count_items（有）
atom/skill: craft / mine_nearby / place_block / find_block / collect_items（有）
```

缺口：

- 木镐耐久不可观测（无耐久字段）；
- 无“坏镐→重做/换工具”链；
- 无空手砍树负样本埋点；
- 失败后 `can't_harvest` 可能重复同一动作。

### D2 食物闭环

```text
need: hunger≤6 eat / ≤12 forage（有）；缺食物存量记账
strategy: secure_food（吃→箱→烹→猎→腐肉）（有）
tactic: survive_eat / locate_station / scan_container / fetch_batch / find_entity / attack_target / collect_drops / smelt_batch（有）
atom/skill: atom.eat_once；seek_food/forage/fight_safe/smelt/fetch_items（有）
```

缺口：

- 生肉直接吃未实测；
- 同一动物连打失败不换目标；
- 无猎场记忆；
- 无动物时容易重排 hunt，而不是 `material_unavailable`；
- 熔炉/GUI 超时可能被当可重试失败。

## 3. 失败与终止语义（必须实现）

四类终止动作都必须存在，且带 reason：

```text
terminate  当前动作/战术明确结束
wait       有上限的等待（等天亮/等槽/等熔炉），不能把“在等”记成“在干”
ask        求助主人/上级（显式、有次数上限）
abandon    放弃当前 need/目标，记 material_unavailable 或 blocked
```

规则：

- 同参数重复失败 ≤2 次必须升级归因；
- 同原子失败 ≥3 次必须换策略或 abandon；
- 失败预算按“不同策略数”而非“次数”；
- 无进展 watchdog：进度谓词不单调 → 升级；
- 抢占后被抢段要么续跑，要么记失败；不允许整脚本重放；
- 掉落/挂起段回补必须可观测；重复副作用 = 0。

## 4. M3 正样本取证

默认：

```text
木剑攻击动物
```

要求：

- 动作前手持工具物；
- 动作返回 ok；
- 独立 item_delta / block_target_changed postcheck（掉落真正进背包）；
- 空手同动作做不成的负样本对照（证明工具是必要条件，不只是“手上有东西”）。

无动物夹具时，才允许：

```text
1–3 块石质方块 probe
evidence_action = stone_probe
```

二者择一记录，不得都算，不得临时切换顶替。  
若 `collect` 不可观测（pickup_delay / 5 min 过期），该次 M3 判**不可判**。

## 5. 夹具

- 固定夹具预置 ≥3 只动物，落在已加载区块；数量/距离/方位冻结；
- 另留一套**无动物夹具**，验证 `material_unavailable` + 箱/烹降级；
- 自然探索版只作 Track B 参考，不替代夹具版；
- 预置只布置世界，不布置知识：不得把动物位置写进 Fact/目标；
- 玩家方块同意被拒 → 放弃该簇，记 owned_resource，不重试。

## 6. 最低验收

### A 食物

一次完整“发现→获取→吃”证据（饥饿上升 + world postcheck），或入夜前存量 ≥2；  
无动物夹具必须走箱/烹并上报 `material_unavailable`，不得空转。

### B 工具链

原木 ≥6 → 工作台 L1 可交互 → 木工具持有并完成一次动作（M3 取证）；  
空手砍树判负；不合成石工具/熔炉。

### C 无空转

同参数重复失败 ≤2 必升级；四类终止动作都存在且带 reason；  
world postcheck 与自报一致；抢占后回补可观测、重复副作用=0。

## 7. 理想场 / 缺陷场验收矩阵（PM 审核稿）

### 理想测试场

- D1：木头≥6 → 工作台 L1 可交互 → 木工具持有并完成一次动作；
- D2：发现→获取→进食完整闭环，或入夜前存量≥2；
- 无空转、无同参数重复失败、无抢占后整脚本重放；
- world postcheck 与自报一致。

### 缺陷测试场

每次只注入一个缺陷（如无树、无工作台、无动物、工具坏、玩家方块不可用）：

- 失败必须**限制在该缺陷对应的 need/strategy 分支内**；
- 允许该分支内出现**有界失败循环**，但必须满足：
  - 可归因到该缺陷；
  - 有上限（同参数失败≤2、同原子≤3）后进入 `abandon/blocked`；
  - 不阻塞其他独立 need/领域；
  - 有 reason 和可观测证据。
- **不允许无限死循环**；单动作槽下的无限循环必然挤占其他 need，直接判负。

### 硬判负条件（PM 补充）

1. **硬运行上限**：缺陷场必须冻结 wall time / 游戏时窗 / 步数上限；到点仍无 `abandon/blocked` 或仍无 reason，判负。
2. **独立 oracle**：缺陷注入与 `material_unavailable` 必须由独立 oracle/快照证明，不能靠 reason 自报；夹具起点必须 0 资源、0 食物，预置物只许布置世界，不许布置背包。
3. **其他领域可判**：同一 run 内必须证明其他独立 need 被评估过并有执行机会（或给出安全/昼夜合法让路的 world 证据）；只证明缺陷分支失败，不足以排除全局卡死。
4. **D2 存量**：“入夜前存量≥2”必须来自本次 run 的获取，不能是夹具预置。
5. **M3 工具效力**：工具耐久不可观测时，只能以动作失败/world postcheck 取证；M3 只称 `tool_held_attempt`，不得宣称“工具有效”。

### 判负

```text
理想场未跑通
或
缺陷场失败扩散到其他分支
或
缺陷分支无上限、无 reason、无终止
或
突破硬运行上限 / 独立 oracle 不成立 / 其他领域无机会证明
```
