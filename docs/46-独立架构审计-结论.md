# 46. 独立架构审计结论（2026-11-09）

> 冷启动子智能体只读审计；不继承作者结论。  
> 结论：**修改后推进；方向成立，但组件顺序与范围要改；当前“多日多链最终完成”不可实现。**

## 1. 核心结论

当前实际架构是：

```
规则表仲裁 + 单意图需求目标 + 单计划槽配方状态机 + 战术/原子执行
```

不是目标架构中的：

```
ProfileManager + milestone + bounded Planner + ResourceLedger + DayAgenda
```

**多日穿插并最终完成：当前不可实现。**

断点不是 DayAgenda/公平配额，而是四件更基础的事：

1. 长期目标/milestone 不落盘（重启、死亡即丢）；
2. resume 前不复核事实（世界变了仍硬跑）；
3. 没有跨天条件唤醒（wait-until，农场不可能）；
4. 没有方法回推（铁件/挖铁/铁链不存在）。

## 3. 关键判断

- **单意图/承诺/迟滞**：已有，保留。
- **反射打断**：已有且干净，是现有架构真实强项。
- **ResourceLedger**：对单同伴是过度设计；换成“站点注册表（位置+最后校验时间）”即可。
- **DayAgenda**：便宜但顺序靠后；先有持久化/复核/方法表，再谈配额。
- **Planner**：不要先上 GOAP；用 HTN 式方法表 + 有界回推，和现有 recipe 同构，可增量。
- **农场**：没有 wait-until，结构上不可能。
- **基地跨天**：没有 milestone 状态/进度，重启或死亡即归零。

## 4. 修正后的最小落地顺序

### P0 DurableGoalStore

磁盘 JSON 保存：

- 1 个活跃长期目标；
- milestone 列表；
- 最后推进日；
- checkpoint。

验收：kill 进程、死亡、换会话后仍从 M2 继续。

### P0 resume 前事实复核

位置/背包/站点/时间任一不符 → 重规划，不硬跑。  
验收：箱子空了、水冻了、被带远，不按旧快照执行。

### P1 wait-until milestone

`dueAt/wakeAt`，到点唤醒，不轮询。  
验收：等待类 milestone 不刷 tick，到点自动回来。

### P1 方法回推

方法表 requires/produces；缺料插子目标，父暂停；深度 ≤4、节点 ≤20。  
验收：缺矿自动插 mine_iron，而不是 report。

### P1 单活跃长期目标 + 每日至少 1 milestone

在 schedule 上扩，不新造 DayAgenda。  
验收：3 天 2 条链都有推进，无 0 进度链。

### P2 站点注册表 + 每日指标

站点：工作台/炉/箱 + 最后校验时间；指标：milestone 完成数/切换次数/夜死/饿死。

## 5. 第一个纵向切片

**iron_age 只做到：石镐 → 熔炉 → 3 粗铁，跨 2 夜。**

不要先做整条铁具链。  
总验收：无 LLM 活过 3 昼夜、两条链各完成 ≥1 milestone、重启可续、无夜抖。

## 6. 一句话

> **方向对，但先补“持久化 + 恢复复核 + 条件唤醒 + 方法回推”，再谈多链配额；不要同时上四层新组件。**
