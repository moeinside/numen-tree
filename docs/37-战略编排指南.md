# 37. 战略编排指南：前置检测 → 补缺 → 执行 → 后处理 → 存储

> 2026-11-09。由 `fish_food` 实战失败提炼：  
> 扁平计划默认“工具/水域/熔炉/箱子都已存在”，任何一环缺失就整条失败。  
> 以后新战略包/战略表按本指南编排。

## 1. 核心原则

**每个战略/战略表 profile 必须显式建模完整链：**

```
能力检测 → 缺什么补什么 → 执行 → 后处理 → 存储/交付
```

不能只写“执行”那一步。

## 2. 六段式模板

### M0 前置事实检测

先查 Facts：

- `hasRod / hasString / hasSticks`
- `openWater / iceHole`
- `hasFurnace / hasFuel / hasChest`
- `hasWeapon / hasPickaxe / hasAxe`
- `homeDistance / timePhase / hostileCount`

缺什么，进入对应补缺里程碑；不要直接执行。

### M1 补工具

- 有工具 → 跳过；
- 没工具但材料够 → 制作；
- 材料不够 → 找箱子/采集/猎杀/向玩家求助；
- 都不行 → 短报“需要玩家给什么”，不无限重试。

### M2 找场地/目标

- 水域：开放水面优先；冰洞需要玩家/环境支持；
- 矿点/箱子/床/熔炉：先扫描/记忆/确认可达；
- 不满足 → 探索/换目标/短报。

### M3 执行

- 真正做动作；
- 有预算、失败分类、重试上限；
- 执行成功后不要假设后处理一定可行。

### M4 后处理

- 钓鱼 → 烤鱼；没炉/燃料 → 安全生鱼直接吃；不能吃 → 带着；
- 采集 → 合成/存储；没工作台 → 先做台；
- **可选后处理不能把整个任务判失败**，要有 fallback。

### M5 存储/交付

- 有箱子 → 存；
- 没箱子 → 随身携带，不当作失败；
- 需要交付给玩家/基地 → 记录未完成事项。

## 3. milestone 契约

```js
{
  id: 'ensure_rod',
  requires: ['hasSticks'],          // 或可制作条件
  acceptance: 'hasRod',
  fallback: {
    no_string: 'find_string',
    no_material: 'ask_player',
  },
  checkpoint: true,
  helpHint: '需要玩家给钓竿或线',
}
```

每个 milestone 必须有：

- `requires`（Facts）
- `acceptance`
- `fallback`
- `checkpoint`
- 失败短报（如果需要玩家干预）

## 4. 玩家干预是一等公民

有些失败不是树能解决的：

- 冰面需要玩家开洞；
- 没有线/钓竿；
- 没有熔炉/燃料；
- 没有食物来源、没有箱子。

处理方式：

1. 不盲目重试；
2. 生成 `intervention_needed` 短报；
3. 明确告诉玩家：**做什么、在哪里、为什么**；
4. 同类短报限频；
5. 玩家完成后能重新进入该 milestone。

## 5. 反模式（`fish_food` 案例）

```text
fish_once → cook_cod → cook_salmon → store
```

默认钓竿/熔炉/箱子都存在；结果：

- 钓到了鱼；
- 没炉子 → 烹饪失败；
- 整条计划判失败；
- 之后死亡丢竿，无法恢复。

**错误不在钓鱼，而在编排把“后处理”当成了必经硬步骤。**

## 6. 新战略检查表

写新战略前逐项问：

- [ ] 工具/装备检测了吗？
- [ ] 缺工具能补吗？补不了找谁？
- [ ] 场地/目标确认了吗？
- [ ] 执行失败分类了吗？
- [ ] 后处理有 fallback 吗？
- [ ] 存储失败会毁掉主任务吗？
- [ ] 需要玩家干预时，短报写清“做什么”了吗？
- [ ] 这个任务应该做成 routine 还是 profile 里程碑？
- [ ] milestone 粒度能被打断并恢复吗？

## 7. 与优先度系统的关系

- 优先度系统选 **milestone / work unit**，不选整个大计划；
- 前置检测属于 milestone 的 `eligible`；
- 补缺动作可以是同 profile 的 milestone，也可以是独立救援 intent；
- 跨 intent 阻塞才升级给 arbiter；
- 可选后处理失败不应触发整任务重跑。

## 8. 一句话

> **战略包不是“动作清单”，是“能力检测 → 补缺 → 执行 → 后处理 → 存储”的可恢复链路；缺一环就补，补不了就明确告诉玩家，而不是整条失败。**
