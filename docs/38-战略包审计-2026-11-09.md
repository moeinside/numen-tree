## 2. 已修

### `fish_food`

- 钓鱼成功不再假设能烤：
  - 无炉/燃料 → `cook_*` 失败 → `eat_raw` 生吃（鳕鱼/鲑鱼安全）；
- 存储失败不再判整任务失败：
  - 无箱子 → 继续 `done`，鱼随身带；
- 缺钓竿/水面 → 短报玩家：
  - “请玩家给钓竿或线”
  - “请在冰面开洞，或指一个开放水域”
- 错误短报修正：只有 `fish` 步失败才报 `ice_or_water`，烹饪失败不再误报。

## 3. 仍需补的战略表

1. **`fish_supply` profile**：
   - ensure_rod（检测→制作/找线→玩家求助）
   - ensure_water（开放水/玩家洞）
   - fish
   - process（烤/生吃）
   - store/carry
2. **`smelt_item` 参数化**：不要固定 `raw_beef`，由调用方给 item。
3. **通用 `tool_recovery`**：检测镐/斧/钓竿/线，缺什么补什么。
4. **`food_security` profile**：feed/fish/猎杀/箱子/作物统一入口。

## 4. 结论

- 现有 flat recipe 大多能处理“缺材料/缺台子”，但**缺工具检测和后处理 fallback**；
- `fish_food` 已按指南补了后处理 fallback；
- 下一步按 profile 化补 `fish_supply` / `tool_recovery`，而不是继续往 flat recipe 里塞 if。
