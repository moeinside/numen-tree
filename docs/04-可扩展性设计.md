# 可扩展性设计

> 目标：加新功能不需要改树的核心；换 mod、接新 API 也不需要重写。

---

## 1. 三层扩展点（从便宜到贵）

| 层 | 加什么 | 怎么做 | 成本 |
|---|---|---|---|
| **L1 技能卡** | 新的"一次任务" | 往 `src/skills/` 丢一个 `.mjs` | 极低，自动发现 |
| **L1.5 台词库** | 新的"机械播报话术" | 往 `lines/*.json` 加条目 | 极低，纯数据 |
| **L2 Lua 模块** | 新的"复合动作/循环" | 在游戏内装 Lua 模块（`numen.module.save`），技能卡一行调它 | 低，改配置文件 |
| **L3 NumenPlugin** | 接别的 mod 的新 API | 写一个 NeoForge 小 mod，实现 `NumenPlugin` | 高，需要 Java + 构建 |

**先 L1，不够再 L2，真需要新 API 才 L3。** 绝大多数需求在 L1/L2 就能解决。

> 台词库（L1.5）额外约定：它是**纯数据 + 机械选择**。生成/更新由离线的一次性子 agent 做，
> 运行时只查表。详见 `lines/README.md`。

## 2. L1：技能卡

### 2.1 接口契约

```js
export default {
  id: 'go_to',                    // 唯一，CLI 里用它
  title: '走到目标点 / 主人身边',   // 人看的
  params: { ... },                // 参数说明（用于 help）
  build(ctx, params) {            // 生成一段 Lua
    return { code: '...', timeoutMs: 300000 };
  },
};
```

### 2.2 硬规矩

1. **Lua 程序最后必须 `return` 一个紧凑 JSON 字符串**（≤300 字符）。
   原因：MCP 回执对单个长字符串会截断。
   格式：`{"ok":1,...}` 成功；`{"ok":0,"kind":"...","msg":"...","hint":"..."}` 失败。
2. **必须用 `prelude.mjs` 里的 `S/N/J/F/FAIL`**，不要自己拼 JSON。
3. **不要在技能里做价值判断**。技能只回答"做完了没有、怎么失败的"。
4. **失败要带 `kind`**（`no_path` / `out_of_reach` / `not_found` / `denied` / …），树靠它做升级与恢复。
5. **超时要写**：`timeoutMs` 要覆盖最坏情况，宁可长也不要让调用被截断。

### 2.3 加一个技能的完整流程

1. 新建 `src/skills/<id>.mjs`，按上面契约写。
2. `node src/cli.mjs skills` 确认被自动发现。
3. `node src/daemon.mjs` 重启（技能是启动时加载的）。
4. `node src/cli.mjs goal --companion <名> --skill <id>`。

不需要改 `index.mjs`、不需要改 `lane.mjs`、不需要改 `daemon.mjs`。

### 2.4 现有技能

| id | 用途 |
|---|---|
| `go_to` | 走到坐标 / 主人身边 |
| `follow_owner` | 跟随一段时间 |
| `dig_nearby` | 挖附近指定方块 |
| `eat` | 吃东西 |
| `retreat` | 远离最近敌对生物 |
| `idle` | 原地等待（节流/占位） |

## 3. L2：Lua 模块

当技能逻辑变复杂（多阶段、循环、需要跨调用保留状态），不要把它堆进技能卡的字符串模板里，而是：

1. 在游戏内用 `numen.module.save` 存一个 Lua 模块（例如 `numen.brain.gather`）。
2. 技能卡只负责 `return numen.brain.gather({...})`。

好处：

- Lua 侧可以单元测试、可以复用；
- 技能卡保持短小；
- 修改不需要重启树进程（模块在游戏侧）。

⚠️ 注意：模块是**按某个 id 分目录**存的（`config/numen/lua/<id>/`）。该 id 的作用域尚未确认（见 `02-探针记录.md` §6.3），所以不要把模块当作"全局唯一"来依赖。

## 4. L3：NumenPlugin（接别的 mod）

numen 官方提供插件 SPI（`com.dwinovo.numen.api.NumenPlugin` / `NumenApi`）：

```java
public interface NumenPlugin { void setup(NumenApi api); }
public interface NumenApi {
  <T> void on(CompanionEvent<T>, Consumer<T>);
  void api(String group, String name, Class<?>);
  <T> void codec(Class<T>, Codec<T>);
  void bundleSkills(Path);      // 注册技能包（SKILL.md）
  void bundleModules(Path);     // 注册 Lua 模块包
  void registerGear(GearSource);
  void registerEventType(String, boolean);
  void emit(NumenPlayer, String, Map<String,String>, String, boolean);
}
```

现成例子（jar 内）：`plugins/ysm`、`plugins/tlm`、`plugins/kaleidoscope`、`plugins/ftbquests`。它们各自带 `SKILL.md` 和（部分）`modules/*.lua`。

**什么时候才做 L3**：当需要的功能在现有 Lua API 里根本表达不出来（例如某个 mod 的界面状态、事件流）。这时写一个很小的 NeoForge mod，注册几个 `numen.<group>.*` 函数，树的技能卡就能用，**完全不需要改 numen 本身**。

## 5. 目录约定

```
src/skills/*.mjs   技能卡（自动发现，加文件即扩展）
macros/            宏计划（多个技能的固化组合，尚未实现）
skills/            （预留给未来的 SKILL.md 型知识包）
logs/              trace
probe/             探针与一次性脚本
```

---

## 6. 版本与兼容

- 技能卡的 `id` **一旦被宏计划引用就不能随便改**，改要先迁移 `macros/`。
- 技能参数尽量**只增不改**；要改语义就新建一个 id（`go_to_v2`）。
- 每条宏计划都要记：创建时间、来源（手写/右脑生成）、依赖的技能 id 与版本。
