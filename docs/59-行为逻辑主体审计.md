# 59. 行为逻辑主体审计结论（行为学家）

> 2026-11-10。第一次静态行为逻辑审计。  
> 结论：闭环设计方向对，但当前循环未闭上；P0-0 方向正确，但必须先补三个结构缺口。

## 1. 四个断点

1. **观测仍是第 3 步的定时轮询**，needs 在第 4 步消费同一份旧 Facts；
2. **settle → postcheck 之间可被抢占/挂起/空闲仲裁插队**，导致“假 ok”逃过失败三分；
3. **失败三分缺“信息缺失”归因入口**，观察失败会被算成策略失败；
4. **predicate 尚未存在**，triage 收到的失败语义不清。

修法：

- 观测改为触发/前置门，不再只是定时；
- **settle + postcheck 做成不可抢占的原子段**；抢占只能在其后发生；
- 观察失败归因“信息缺失”，不算策略失败；
- postcheck 后统一进 FailureTriage。

## 2. 五者边界混乱

reflex / instinct / attention / need / priority 不是五个正交概念。  
实际共线：安全硬信号、本能加成、注意威胁加成、safety_hold 需求——四者同源，叠加会造成安全过冲。

建议压成三层：

```
硬信号（只抢占，不进候选分）
压力-需求（drive：hunger/fatigue/safety 池）
注意-惊讶（salience：只由观测与预期违背产生）
```

候选分 = 需求 + 注意 + 学习；**安全不在候选分里重复计权**。  
夜间抑制属于上下文，不属于需求。

## 3. 单意图 + 单计划槽

能产生连续行为，但会有：

- 挂起/恢复抖动（17s 已是证据）；
- 忙而无进度（每 tick 重算 + 失败预算不断换策略）；
- 观察无处安放（观察不进 Arbiter，只能塞进动作内，拉长动作/超时）。

建议：

- 观察作为“不占计划槽的微打断通道”，由 Executor 前置门直接调 PerceptionService；
- R5 信息缺失归因进失败三分；
- 观察失败不重试成风暴。

## 4. 昼夜时段表

P0 两夜够用，但缺三样：

1. **过渡带**：dusk 应有“收工前最后一件”+照明检查；
2. **疲劳-时间耦合**：累了提前收，schedule 是默认值不是命令；
3. **夜间低强度活动**：无威胁时守夜不能站桩，应有 glance/整理/巡看。

最低补：

- dusk 预警窗口；
- 疲劳可覆盖 schedule；
- 夜间 idle glance。

## 5. 失败责任层

分层合理，但失败归属错位。应是：

```
atom 失败 → plan 内 onFail
plan 失败 → strategy
strategy 反复失败 → milestone 层（谓词 + 无进展 watchdog + 降级/求助）
```

**只有 milestone 层有权宣布目标不可达；onFail 无权。**

否则 onFail 承担太多“环境变了”的失败，退化成无限换策略的瞎忙。

## 6. 行为树切片建议

外层五节点：

```
Selector
├ Reflex
├ Goal Sequence(Preflight, Action, Settle, Postcheck)
├ SurpriseInterrupt
└ IdleGlance
```

内层步骤顺序保持 SOP/recipe。  
FailureTriage 抽成独立子行为（postcheck 后统一入口），不要散落在每个 onFail。  
多步观察/找水/找箱才抽独立子行为。  
守夜/巡逻用 schedule 上下文选择器，不做深树。  
不要给每个动作写 BT。

## 7. P0 必要 vs 后置

**必要**：

- 白名单三态；
- 前置门；
- postcheck；
- 单 inflight + 预算 + 退避；
- 惊讶打断；
- 失败三分含“信息缺失”归因；
- settle+postcheck 原子化；
- resume 观测门；
- dusk 过渡；
- milestone 无进展 watchdog。

**后置**：

- 完整 BT；
- 观察进 Arbiter；
- ObservationPlan 作 Planner 子目标；
- FOV/LOS/partial；
- 双源仲裁；
- SiteRegistry；
- 夜间巡逻智能；
- 多段日程细化。

## 8. 三个尖锐问题的答案（设计口径）

### Q1 settle 与 postcheck 之间允许被抢占吗？

- 设计上：**不允许普通抢占/挂起**；
- 反射硬信号可以打断，但 action 结果立即标记 `unknown`，不携带 success；
- 中断结束后先 postcheck，再决定失败三分；
- 需要原子段标志/所有权，而不是靠时序运气。

### Q2 安全四重叠加会永久停摆吗？

- 会；所以 hard signal 只抢占，不进候选分；
- safety need 只在无硬信号时存在；
- 恢复条件必须明确（威胁消失/距离阈值/时间退避）；
- P0 指标：安全过冲导致的“活着但 0 进度”时间要有上界。

### Q3 谁有权宣布目标不可达？

- atom/onFail：只处理本步可恢复失败；
- strategy：换方法；
- **milestone/watchdog：唯一有权宣布不可达/求助**；
- 全局失败预算只升级到 milestone，不直接宣判。

## 9. 结论

**行为逻辑主体需要改的不是“再加一层”，而是：**

1. settle+postcheck 原子化；
2. 安全信号去重（硬信号不进候选分）；
3. 失败责任层归位；
4. 观察微打断 + 信息缺失归因；
5. dusk/疲劳/夜间 glance 的节律。

这些应并入 P0-0，而不是等 P1。
