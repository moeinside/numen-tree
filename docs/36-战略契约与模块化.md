# 36. 战略契约与模块化：优先度 / 战略包 / 战略表

> 目的：改优先度机制时，不批量改战略内容；改战略时，不动优先度。  
> 同时控制 DSH 上下文：按领域拆文件、只读契约、默认值、schema 校验。

## 1. 三个契约

### 1.1 Facts（事实）

优先度和战略都只读 Facts，不互相读内部状态。

```js
{
  hp, maxHp, hunger, foodCount,
  hasWeapon, hasPickaxe, hasAxe,
  homeDistance, timePhase,
  hostileCount, ownerDistance,
  canFish, hasRod,
  // 可扩展；新字段必须有默认值
}
```

### 1.2 Strategy Profile（战略包内容）

```js
{
  schemaVersion: 1,
  id: 'food_security',
  kind: 'routine',            // routine | profile | emergency
  intents: ['food_low'],
  requires: ['hunger', 'foodCount'],
  steps: [...],               // 战术节点
  acceptance: 'hunger >= 16',
  fallback: {...},
  checkpoint: true,
  scoreHints: { base: 65, timePhase: { dusk: 5, night: 5 } },
  commitment: { minRunSeconds: 15, switchCost: 10, cooldownSeconds: 45 },
}
```

### 1.3 Candidate（优先度唯一输入）

```js
{
  id, intentKey, profileId,
  hard, hardPriority,
  eligible(facts),
  score(facts) -> {total, parts},
  minRunSeconds, switchCost, cooldownSeconds
}
```

优先度只认 Candidate；战略表只提供 Profile；`profileToCandidate()` 负责适配。

## 2. 修改影响范围

| 修改 | 只改 |
|---|---|
| 调优先级权重/阈值 | `scoreHints` / arbiter 配置 |
| 新增评分维度 | Facts + 默认处理；需要覆盖的 profile 才写 |
| 新增战略 | 新 profile 数据 + 测试 |
| 改战略步骤 | 该 profile 的实现文件 |
| 合并 intent | intent 映射表 |
| 改 Candidate 契约 | 升 `schemaVersion`，用默认值迁移 |

## 3. 模块化规则（控制 DSH 上下文）

```
src/
  contracts.mjs          # 三契约 + 适配器（稳定，少改）
  facts.mjs              # Facts 派生（稳定）
  arbiter.mjs            # 机制（稳定）
  intents.mjs            # intent 映射（小）
  strategies/
    survival.mjs         # 按领域拆
    food.mjs
    night.mjs
    storage.mjs
    index.mjs            # 注册表
  profiles/
    iron_age.mjs         # 长期战略表
    base.mjs
    index.mjs
```

规则：

1. 改一个领域只读该领域文件 + contracts；
2. 不在 `strategy.mjs` 大杂烩里继续堆；
3. 新字段必须有默认值，避免批量迁移；
4. 启动时校验 schema，坏数据直接报错；
5. 回放覆盖“候选生成/契约”关键路径。
