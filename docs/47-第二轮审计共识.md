# 47. 第二轮审计共识：目标架构可支撑范围与执行顺序

> 2026-11-10。基于第一轮审计 + 作者方质疑的第二轮独立评估结论。  
> 结论：**方向一致；"设计结构可支撑单同伴确定性多日多链"成立，但"策略/实现待补"；先修 resume 抖动，再做持久化/复核/方法回推。**

## 1. 已达成的共识

1. 当前实现不能支撑多日多链；
2. 四个断点成立：持久化、resume 前事实复核、wait、方法回推；
3. docs/44 的 ✅ 多数是“设计可”，不是“已实现”；
4. docs/45 的 80%/30% 无测试支撑，铁器端到端接近 0；
5. 不上 GOAP；HTN 方法表 + 有界回推是正确增量；
6. 完整 ResourceLedger 应砍，但需要**站点注册表 + 轻量 claim**；
7. DayAgenda 不新增独立层，用 profile aging + schedule 扩展；
8. wait 不需要独立事件调度器，用 milestone `waiting` 状态 + tick/条件检查，关键是让出动作槽、持久化、timeout/fallback；
9. 第一切片仍推荐 `iron_age`，但必须覆盖“重启续跑 + 跨夜等待”。

## 2. 修正的表述

- “设计已能支撑多日多链” → **“结构可支撑，策略待补”**；
- “ResourceLedger 全砍” → **站点注册表 + claim**：
  - `site{id,kind,pos,dim,verifiedAt,confidence,source}`
  - `claim{resourceKey,qty,holder,mode:use|consume|reserve,since,expiresAt}`
- “wait-until 独立机制” → **milestone waiting 状态**；
- “铁器实现 5%”分口径：
  - 端到端链路：接近 0（无 iron 配方/装配）；
  - 原语覆盖：约 15–20%（mine_nearby 可挖铁、smelt 可烧铁、craft 有部分能力）。

## 3. 仍存的分歧（已收敛）

- ResourceLedger：完整账本砍，但 site+claim 保留；
- 设计能力：只限“单同伴、确定性、可验收任务”；
- wait 机制：tick 条件即可，不新增调度器；
- 顺序：稳定性前移，先修 resume 抖动，再持久化。

## 4. 最终执行顺序（共识）

### P0-a 修 resume 抖动

- dispatch 立即 `slot_blocked` 也要计入 `st.slotBlocked/instinctBlocked`；
- 恢复前要求一次成功观测；
- resume 次数上限/升级；
- 目标：消除 17s 级 suspend→resume 循环。

### P0-b profile/milestone schema + DurableGoalStore

- 按 `worldId + companionId` 键；
- 原子写；
- 只存 milestone/checkpoint，不存 plan cursor；
- 验收：kill 进程/死亡后从 M2 继续。

### P0-c load 后事实复核

- 位置/背包/站点/时间任一不符 → replan，不硬跑。

### P1 方法表 + 有界回推

- `method{id,task,requires[],produces[],steps[],acceptance,fallback[],cost}`；
- depth ≤4、nodes ≤20；
- 缺前置递归子任务，父暂停；
- fallback 由 requires 选，不靠 onFail。

### P1 waiting milestone

- `status=waiting`，`wakeAt/condition` 持久化；
- 到点/条件满足重新评估；
- 让出动作槽，不轮询。

### P1 site registry + claim

- 工作台/炉/箱位置与最后校验；
- 关键消耗品预留，防被别的 milestone 烧/存。

### P2 profile progress + aging

- `lastProgressDay / starvedDays / progress7d`；
- 单活跃长期目标 + 每日至少 1 milestone 验收护栏；
- schedule 只扩 dayPart/work window，不加 DayAgenda。

## 5. 两夜验收（共识版）

固定测试世界：基地旁 32 格内 1 棵树、3 铁矿石、1 煤，平坦，夜间 1 僵尸；无 LLM；固定种子。

- D1：M1 石镐 → M2 熔炉（8 圆石）并放置；入夜 guard；N1 无死亡、不重复造炉。
- D2：M3 挖 3 粗铁；18:00 kill 进程重启，应加载 profile，复核熔炉站点后从 M2/M3 继续，不重做 M1；N2 存活。
- D3 晨：背包 3 raw_iron + 石镐；熔炉站点唯一有效；M1/M2/M3 done；death=0；resume 抖动 ≤2 次/分钟；持久化 JSON 重启前后一致。

## 6. 一句话

> **结构可支撑，但先修稳定性；再做持久化与事实复核；再用 HTN 方法表 + waiting + site/claim 支撑多日多链。**
