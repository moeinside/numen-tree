## 2. MVP 范围（只做这些）

### 目标

解决“丢芝麻捡西瓜”：砍树一半做饭、做饭一半回家、永远做不完。

### 统一候选仲裁

把现有 `src/arbiter.mjs` 从 `store_materials` 试点升级为**统一候选接口**：

```
候选 = {
  id, kind: 'need'|'strategy'|'utility',
  eligible(ctx),
  score(ctx),
  minRunSeconds,
  switchCost,
  hardPriority,   // 安全/紧急：可抢占
}
```

来源：

- needs 板：get_weapon / get_tools / food_low / night_safety / night_chase / stuck_escape；
- 战略包：secure_gear / night_hold / secure_food / prepare_for_night / light_base / escape_stuck…；
- 效用：store_materials。

### 仲裁规则

1. **硬安全带**：威胁、低血、被追、卡住等 `hardPriority` 直接抢占，不受迟滞限制；
2. **承诺**：当前候选至少跑 `minRunSeconds`，普通候选不能随意切；
3. **切换成本**：`newScore > currentScore + switchCost` 才换；
4. **迟滞**：`newScore > currentScore + margin` 才换；
5. **防饿死**：排队久了加分；
6. **决策点**：动作/战术边界、5s 兜底、重大状态变化，不是每 tick 重选。

### 必须有的可观测性

- `tree_status detail` / `arbiter` 查询：
  - 当前候选、分数、承诺剩余、最近切换原因；
  - 候选列表 top3；
- trace：`arbiter_choice`；
- 能统计：切换频率、任务完成率。

- 职业风格参数表；
- 语义匹配/LLM 实时改优先级；
- L4 项目/黑板调度。

﻿## 6. 与黑板/项目层的关系（架构补充）

**优先度系统 = 仲裁器（选谁做）；黑板 = 任务/项目状态库（有什么可做）。**

- 仲裁器保持相对独立：`arbiter.mjs` 只认 Candidate 接口，不直接读黑板/需求/战略内部状态。
- 黑板通过 **BlackboardProvider** 生成候选，而不是把项目状态塞进仲裁器。
- 候选来源统一为：
  - LocalNeedProvider（饥饿/安全/卡住）
  - StrategyProvider（secure_gear/night_hold/...）
  - UtilityProvider（store_materials 等）
  - BlackboardProvider（L4 项目包：分基地、农场、探索）
- 黑板候选字段（示例）：
  - project/package/deps/status
  - claim/lease（多同伴防重复）
  - progress/checkpoint
  - value/deadline/requiredCompanion
- 仲裁器生命周期钩子：
  - `onSelect` → 黑板 claim/lease
  - `onComplete` → 标记包完成
  - `onAbort` → 释放 claim，保留 checkpoint（被安全需求打断不算失败）
- 两层决策：
  - **本地仲裁**：每个同伴决定“现在做个人紧急需求/普通战略/黑板包”；
  - **黑板项目调度**：跨同伴的项目优先级、依赖、分工（后置）。
- 硬安全永远在本地抢占；黑板包被抢占时走 `onAbort`/resume，不丢进度。
- 初期单同伴：只做本地仲裁；BlackboardProvider 留接口，不实现黑板本体。
