# 82. Pilot 双轨参考运行：共识

> 2026-11-10。六位顾问质询 docs/81 后的 Lead 收敛。  
> 结论：**有条件共识；Track B 存在，但不是第二条主线，也不是“并行”驾驶。**

## 1. 共识

- Track A：树自己跑 Day1，唯一出线证据；
- Track B：LLM reference pilot，人工批准、只读观测、参考；
- **同世界/同同伴/同动作槽不能并行**：B 跑时树退出或只读挂起，不占槽；
- 优先**串行**：A 跑完 → 世界/树状态恢复并验证 → B 再跑；
- 若要并行，必须独立进程/独立世界/独立端口/独立状态目录，且接受 TPS 风险；
- B 不是“上限”也不是“基准”：有人工纠错，只是“参考示范”。

## 2. Track B 产物只允许三类

1. 缺失的谓词/前置条件；
2. 恢复点/失败分类；
3. 机制事实（路线/夜间/食物规则）。

禁止：

- 动作序列；
- 时序/阈值/优先级数值；
- 直接转策略/调参目标；
- 进树/学习/EWMA/验收/记忆。

## 3. 使用规则

- A 先跑；B 只由 A 的具体缺口触发；
- B 不设“达标”概念；
- B 失败不算树失败；A 通过不依赖 B；
- 每条设计候选必须绑定一条 A 的失败 trace 或负样本；
- 报告只判“树缺什么”，不判“树该多像 pilot”；
- B 产物进设计前，必须过“纯具身可触发”审查（L0/L1 能否自己触发）。

## 4. 运行/隔离

- 独立世界/同伴/places/goalstore/trace/端口；
- B 运行时树只读挂起或退出，不持动作槽；
- 观测台只读：轮询 `get_events`/status，不吃槽、不 scanWorld、不写 Facts；
- A/B 不共享世界基线；若串行，恢复后验证世界哈希与树侧状态；
- B 报告标 `mode=reference-pilot` + 人工纠错次数 + “不构成自主证据”。

## 5. 工程硬约束

- 进程/世界/同伴/目录四拆；
- 所有权 fencing（A/B 不能同时认为持有槽）；
- 外部 supervisor kill + 硬上限（步数/墙钟/成本取先到）；
- 人工批准粒度：每 N 步或每类不可逆动作，不只是 run 开始一次；
- 优雅停机 + settle + lockfix；不能硬杀。

## 6. MVP

只保留：

1. LLM 通过 MCP 单步操作；
2. 原始 JSONL 落盘；
3. 实时只读观测台；
4. 手动 stop + run manifest；
5. 人工逐步批准、硬上限、kill switch。

砍掉：

- segmenter/summarizer（摘要会变“参考结论”）；
- review pack 自动化；
- 自动长跑；
- cheat/scanWorld；
- 轨迹转策略/自动调参。

## 7. 顺序

1. 冻结 Track A 的 Day1 规格与审计拒绝规则；
2. 做 B 的最小 harness/观测台；
3. A 先跑；
4. B 仅按 A 缺口串行跑；
5. 产物只转谓词/入口/恢复规则；
6. 出现“树抄 pilot/注意力倒挂”即停 B 一轮。

## 8. 明确不能从 B 得出

- “树能自主生存”；
- “Day1 通过/P0 出线”；
- “缺的是能力而不是机制”；
- “人和 LLM 能做到 = 树的上限/基准”；
- “验证了无干预”（B 有人工纠错）。

## 9. 共识表

| 角色 | 结论 | 关键条件 |
|---|---|---|
| 总控 | 有条件同意 | B 只是探针，不是第二主线；A 唯一证据 |
| 产品经理 | **有条件批准并行** | A 规格/审计先冻结；B 不占关键路径；MVP 四件 |
| 行为学家 | 有条件同意 | B 是假设生成器，不抄动作/阈值 |
| MC 专家 | 有条件同意 | 禁止同世界同同伴并行；串行优先；B 不占槽 |
| 点子王 | 有条件同意 | 四拆 + fencing + 外部 kill + 三重上限 |
| 玩家代表 | 有条件同意 | B 不是上限/进展；标注纠错；只进附录 |

## 10. 一句话

> **A 是唯一证据，B 只是探针；同槽不并行，B 不占 A 的世界/时间；pilot 只能帮我们找缺口，不能替我们证明能力。**
