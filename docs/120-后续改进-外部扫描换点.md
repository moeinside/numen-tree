## 2. 先决条件

### 2.1 外部扫描能力

当前触手只有：

```text
self feet/head/above/below
terrain.dirs 4 方向 ×2 格 standable
```

**没有任意格 3×3×3 查询**。  
要“不占 Lua 槽”地外部扫，必须先扩展触手：

```text
给定 center + radius（≤2）
返回每格 block / air / solid / loaded
```

要求：

```text
只读
只读已加载区块
范围 ≤3×3×3
带 observedAt / source
```

### 2.2 no_path 分类

换点前必须先分：

```text
水/岩浆
门/活板门
垂直落差 >1
未加载区块
移动实体
玩家方块同意被拒
目标在方块内
真·目标格不合法且环境正常
```

前七类不换点，按类处理。

## 3. 安全版流程

```text
1. move_to(target) 失败
2. 分类 no_path
3. 水/门/落差/未加载/移动实体/refused → 不换点
4. 剩余：派发边界外部扫 ≤3 候选
5. 每个候选：
   standable
   → route.plan 可达
   → 同一交互面 / LOS（如果目标可交互）
6. 每候选 1 次，总 move ≤2
7. 全败 → no_path_after_scan
   → 回上层换策略，本层不再重试
8. 全程留痕：原 target / 候选 / 每步失败 / final
```

## 4. 禁止

```text
扫到就 move
每 tick 扫描
候选无限扩圈
同一目标 move_to >3 次
no_path_after_scan 后本层继续重试
把候选到达记成原目标 success
换点后交互反复失败且不 abandon
```

## 5. 验收

```text
同一 goal 内 move_to ≤3
no_path_after_scan 后本层零重试
候选必须同时通过 standable + route + 交互面
换点 trace 完整可审计
```

判负：

```text
换点成功但原目标交互仍失败且无 abandon
或同一目标重试超过预算
```

## 6. 阶段建议

```text
P0：不动
P1/M5：触手 area scan
P1/M6：no_path 分类
P1/M7：候选 + route + 交互面 + 预算
```
