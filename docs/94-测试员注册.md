# 94. 测试员（Tester）注册

> 2026-11-10。正式名称：**测试员（Tester）**。  
> 旧称：开发工具 / 试驾员 / pilot。以后项目内统一叫“测试员”。

## 1. 定位

测试员是**人类授权启动**的 LLM 接管测试工具：

```text
人类给测试目标
→ 测试员用原生 Numen MCP 接管同伴
→ 自主行动
→ 留下 session / GM / 触手数据
→ Analyst 整理成顾问团可读文件
```

测试员**不是**树、不是验收器、不是学习样本生成器。  
它的日志只用于观察和提出问题，不自动改树。

> 对外表述固定一句：**“这是测试员在驾驶，不是树在驾驶。”**

## 2. 当前能力

- 原生 `mcp__numen__*` 工具接管，不走 shell bridge；
- 一次只操作一个同伴；
- 硬截止由外部执行；
- 外部监督员可做最小 GM 干预并标记 assisted；
- 触手只读 8769 可采集世界信息；
- session、GM、触手使用记录归档；
- 独立 Analyst 生成 `ADVISOR-BRIEF.md`。

## 3. 入口

- DSH `preset_dispatch`，preset id `numen`；
- 依赖本机插件 `DSH-Preset-Dispatch`（已做 rc.2 兼容补丁）；
- GM 通道 8770 仅监督员使用，测试员提示词中不出现；
- 触手 8769 只读。

## 4. 启动规则（硬）

```text
测试员的启动必须由用户人工许可。
没有“许可启动”这句话，任何 Day1/长测都不得开始。
```

Lead 可以准备 GOAL、预检环境、写数据目录，但不能自行启动。

## 5. 数据产物

```text
runs/<runId>/
  child-session.jsonl
  child-session.v4.jsonl.zstd
  gm.jsonl
  tentacle_use.jsonl
  manifest.json
archive/<runId>/
  ADVISOR-BRIEF.md
```

## 6. 边界

- 测试员只做游戏内自主行动；不写项目文件、不改树；
- GM 只由外部监督员执行；
- 测试员不知道 GM、不知道开发团队对 numen 行为的结论；
- 不把 assisted 跑当自主证据；
- 不自动把测试结果写回树设计，必须由开发团队/顾问团判断。

## 7. 当前状态

```text
原生 MCP 接管：已验证
5 分钟启动测试：已验证会自主启动（侦察型）
Day1：未启动，等待用户人工许可
```

## 8. 顾问团边界确认（2026-11-10）

- 测试员数据属于**观察域**，与 Track B 同级，不进入 Track A 证据、学习正样本、回归基线；
- 测试员会占用 `numen` 单动作槽并改变同伴行为轨迹，session 只能作机制/现象参考；
- 若与 Track A 混跑，必须标记 `mode=tester`，并隔离世界/进程/状态目录；
- 设计变更仍必须绑定一条**未 assisted 的 Track A 失败 trace**；
- 同一时刻只允许一个持有 `numen` MCP 的角色（树或测试员二选一）；
- 启动唯一条件：用户人工许可。

## 9. Day1 证据包（顾问引用门槛）

若测试员 Day1 结果要交给顾问团评估，至少提供：

- `manifest.json`：`mode=tester`、`assisted` 标记；
- `gm.jsonl`：是否零记录；有记录则标 assisted；
- 触手轮询记录：是否全程未占用单动作槽；
- `child-session.jsonl`：测试员驾驶轨迹；
- 明确声明：**这是测试员在驾驶，不是树在驾驶**；不是 Tree Track A 能力证据。
