# 39. 调度器评估：从人类行为模型看优先度系统

> 2026-11-09。前提：原子/战术/战略包不改，只评估优先度调度器。

## 1. 现在的调度器

```
需求阈值 → 优先级 → 单意图 + 切换成本 + 硬安全 → 执行
```

优点：

- 不再多目标乱排队；
- 有硬安全和承诺；
- 有意图归并。

问题：

- 优先级是**静态/手写**的，缺少连续压力；
- 只有“超过阈值”才反应，没有**预期/提前量**；
- 没有**满足后的饱腹/惯性**，容易反复触发；
- 切换只看分数和固定成本，没有**自然断点**；
- 没有**情绪/疲劳/唤醒度**；
- 没有**习惯/熟练度**；
- 没有**长期志向**与短期冲动的分层（profile 还没有）；
- 行为看起来“机械”，不像人“有状态地活着”。

## 2. 人类行为循环（简化）

1. **内驱力/稳态**：饥饿、疲劳、安全、社交、好奇持续积累；
2. **注意/显著性**：威胁抢占注意，其他目标进入候选；
3. **评估**：收益、成本、风险、时间、概率；
4. **选择**：选当前行动；
5. **承诺**：开始后倾向完成，除非硬中断；
6. **满足/饱腹**：需求被满足后压力清零，并短暂抑制；
7. **预期/计划**：预判天黑、饥饿、危险；
8. **情绪调制**：压力/恐惧/疲劳改变权重与注意力；
9. **习惯**：重复行为成本降低，成为默认；
10. **元认知**：不确定时停下来、观察、求助。

## 3. 映射到我们的系统

| 人类机制 | 系统组件 | 现状 |
|---|---|---|
| 内驱力/压力池 | needs + drive pressure | 只有阈值 |
| 显著性/注意 | 硬安全 + score | 有硬安全，无注意机制 |
| 收益/成本/风险 | candidate score | 部分手写 |
| 承诺 | minRunSeconds/switchCost | 有 |
| 满足/饱腹 | 需求 done + cooldown | 有但零散 |
| 预期 | 时间阶段/提前准备 | 有 timePhase，但未预测 |
| 情绪 | 全局权重调制 | 无 |
| 习惯 | 熟练度/默认行为 | 无 |
| 元认知 | 不确定性/求助 | 有 help report，未系统化 |
| 长期志向 | profile | 待做 |

## 4. 压力系统是否是必要组件？

**是，但不是全部。** 只有压力池会变成“数值越滚越大”，必须配对：

- 满足 → 压力清零；
- 饱腹/不应期 → 短暂抑制；
- 预期 → 在阈值前提前行动；
- 成本/风险 → 压过冲动；
- 承诺/断点 → 不中途乱切。

## 5. 建议的评分模型

```
urgency_i = pressure_i × imminence_i
value_i   = expected_benefit_i - effort_i - risk_i
score_i   = w_drive*urgency
          + w_value*value
          + w_commit*commitment
          + w_habit*habit
          - switch_cost
```

选择规则：

1. 硬安全/反射覆盖；
2. 只在**动作/战术断点**切换；
3. 新候选需超过当前 + 迟滞 + 切换成本；
4. 压力清零 + 饱腹抑制；
5. 预期（天黑/饥饿）提前提高对应压力；
6. 情绪/疲劳作为全局权重调制，不是另一个决策者。

## 6. 最优解的务实版本

不是 POMDP/完整认知架构，而是：

```
稳态压力池
  + 显著性/硬安全
  + 收益-成本评估
  + 承诺/断点
  + 预测（时间/需求）
  + 情绪权重
  + profile 长期目标
```

这叫**分层稳态效用调度器**（homeostatic utility arbiter）。

## 7. 分阶段

### P1 压力池 MVP

- 饥饿、疲劳/夜晚、安全、资源 4 个；
- 按游戏时间累积；
- 满足清零 + 饱腹抑制；
- 接入候选分数。

### P2 断点与预期

- 只在战术/动作边界切换；
- 天黑/饥饿预测提前；
- 紧急中断仍可随时。

### P3 情绪/疲劳

- 低血/被围 → 安全权重上升；
- 疲劳 → 长任务成本上升；
- 压力 → 探索/社交权重下降。

### P4 习惯与 profile

- 重复成功 routine 降低成本；
- profile/milestone 长期目标；
- 人格权重预设。

## 8. 验收

- 任务切换频率下降；
- 需求不再“到阈值才反应”，而是提前准备；
- 吃饱后不会立刻又找食物；
- 被打断后能回到原任务；
- 行为看起来有“状态”，不是每 tick 重算。

## 9. 结论

当前调度器是**有承诺的优先级队列**，还不是**稳态行为系统**。  
压力系统有必要，但要和满足、饱腹、预测、断点、成本一起做；单独加压力池会制造新的抖动。

一句话：

> **人类行为不是“需求→应答”，而是“压力累积→注意→评估→承诺→满足/预测”的循环；调度器应实现这个循环的工程简化版。**
