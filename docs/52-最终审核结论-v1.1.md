# 52. 最终审核结论：架构 v1.1（有条件批准）

> 2026-11-10。点子王（架构）与产品经理（验收）分别审核 docs/47–51 后的最终结论。  
> 双方均“有条件批准”；条件已并入 v1.1。

## 1. 最终结论

**批准开工，但先完成两个阻塞项：**

1. `Profile` 命名契约；
2. 落盘 vs 世界回档的 epoch/快照证据。

P0 范围不变：**P0-a + P0-b 都过才出线。**

## 2. 架构师条件

### A. 消除 Profile 命名冲突

- 现有 `src/profiles.mjs` 是“策略→候选”的运行时 routine profile；
- 架构 v1 的 Profile 是长期目标；
- 动工前将长期目标改名为 **`GoalProfile`**；
- `DurableGoalStore` 只管理 `GoalProfile`；
- 代码/日志/快照中禁止混称 `profile`。

### B. LLM 的 `methodHints` 在 P2 前禁止被消费

- `AdviceProposal` 可保留字段；
- P2 前 Planner 不得读取；
- 必须是硬性禁止（代码级），不是约定；
- 防止自然语言重新污染确定性计划层。

### C. 时间/世界同步与回档

- 落盘需要 `worldId` + **`worldEpoch`/快照序号**；
- 不能用 wall clock 代表游戏时间；
- 谓词 evidence 带 `snapshotSeq/gameTime`；
- 加载时如果“落盘比世界新”（玩家回档/切存档），直接判负/作废重规划；
- 审计发现 epoch 不一致 → 负；不允许“未知”。
- 单条 reservation 到期绑**游戏内日界**；进程重启作废重建。

### D. 语义接口边界

- `SemanticResolver` 输出的 `requires` 必须是**封闭枚举**；
- `confidence` 不得流入 Planner；
- `GoalIngress → validator → Arbiter` 这条链保持干净；
- `methodHints` 是唯一后门，P2 前封死。

## 3. 产品经理条件

### A. kill 点固定

- kill 点：**checkpoint + trace 已 flush 后、下一动作 begin 前**；
- 不得在日志未落盘时 kill，否则“死亡=0 / replay=0”可能只是丢日志的假象；
- 心跳缺口超阈值 → 一律按可疑/死亡计，不留“未知”。

### B. 冻结对象写全

开跑前冻结：

- 夹具版本；
- 审计脚本；
- A/C/D 阈值；
- **分母与采样窗口**；
- kill 点位置；
- P1 的 5 点 × 3 种子预算上限。

不兼容直接拒绝启动，不静默降级。

### C. P0 范围

- 一周只够 P0-a；
- P0-b 是从零新建，不是接线；
- 固定夹具（1 树/3 铁/1 煤/1 僵尸）本身是实打实工作量；
- 语义/LLM 只留字段，不进 P0 验收：
  - schema 字段存在；
  - `source` 默认 player/auto；
  - 低置信/未知意图不硬执行；
  - P0 运行记录不得出现 `source=llm`。

### D. 验收措辞

- P0 出线只证明“该固定夹具上可过”，不证明泛化；
- 报告必须原话写明；
- P1 第一件事是留出种子 + 扰动复验。

## 4. 最终 v1.1 架构

```
Reflex/本能
  ↓
GoalIngress / SemanticResolver（封闭枚举 requires；confidence 不进 Planner）
  ↓
Arbiter（承诺/迟滞/切换成本）
  ↓
GoalProfile（长期目标，非旧 profiles.mjs）
  ↓
Milestone（谓词 + evidence + lastProgressDay）
  ↓
SOP + 有界补缺 depth≤2
  ↓
Executor（战术/原子，settle）
  ↑
Facts（gameTime/snapshotSeq）/ Readiness / SiteRegistry（候选）/
reservation（游戏日界到期，重启作废）
```

附加：

- `DurableGoalStore` 只存 `GoalProfile` + milestone + checkpoint + intent label；
- 原子写、重启幂等、replay 副作用=0；
- worldEpoch 反向校验（回档负）；
- LLM 只读 context + propose；`methodHints` P2 前禁用；
- 审计先自证判负，再改行为。

## 5. 一句话

> **架构 v1.1 有条件批准：先改 Profile 命名与 epoch 契约，再冻结验收；P0-a 一周，P0-b 从零；语义/LLM 只留字段，P2 前不通计划层。**
