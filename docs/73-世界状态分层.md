# 73. 世界状态分层：GM 真相 vs 同伴已知

> 2026-11-10 玩家的澄清：作弊扫描是给**树工具**做“世界状态记忆”的，不是给同伴做具身感知。  
> 开放世界高频变化（箱子、地貌），单纯记录表不够。  
> 目标：允许树掌握全局，但不让同伴变成全知。

## 1. 问题重述

之前把“禁止作弊扫描”当成一条死红线，可能过头了：

- 动作时的感知必须具身（触手/numen 现场观测）；
- 但树作为“世界模型/记忆/规划后端”，需要稳定、全局、可查询的世界状态；
- 仅靠静态 JSON 记录，无法跟上箱子内容、地形变化、资源消耗；
- 所以需要一种**树级世界状态服务**。

关键不是“能不能扫”，而是：

> **树知道的世界真相，不能直接变成同伴行动的前提。**

## 2. 两层分离

```text
WorldTruth（树级，GM/扫描）
  - 周期快照 + 事件/diff + 版本号
  - 树内部规划、记忆、审计可用
  - 不写入 CompanionFacts
  - 不能直接满足动作前置

CompanionKnowledge（具身，同伴）
  - 触手/numen 现场观测
  - 三态 Fact（known/unknown/stale）
  - 只有它能满足动作前置
  - 动作目标必须已被同伴发现/验证
```

行动链：

```
WorldTruth：建议“去哪探索/可能有什么”
  ↓
Planner：生成“探索/验证”子目标
  ↓
Companion 现场观测 → 发现/确认
  ↓
CompanionKnowledge 变为 known
  ↓
Executor 才允许动作
```

## 3. 允许/禁止

### 允许 WorldTruth

- 维护全局地图/资源/容器/地貌的**记忆与版本**；
- 给 Planner 提供“探索方向/候选区域/异常变化”；
- 给审计提供地面真值；
- 给多同伴未来共享世界状态；
- 检测“记忆与世界不一致”，触发重探。

### 禁止

- 直接生成“去拿未发现的箱子/资源”的目标；
- 直接满足动作前置；
- 把 WorldTruth 写入 CompanionFacts；
- 让同伴隔墙/远程操作；
- 用 WorldTruth 替代现场校验。

### 灰区（需定义）

- “知道某区域可能有树/水/怪” → 是否允许 Planner 选择探索方向？
- 知道箱子内容 → 是否允许规划“去那个箱子”，但必须先“发现/打开”？
- 知道怪物位置 → 是否允许绕行，还是必须同伴看见才反应？

## 4. 动态世界怎么跟

单次黎明扫描不够：

- 周期快照（低频）；
- 事件驱动：容器开关、方块变化、区块加载；
- diff/版本号；
- 惰性刷新：靠近/使用时重新校验；
- TTL/置信度；
- 不能保证实时，必须承认快照会过期。

## 5. 需要讨论

1. 两层分离是否成立？会不会只是“把作弊藏到树里”？
2. Planner 可以用 WorldTruth 到什么程度：探索方向？候选资源？容器内容？怪物位置？
3. 动作前置如何强制只认 CompanionKnowledge？
4. 动态世界用快照+事件+diff 是否够；还是需要实时查询？
5. P0 是否允许带 WorldTruth 跑？还是只测试 oracle？验收如何防泄漏？
6. 对多同伴：共享 WorldTruth 是不是合理基础？
7. 北极星不变量 8 需要怎么改写，才不变成“口头禁止、实际全知”？

## 6. 初步建议

- 保留“动作前置只认具身事实”硬线；
- 允许树级 WorldTruth 作为**记忆/规划/审计**；
- 所有 WorldTruth 派生目标必须是“探索/验证”类，不能是“直接获取”；
- P0 第一版可以**默认关闭 WorldTruth**，先跑纯具身；WorldTruth 作为独立开关和后续能力；
- 不让它成为 Day1 通过的理由。
