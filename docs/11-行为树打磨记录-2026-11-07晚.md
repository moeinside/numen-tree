## 1. 改了什么（按设计边界，只加规则不改边界）

### 1.1 仲裁器：从"两三条 if"变成**有序规则表**（`src/lane.mjs` `#arbitrate`）

规则从上往下，第一条成立的胜出；命中的规则和理由写进 trace（`auto_action` 的括号里），
每一件事为什么做都可复查。当前顺序：

| # | 规则 | 条件 | 动作 |
|---|---|---|---|
| 1 | 血太少 | `hp <= retreatHp(8)` | `retreat` |
| 1.5 | 近处有敌 + 血不满 | 敌对 ≤ `dangerRange(8)` 且 `hp% <= panicHp(65)` | `retreat` |
| 1.6 | 天黑 + 有敌 + 血不满 | `dark && hostile>0 && hp% < 80` | `retreat`（活着比找到食物重要） |
| 2 | 饿了有吃的 | `hunger <= eatHunger(6)` 且背包有食物 | `eat`（吃饱为止，最多 4 件） |
| 3 | 饿了没吃的、附近有猎物 | `hunger <= forageHunger(12)` 且 `animalCount>0` 且环境平静 | `forage`（打猎取肉） |
| 4 | 饿了没吃的、附近没猎物 | 同上 + 没猎物 + 夜里有血才许出门 | `seek_food`（搜箱子/探索） |
| 5 | 饿且没吃的太久 | 持续 `starvingEscalateSeconds(180)` | 上报 `starving` + **停手等大脑** |
| 6 | 模式：combat | 血 > `attackHp(60%)` 且有武器且没被围 | `fight_safe` |
| 6' | 模式：combat 撤退 | `hp% <= fleeHp(40%)` / 被围 `> maxTargets(2)` / 没武器且敌人近 | `retreat` |
| 7 | 模式：production | 原有轮换 + 连续失败 4 次出去探 | `dig_nearby` / `explore` |

要点：
- **"报了 = 已经停手等你"**：上报 starving 后 `survivalHaltedUntil` 停掉自动觅食 240 秒；但**吃永远不停**（包里有吃的就吃，大脑投放/自己捡到都算恢复）。
- **自己还能处理的不报**：自动规则失败只在 trace 留痕；连续失败 `escalateAfterAutoFails(3)` 次才升成一次规则级求助。大脑下的目标失败仍然必报。
- 动作结束后**立刻强制重新观测**再仲裁，避免拿动作前的旧数据再派一遍同样的活（实测踩过）。

### 1.2 感知扩展（`OBSERVE_LUA`，仍是"一次只读观测"）

新增字段：`food / food_kinds`（背包食物总数）、`weapon / weapon_score / held`（武器 + 手持物，按木1石2铁3金1钻4下界合金5 记分）、
`animal_n / animal_d / animal_t`（32 格内可猎杀的被动生物：牛/猪/羊/鸡/兔）、`dark`（`world.is_dark_outside`）。

> 实测确认：`scan.entities` 过滤名只有 `hostile/passive/player/item/all`；按 `e.type` 在 Lua 里二次过滤。
> `status.self().hands.mainhand` 能拿到手持物（空手是 nil）。详见 `10-numen-Lua-API速查.md`。

### 1.3 技能卡（`src/skills/`）

| 技能 | 变化 |
|---|---|
| `eat` | 食物表扩到熟肉/主食/生肉/腐肉四档，按性价比挑；一次最多吃 4 件直到饱 |
| `forage`（新） | 找被动生物 → `fight.attack` → 走到尸体 → **`work.collect()`（掉落不会自动捡）** → 看背包肉量是否增加；没有猎物报 `not_found` |
| `seek_food`（新） | 扫 chest/barrel → 走过去开箱拿食物 → 没箱子就分小段探索（撞生物群系） |
| `fight_safe`（新） | 每刀后复检血量/敌人数，触发撤退条件立刻 `move.flee`，而不是硬打到死 |
| `go_to/dig_nearby/explore/follow_owner/idle` | 单次动作预算收紧到 ≤200 秒；`explore` 单次最多 150 秒 |

### 1.4 状态可见性（`src/mcpserver.mjs`、`src/cli.mjs`）

- `tree_status` 现在是**可解析 JSON 文本**：`{now, inboxSeq, companions[{summary, progress{current_skill, current_goal_id, running_seconds, budget_seconds, last_action, pending_goals[waited_seconds], slot_blocked_seconds}, foodCount, weapon, animalCount, goals[...]}]}`。
- `summary` 是一句人话：`tyrander 正在 seek_food（已 42 秒），上一步 forage 成功，饥饿 5（食物 0 份），武器 无，模式 survival`。
- 超过技能自报预算会直接标 `⚠️ 已超自报预算`，不再"看起来像卡住"。
- `node src/cli.mjs status` 同步显示这些（等待秒数从 8767 的 tree_status 取，MCP 不通时本地自算）。

### 1.5 运行 robustness

- **`numen.mjs`：lua 调用永不重试、永不因超时重连。** 超时只返回 `kind='timeout'` 交给下一轮观测。之前超时→重连→重发→会话重建→僵尸锁的链条被切断。
- **新增 `control --op exit`**：先停所有通道、等在途动作自然结束再退出进程（drain 等待 240 秒，≥ 最长技能预算；替代 taskkill，避免把在途 lua 留在游戏里）。
- **新增 `control --op reload-skills`**：改完技能卡热重载，不用重启树进程。
- 高频事件（reflex 之类）做了去重（`loop.eventDedupeSeconds`），收件箱/trace 不再被刷屏。
- **牵引绳失败退避**：回主人走不过去时，间隔 15→30→60→120 秒指数拉长；连续 3 次上报一次 `stuck` 并停手 180 秒（实测：21:33 触发，不再每 15 秒刷一条 skill_failed）。

### 1.6 地点簿（新需求，2026-11-07 晚加）

用户需求：*"需要一个记录地点的功能。比如死亡的地点、基地的地点、我的地点、或者其他什么的地点。这个地点应该主要由树工具记录，但 LLM 这边通过模糊的意思也要能传导到 mcp 去执行。"*

| 层 | 实现 |
|---|---|
| 存储 | 项目根 `places.json`（`{version,seq,places[]}`），原子写、坏文件降级空簿、上限 500 条（非 base 先删） |
| 树自动记 | 死亡事件 → `lane.mjs` 自动 `record` 一条 `kind=death`（坐标取最后一次观测，note 注明可能有偏差） |
| LLM 工具 | 第 9 个 MCP 工具 `tree_place`：`record` / `list` / `find` / `forget`；`pos` 支持 `here`（同伴当前位置）/`owner`（主人当前位置）/`{x,y,z}`；`kind` 缺省按名字推断 |
| 模糊解析 | `src/places.mjs`：精确 id/名称 → 时间词（上次/最近）→ 中英别名（家/基地/home→base、死/坟→death、主人→owner）→ 名称/备注子串；返回 `why`/`distance`/`alternatives` |
| 实时位置 | 查 "主人/我的位置/你在哪" 时直接返回主人实时坐标（`live:true`），不写簿 |
| CLI | `node src/cli.mjs place list|find|record|forget`（走控制 API `/places`、`/place`） |

边界：地点簿**只记录与解析，不做价值判断**；"带我去某处"仍由大脑 `find` 拿坐标 → `tree_goal go_to` 两步完成。

## 3. 新踩的坑（比 09 那份更狠，务必先看）

| 坑 | 现象 | 结论/对策 |
|---|---|---|
| **僵尸锁：谁留的、补丁为什么没拦住** | 2026-11-07 22:22 复查：`numenlockfix` 在 mods 里、日志有加载记录，但**只在服务器启动时清表**（为"切存档"设计）；今晚的锁是 ①我 taskkill 树进程时正在飞的一次只读观测 ②同伴死亡打断在途调用（`halt DEATH ... abandoned calls=1`）——都在同一个服务器会话内，补丁不触发 | 补丁升级 v2：**死亡时定向清该 UUID + `/numenlockfix` 手动清全部**；仍需重启游戏加载。根本纪律不变：树进程用 `control --op exit`，永不中断在途调用 |
| **地点簿死亡点** | 每次死亡都记一条，越积越多 | 改为**每个同伴只保留最近一次**（记录新死亡点时自动删掉该同伴更早的 death 条目） |
| **单次程序 200 次 Lua API 调用上限** | `The script stopped at line 45 (numen.status.world) after N calls: it reached the limit of 200 calls per run` | 热循环里不能反复调 `numen.*`；预算用"固定次数的小段循环"表达，不要用墙钟 |
| **`task.timer` 触发的是 URGENT 事件，会打断当前程序** | `an urgent timer event arrived. Nothing after that ran.` | **不要用 timer 做进度上报**。长任务进度靠 `tree_status` 的"已运行 N 秒/自报预算"，以及 `numen.task.status()`（只读 lua） |
| **僵尸锁的真凶** | 21:06:28 那次锁：最后一次 `[numen-program]` 是 21:00:41（6 分钟前就结束了），锁却从 21:06:28 开始 —— 是我用 `taskkill` 杀树进程时正好赶上一次**在途只读观测**。21:07/21:08 两次死亡日志都是 `halt DEATH (abandoned calls=0)`，**死亡本身不留锁** | ① 退出树进程一律 `control --op exit`；② 它的 drain 等待必须 **≥ 最长的技能预算**（240s），否则退到一半强杀同样留锁；③ 真被锁了：**删掉重建同伴（MCP `delete_companion` + `create_companion`）就能清，实测两次成功、不用重启游戏**；退到主菜单**不能**清锁，彻底重启游戏能清 |
| **URGENT 事件会打断只读观测** | `observe_bad_shape error: ... an urgent task_finished event arrived. Nothing after that ran.` | 观测不是"绝对安全"的原子操作，偶尔被紧急事件打断是正常的；下一 tick 会重试。树干只记一条 warn，不重派动作 |
| **`seek_food` 可能返回 detached** | 主人在游戏里说话会打断程序：`your owner spoke; t97 keeps running`，`move.go` 后台继续跑 | 这是 mod 设计（抢占 = 派新任务），树按 `detached` 记账、等 `task_finished` 收尾即可 |
| 服务端脚本 continue 时仍留程序 | `a program is already running...` 出现在动作之后 | 树会自动降频观测并上报；不要手动 kill 树进程（用 `control --op exit`） |
| `move.explore` 必须给 `until_` | 不给时每跳后调用 nil 报错，且被 pcall 吞掉看起来"瞬间成功" | 技能里显式传 `until_ = function() return nil end` |
| 夜间乱跑 | 21:01 tyrander 在夜里探索时被怪打死（hp 10、无武器、hunger 9） | 新增 1.6/4 的夜间守卫；血的教训 |
