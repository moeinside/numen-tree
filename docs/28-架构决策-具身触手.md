# 28. 架构决策：具身触手 / 兼容层 / lockfix

> 状态：**已记录，暂不实现兼容层**。主功能（生存/食物/照明/建造）完成后再启动兼容 mod。

## 1. 三个 mod 的分工

```
numen_tree_tentacle          核心触手：具身感知、事件、只读元数据、SPI
numen_tree_compatibility     可选兼容层：第三方 mod 适配器（延后）
numenlockfix                 独立医生：numen 锁/内置脑/技术恢复
```

依赖方向（单向，不允许反向）：

```
compat ──optional──> tentacle 核心 API
tentacle ──不依赖──> compat / 任何第三方 mod
lockfix  ──独立──> 谁都不依赖
```

**核心触手永远不知道 compat 存在**；删掉 compat 不影响基础感知。

**命名（英文）**：modId `numen_tree_compatibility`，显示名 **Numen Tree Compatibility**，jar `numen-tree-compatibility-0.1.0.jar`。

## 2. 核心触手（tentacle）的定位

- 树的“触手/感官”：只从游戏吸取信息给树；
- **具身感知**：不是上帝视角；FOV、遮挡、距离、光照、听觉、短期记忆；
- 只读：不移动、不战斗、不合成、不修改世界；
- 本地接口：`127.0.0.1`，只给树，不直接暴露给 LLM；
- 不注册 MCP 工具；工具面仍归树；
- 通用优先：所有方块/实体/物品用 namespaced id + tags + 通用属性，避免写死原版。

## 3. 兼容层（compat）决策

- **暂缓到主功能完成后**；
- 单独 mod，可选安装；
- 只做 `extras` 丰富，不改核心感知语义；
- 每个适配器独立 try/catch + 熔断；失败只禁用适配器；
- 第三方 mod 依赖全部 optional，缺 mod 时 compat 仍可加载；
- 不把原始 NBT 直接交给树/LLM。

## 4. 没有 compat 时的“基础具身同伴”

结论：**仍然能有一个可用的基础同伴**，但能力边界要说清：

| 场景 | 没有 compat 时 |
|---|---|
| 原版方块/实体/物品/配方 | 正常工作 |
| 模组方块/物品 | 能看到 namespaced id、tags、光照、碰撞等通用属性；可绕开/采集/存放 |
| 模组食物/工具/机器 | 树没有语义适配，可能不会“正确使用” |
| 模组配方 | 服务端 RecipeManager 可读；但树的静态配方表可能不认识 |
| 模组特殊机制（魔法/科技/多同伴） | 不认识，按普通方块/实体处理，不崩即可 |

即：**基础同伴 = 能活、能走、能砍、能打、能存、能建原版级东西；不理解模组语义，但不被模组内容搞崩。**

## 5. 为什么“具身同伴不太需要兼容”

- 具身 AI 的核心循环（生存/采集/合成/战斗/照明/存储）大部分是原版机制；
- 模组内容通常属于“扩展玩法”，不是基础生存必需；
- 过早做兼容会拖慢主功能，而且适配器会随模组版本腐烂。

但其他玩家确实大量使用模组，所以：

- 核心触手从第一天就用**通用注册表 + namespaced id + tags**，不要写死原版；
- 等主功能稳定后，再把高频模组做成 compat 适配器；
- 不兼容时保证“降级但不崩”。

## 6. 当前优先级

1. 生存闭环（装备/食物/照明/过夜）
2. 合成/工作台/存储
3. 具身触手核心（感知/事件/诊断）
4. 兼容层（延后）

## 7. 非目标（明确）

- 不在 mod 里做行为决策；
- 不让 compat 影响核心感知；
- 不为了兼容而提前抽象过度；
- 不把原始世界数据灌给 LLM。

## 触手信息边界（硬规矩，2026-11-09）

**触手只允许模拟“真人玩家能获得的信息”，禁止作弊级信息获取。**

### 允许

- 自身身体：HP、饥饿、背包、手持、护甲、位置、朝向、光照、状态效果；
- 自身感知范围：视锥内、无遮挡、距离内的实体；
- 视线内/脚下的地形、方块、水面/冰面；
- 曾经看过并记住的地点/地标（必须带“记忆”来源，不是实时透视）；
- 已打开容器/界面的内容（通过正常交互打开）。

### 禁止

- 未访问/非基地的未打开箱子/容器内容（基地内已登记容器按“记忆”处理）；
- 隔墙实体、超出视距/视锥的实体精确位置；
- 穿墙探测矿脉、洞穴、结构、地下水；
- 其他玩家/同伴的背包、末影箱、隐藏数据；
- 世界种子、结构坐标、刷怪计时、AI 内部状态等“系统信息”；
- 全图/全服扫描；任何“上帝视角”。

### 输出纪律

- 每条观测带 `source: body | sight | hearing | memory`、`observed_at`、`confidence`；
- 未观测到的信息输出“未知/缺失”，不要输出“没有”；
- 树只使用带来源/时效的事实；过期事实降级；
- LLM 永远看不到触手原始数据，只看到树压缩后的事实简报。

### 当前 v0.3 待补

- `landmarks` 目前可能未完全按 FOV/LOS 过滤 → 需要补视线/距离；
- `water` 扫描可能穿墙/穿地层 → 需要只统计可见水面/岸边；
- 尚无 hearing/memory 来源标记；
- 若 v0.4 加 `body`（背包/手持），只允许读**自己**，且禁止读未打开容器。

## 信息边界细化：允许“基地记忆”，禁止“全知实时”

> 2026-11-09 补充。触手规矩是“尽量模拟真人”，不是“技术上绝对不读”。

### 三类信息

| 类别 | 例子 | 处理 |
|---|---|---|
| **绿色：本体/实时感知** | 自己背包/手持、视锥内实体、脚下地形 | 允许，标 `body/sight` |
| **黄色：基地记忆** | 基地里自己用过/见过的箱子内容、基地地标 | 允许，标 `memory`，带 `last_seen`，可过期 |
| **红色：作弊级信息** | 隔墙敌人、矿脉透视、未访问结构箱子、其他玩家背包、远程容器 | 禁止 |

### 基地记忆规则

- 只限**自己的基地/据点**（家锚点附近）内的容器；
- 只限**打开过或近距离确认并登记过**的容器，不是全图任意箱子；
- 内容必须标 `source: memory` + `last_seen`，并允许过期；
- **使用前要验证**：记忆说箱子里有食物，仍要走过去打开/取用，不能远程拿；
- 记忆过期/不一致时以现场为准，更新记忆；
- 不把基地记忆用于战斗/威胁判断。

### 表现层原则

- 玩家看到的是“它记得基地箱子里有什么”，而不是“它开挂透视”；
- 允许“记得”，不允许“实时全知”；
- 允许“猜/回忆”，不允许“确定地知道没看过的东西”。

### 硬红线（不变）

- 隔墙实体精确位置；
- 穿墙矿脉/洞穴/结构扫描；
- 未访问结构/地牢箱子；
- 其他玩家/同伴背包、末影箱；
- 远程打开/取用容器；
- 世界种子/刷怪计时/AI 内部状态。
﻿
## 容器记忆模型：允许“记得自己操作过的箱子”

> 2026-11-09 补充。目标不是让触手实时透视，而是让同伴“记得自己打开/操作过的容器”，并据此行动。

### 规则

- 只对**已操作过/登记过的容器**建立记忆：打开过、取过、存过、在基地近距离确认过；
- 记忆包含：位置、维度、`last_seen`、已知内容快照、置信度；
- “想要某物”时，允许查记忆匹配合适箱子 → **亲自走过去** → 打开验证 → 取用；
- 内容与记忆不一致是**合理的未感知变化**：不预知、不远程读取；到现场发现不对就更新记忆/换箱子/上报；
- 动作表现必须物理合理：不能瞬移、不能隔空取物、不能隔墙操作。

### 允许的“作弊”边界

- 内部可以查记忆，知道“我上次在某箱子里见过 X”；
- 玩家看到的是：它走向一个箱子、打开、取出/发现不对——而不是“隔空知道”。

### 仍然禁止

- 对**没操作过**的容器实时透视；
- 全图/全服容器扫描；
- 远程打开/取用；
- 用容器记忆做战斗/威胁判断。
