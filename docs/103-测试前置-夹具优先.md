# 103. 测试前置：夹具优先，不追自主行为

> 2026-11-11。用户明确要求：树在跑时同伴可能乱动；测试/观察/监控前，先用作弊工具创造测试环境，不要顺着树的自主行为做观察和测试。

## 1. 原则

```text
先冻结/搭夹具
→ 再让树进入
→ 只看夹具内行为
```

禁止：

- 树自由漫游时，追着同伴做观察；
- 把自主移动、随机战斗、自然死亡当作测试样本；
- 边跑边改夹具参数来“凑”结果。

## 2. 每次测试前置

1. 暂停/停止相关自动目标，避免测试开始前已乱动；
2. GM/夹具把玩家与同伴移到固定测试场；
3. 清 hostile、掉落物、天气/时间干扰；
4. 固定 HP、饥饿、装备、资源、玩家距离；
5. 记录 GM 操作，标 `assisted`；
6. 冻结本次夹具参数（坐标/数量/阈值/上限）；
7. 再启动或恢复树，只观察夹具内行为。

## 3. 判定

- 只认夹具内、可归因、有上限的行为；
- 自由漫游期间的移动/战斗/死亡不作为验收证据；
- 测试中途 GM 干预 → 该次作废或单独标 assisted；
- 监控只用于看夹具内状态，不用于“发现行为后再补测试”。

## 4. 当前边界

- 树可以继续跑用于监控；
- 但下一步 M3/D1/D2 真实测试开始前，必须先搭好夹具；
- 不因为监控里看到什么就直接顺着它测。

## 5. 背包复制夹具（按需）

重建同伴后，若测试需要保留效率条件，可把旧背包复制给新同伴：

```text
node tools/pilot/inventory-copy.mjs snapshot --companion bigwhale
node tools/pilot/inventory-copy.mjs restore --companion bigwhale --file <snap> --dry-run
node tools/pilot/inventory-copy.mjs restore --companion bigwhale --file <snap> --apply
```

规则：

- 只在测试需要时用，不是重建默认步骤；
- 只复制 item id + count，不复制 NBT/附魔/耐久；
- 默认 dry-run，`--apply` 才通过 GM 发放；
- GM 记录标 assisted，不进 Track A；
- 复制前的旧背包快照保存在 `runs/inventory-snapshots/`。
