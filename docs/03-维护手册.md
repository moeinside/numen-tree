## 3. 探针工具

`probe/mcp.mjs` 是一个最小 MCP 客户端，自动从 `mcp_server.json` 读地址与 token。

```powershell
cd E:\game\HMCL\numen-tree
$env:NUMEN_COMPANION='tyrander'    # 或 id

# 列工具
node probe/mcp.mjs tools

# 列在线同伴
node probe/mcp.mjs call list_companions

# 执行一段 Lua（短代码直接传，注意 PowerShell 引号）
node probe/mcp.mjs lua 'return numen.status.self()'

# 执行 Lua 文件（推荐，避免引号问题）
node probe/mcp.mjs luafile probe/p01-state.lua

# 传 JSON 参数（从文件读，避免 PowerShell 吃引号）
node probe/mcp.mjs callfile get_events probe/args-events.json
```

> ⚠️ PowerShell 传内含双引号的 JSON 会被吃引号导致解析失败。**一律走 `callfile` + 文件**。

## 4. 启动 / 关闭顺序

1. 启动 Minecraft（NeoForge 1.21.1 实例），进入存档。
2. 确认 numen MCP 已开（游戏内设置，或检查 `Get-NetTCPConnection -LocalPort 8765`）。
3. 确认有同伴在线：`node probe/mcp.mjs call list_companions`。
4. 树进程（未开工）应在 MCP 可用之后再启动。
5. 关闭顺序反过来：先停树，再退游戏。

**硬规矩：同一个同伴同一时间只允许一个驱动者（一个 DSH 会话 / 一个树进程）。**

## 5. 故障处置

### 5.1 `a program is already running for this companion, or its built-in brain is acting`

这个拒绝文案有**两个**可能来源，别混。

| 步骤 | 动作 |
|---|---|
| 1 | 先看是不是自己的程序还在跑（等它结束，或等 20 分钟上限） |
| 2 | 检查该同伴的 `config\numen\companions\<id>\binding.json` 里有没有 `provider`。**有 provider 意味着内置脑可能被触发并占住同伴** |
| 3 | 在游戏内让主人对同伴说一句话（会触发 `watch` → 打断程序）——这是官方机制 |
| 4 | 等 20 分钟任务上限自然释放 |
| 5 | 以上都无效 → 删除并重建同伴（**代价：背包/护甲/饰品全掉，实体 id 变，memory 笔记按同伴归属会丢**） |

> 尚未确认"程序遗留"与"内置脑占用"各自的特征。判定方法见 `docs/02-探针记录.md` §6.3。

### 5.2 MCP 连不上

- 端口没监听 → 游戏没开 / numen 的 MCP 服务没开。
- 端口在但 `initialize` 失败 → token 变了，重读 `mcp_server.json`。
- 树进程和 DSH 都在调同一个同伴 → 参见 5.1。

### 5.3 "this turn was cut off"

程序被切断。已知相关常量：`CLIENT_ANSWER_TICKS = 600`（= 30 秒）。常见诱因：客户端卡顿/断连、主人说话打断、长任务超限。
处置：把任务拆小、避免客户端侧 kill 在途调用。

### 5.4 换档 / 重进世界后的"僵尸锁"（2026-11-07 实测）

**症状**：切换存档后，游戏日志里已经没有任何新的 `[numen-program]` 行，但每次 `lua` 仍然被拒：
`a program is already running for this companion, or its built-in brain is acting`。

**判定**：

1. `Select-String latest.log -Pattern "numen-program"` 看最后一条的时间；
2. 如果最后一条远早于当前时间，且 `lua` 仍被拒 → 僵尸锁，不是有人还在驱动。

**成因（推断）**：`ServerPrograms.RUNNING` 是 JVM 里的**静态表**。换档只重启了内嵌服务器，没重启整个 JVM，旧程序的条目残留；而旧服务器已经没了，那个任务永远不会结束 → 锁永远不释放。

**处置**：已通过独立补丁 mod 修复，见 `patcher/README.md`。

- 补丁名：`numenlockfix-1.0.0.jar`，已装进 `mods\`
- 原理：在服务器启动时清空 `ServerPrograms.RUNNING` 这张 JVM 静态表
- 验证：重启游戏后，日志里搜 `numenlockfix`；进 A 档 → 退出 → 进 B 档，确认 `lua` 可用
- 回滚：删掉该 jar，重启游戏

应急时（补丁没装/没生效）：**彻底重启 Minecraft**（不是只换档）。删掉重建同伴也能绕过（换新 UUID），但**背包/护甲/饰品全部掉落、实体 id 改变**。

**树的反应**：占用满 3 次 → 推 `★ slot_blocked`；持续超过 60 秒 → 再推 `★ slot_blocked_persistent`，附带两个处置方案和步骤。树**不会自动执行删除重建**，只建议。

**预防**：换档前先让树停手——`node src/cli.mjs control --companion <名> --op clear`，等任务结束后再退档。

### 5.5 同伴不见了 / 死了

- `get_events` 里会有死亡事件。
- 创造模式下可用 `creative.give` 补装备（但这是危险动作，需白名单）。
- 重建后 **id 会变**，任何按 id 绑定的东西（包括可能的 Lua 模块目录）都要重新建立。
- 树会在换档/重连时自动刷新同伴 id，并重置状态（见 5.6）。

### 5.6 树的换档自愈行为

树在下列任一信号出现时，会**清空上一局的状态**并推一条 `★` 通知：

| 信号 | 含义 |
|---|---|
| MCP 会话重建（`sessionGeneration` 变化） | 游戏重启过 / 换过档（15 秒防抖） |
| 世界时间回退 > 1200 tick（60 秒） | 进了一个时间更早的世界 = 换档 |
| `list_companions` 里找不到该同伴 | 换档后还没召唤回来 |

清理内容：待办目标全部作废、坐标/HP/饥饿/任务/后台任务清零、槽位计数清零；如果同伴换了新 id，会异步刷新。

## 7. 新预设「外接大脑（Numen 树）」

### 7.1 两个预设的区别

| | 外接大脑（Numen）（旧） | 外接大脑（Numen 树）（新） |
|---|---|---|
| LLM 连谁 | numen 的 MCP（`8765`） | 树进程的 MCP（`8767`） |
| LLM 看到什么 | 9 个工具，含 `lua` | 8 个树工具，**不含 `lua`** |
| LLM 干什么 | 自己写 Lua 微操 | 只下目标、收上报 |
| 依赖 | 游戏在跑 | **树进程在跑** |

两者**按会话二选一**，不是同时开。

### 7.2 启动顺序

```
1. 启动 Minecraft（numen MCP 在 8765）
2. 启动树进程：node src/daemon.mjs（在独立终端，别挂在会话里）
3. 启动 / 重启 DSH
4. 新建会话 → Agent preset 选「外接大脑（Numen 树）」
```

**顺序不能错**：DSH 会话在启动那一刻就连树，树没起会拿不到工具（`failOnStartupError: false`，不会崩，但就是没工具）。

### 7.3 配置位置与回滚

- 预设写在 `~/.dsh/profiles/desktop/cordis.patch.yml` 的最后一个 `- insert:` 块。
- 备份：`cordis.patch.yml.bak-before-numen-tree`
- 回滚：把备份复制回去，重启 DSH。
- 只启用/停用：设置 → 插件里找对应项；或直接删掉那个 `- insert:` 块。

### 7.4 怎么确认新预设生效

1. 会话的工具列表里出现 `mcp__tree__tree_status` 这类工具；
2. 直接调一次 `tree_status`，能返回同伴摘要；
3. 若报 "no tools"：树进程没起，或端口不通（`Get-NetTCPConnection -LocalPort 8767`）。
