# 70. 风险评估职责：总控 + 点子王

> 2026-11-10。明确：关键模块架构变更、模块内部功能变更时，总控与点子王分别承担不同层级的风险评估。  
> 原则：不重复评估同一层，不搞风险表演。

## 1. 两层风险

### 总控：战略/愿景风险

回答：

- 这次改动是否仍服务北极星/H1/H2/H3？
- 是否把项目拖向症状修补/范围漂移？
- 是否破坏系统不变量/因果链？
- 是否让未来可选性变差（不可逆架构债）？
- 是否在用短期指标换长期能力？

不看：

- 具体实现/函数/迁移脚本；
- 单测/性能细节；
- 具体 bug 修法。

### 点子王：工程/架构风险

回答：

- 这次改动最可能在哪里崩？
- 影响面/爆炸半径多大？
- 迁移/回滚/兼容性如何？
- 会不会引入新的槽竞争/抖动/循环？
- 测试/证据是否覆盖真实失败模式？
- 有没有更便宜/更稳的替代？

不看：

- 北极星是否值得做（总控管）；
- 验收口径（产品经理管）；
- 世界机制是否可行（MC 专家管）。

## 2. 触发矩阵

| 变更类型 | 例子 | 总控 | 点子王 | 产品经理 |
|---|---|---|---|---|
| 架构/跨层 | Facts 契约、milestone 语义、Arbiter、GoalStore schema | ✅ 战略风险 | ✅ 工程风险 | ✅ 验收影响 |
| 模块接口 | strategy/tactic 契约、perception 接口 | 视情况 | ✅ 工程风险 | ✅ |
| 模块内部功能 | recipe 步骤、单 tactic 逻辑、strategy 分支 | 仅当影响能力 | ✅ 工程风险 | 视情况 |
| 纯 bugfix | 单点修复、无接口变化 | ❌ | 可选/异步 | ❌ |
| 感知/安全语义 | 触手权威、postcheck、unknown | ✅ | ✅ | ✅ |

## 3. 输出格式

### 总控（一页）

```text
1. 对应能力/里程碑
2. 战略风险等级：低/中/高
3. 最大战略风险（1~3）
4. 是否建议做/缓/换方向
5. 一句话
```

### 点子王（一页）

```text
1. 最可能崩点（按可能性×影响）
2. 爆炸半径/耦合
3. 迁移/回滚/兼容
4. 测试/证据缺口
5. 替代/捷径
6. 一句话
```

## 4. 风险等级

- **低**：模块内部、无接口、可回滚 → 点子王可选，记录即可；
- **中**：模块接口/行为变化 → 点子王必审，PM 看验收；
- **高**：跨层架构/schema/安全/感知权威 → 总控 + 点子王 + PM + 相关域（行为/MC）。

## 5. 决策衔接

```
变更提案
  → 总控：值不值得做（战略风险）
  → 点子王：能不能安全做（工程风险）
  → PM：能不能验收（范围/证据）
  → Lead：裁决
```

任何一层高风险，必须先降风险或改方案，不能直接开工。

## 6. 防风险表演

- 不是每个 bug 都做风险评估；
- 每次 ≤1 页；
- 风险必须带证据/触发条件；
- 必须给替代/缓解，不只说“危险”；
- 高风险项进入 DECISIONS，后续验收回看；
- 不为“显得严谨”加流程。

## 7. RACI 补充

| 事项 | A | R |
|---|---|---|
| 战略/愿景风险 | Lead | 总控 |
| 工程/架构风险 | Lead | 点子王 |
| 验收风险 | Lead | 产品经理 |
| 行为风险 | Lead | 行为学家 |
| 世界可行性风险 | Lead | MC 专家 |
| 玩家期望风险 | Lead | 玩家代表 |

## 8. 一句话

> **总控评估“这事值不值得做、会不会偏航”；点子王评估“这事会不会崩、能不能安全落地”；同一层不重复审。**
